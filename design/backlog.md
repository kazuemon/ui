## Link

- 文字のリンクの ↗ の下線は、文字の下線を2つの要素でつないだものです。hover の濃い下線で、つなぎ目が画素の途中に来ると、そこの1画素だけ少し明るく見えます（[ADR-0030](./adr/0030-text-link.md)、[ADR-0046](./adr/0046-link-rest.md)）
- 枠線のリンクは、子が1つだけのとき（アイコンだけ、要素1つだけ）はアイコンとみなさず、新しいタブなら ↗ を足す扱いです。この扱いでよいかは確かめていません（[ADR-0046](./adr/0046-link-rest.md)）
- `contentAlign` の `between`・`center-end` で、文字の前にアイコン（サービスのアイコンなど）を置く形は比べていません。いまは文字と一緒に包みの中に入ります（[ADR-0046](./adr/0046-link-rest.md)）
- 最後のアイコンは children の最後が要素かどうかで見分けます。children を1つの Fragment にまとめると見分けられず、`between`・`center-end` でアイコンも包みの中に入ってしまいます（[ADR-0046](./adr/0046-link-rest.md)）
- 押せない文字のリンクは、見た目ではリンクであることも押せないことも分かりません。読み上げでだけ「リンク、利用不可」と分かります（[ADR-0046](./adr/0046-link-rest.md)）
- アイコンだけの枠線のリンクに `aria-label` で名前を付けると、名前が `aria-label` だけになり、新しいタブでも「（新しいタブで開きます）」が読まれません（[ADR-0046](./adr/0046-link-rest.md)）
- `ButtonLinkProps` は、ボタンの props（`ComponentProps<'button'>`）をもとにしたままです。`form`・`name` などボタンだけの属性も型では通り、`onClick` の要素の型も `HTMLButtonElement` のままです（[ADR-0046](./adr/0046-link-rest.md)）
- 型を外して `loading` などを渡したときの警告は `import.meta.env.DEV` を見るので、Vite 以外の環境では出ません（[ADR-0046](./adr/0046-link-rest.md)）

- 選択肢を選んで閉じ、フォーカスが本体に戻るときに、説明としても読まれることがあります（`aria-live="polite"` と重なります）（[ADR-0044](./adr/0044-message-announce.md)）
- つまみを引く操作は自前で、引く速さ（勢い）を見ません。はじいて閉じる動きもありません（[ADR-0037](./adr/0037-select-sheet.md)）
- 開いたまま画面の大きさを変えても、シートの半分の高さと浮かぶ選択肢の上限を計算し直しません（[ADR-0037](./adr/0037-select-sheet.md)）

- 浮かぶ選択肢の項目の数の上限（10.5）は「一旦」です。使ってみて見直すかもしれません（[ADR-0037](./adr/0037-select-sheet.md)）
- 選択肢の群（Base UI の `Select.Group`）は、部品にありません（[ADR-0037](./adr/0037-select-sheet.md)）
- 浮かぶ選択肢は、本体の下のエラー・警告を隠します。2行目のある選択肢が多いと、シートが半分の高さで開き、つまみが出ます（どちらも許容済み）（[ADR-0044](./adr/0044-message-announce.md)）

- ボトムシートでの読み込み中の行の見た目は、比べていません（[ADR-0042](./adr/0042-field-loading.md)）
- 読み込み中の行は開いたときに一緒に出るので、読み上げソフトによってはすぐには知らせません。本体の `aria-busy` と合わせて伝える前提です（[ADR-0042](./adr/0042-field-loading.md)）
- 浮かぶ選択肢の開閉の動きは、まだ比べていません。いまは 98% の大きさと濃さ 0 から 0.1 秒で広がる仮の動きで、ほとんど動いて見えません（[ADR-0036](./adr/0036-select-popup.md)）
- 比べる案の候補: 動きなし、いまの小さな広がり、本体の側から伸びる（開く向きで起点を変える）、濃さだけ、少しずれながら現れる、など。開閉で長さ・緩急を変えるか、ボトムシートの動きとどう揃えるか、動きを減らす設定でどうするかも未定です（[ADR-0037](./adr/0037-select-sheet.md)）
- Menu・Popover・Tooltip など、ほかの浮かぶ UI でも同じ影・同じ動きのトークンを使うかは、それぞれを作るときに決めます（[ADR-0036](./adr/0036-select-popup.md)）

## Notice

- 入力欄の下の成功・情報の行（キャプション・エラー・警告と同じ並びの形）は作っていません。白地の文字の役割（`--color-fg-success`・`--color-fg-info`）はあります（[ADR-0041](./adr/0041-caption-and-message.md)）

- 黄色の塗り（`filled` の警告）は白地との比が 1.20:1 ですが、影を付けないので縁もありません。淡い面と同じく、面の色だけで置いています（[ADR-0038](./adr/0038-warning.md)、[ADR-0043](./adr/0043-notice.md)）
- 操作の場所には、白いボタンと文字のリンクを置く前提です。枠線のリンクなど、ほかの部品は確かめていません（[ADR-0043](./adr/0043-notice.md)）

- 警告のお知らせも危険と同じように読み上げに割り込む形（`role="alert"`）にするかは、答えが出ていません（[ADR-0043](./adr/0043-notice.md)）

## Form

- フォーム全体を送っているあいだの形（欄を止めて、印はボタンだけ出す）が部品にまだありません。`loading` を渡すと欄にも必ず印が出ます。フォーム全体の「待っている」を欄に配る仕組み（Provider など）もなく、いまは欄ごとに `loading` を渡します（[ADR-0034](./adr/0034-loading.md)、[ADR-0042](./adr/0042-field-loading.md)）
- エラーの一覧のリンクの欄の名前は、ラベルの文字そのものです。ラベルに文字の印（「必須」など）を入れると、その文字も一覧に入ります（[ADR-0044](./adr/0044-message-announce.md)）
- `<Form>` は Base UI の Form を包まない自前の部品で、「一旦」の形です。あとでブラッシュアップします（[ADR-0044](./adr/0044-message-announce.md)）
- 送信のあとで、あとから（非同期で）出たエラー（サーバーの答えなど）には、フォーカスを移しません。polite で知らせるだけです（[ADR-0044](./adr/0044-message-announce.md)）
- 読み上げは Chrome の AX とページの中で真似た記録で確かめただけです。本物の読み上げソフト（VoiceOver・NVDA）では試していません。選択肢の2行目と選べない選択肢の読み上げも同じです（[ADR-0044](./adr/0044-message-announce.md)）

## Switch・Tag

- いまのタグ（`<Tag>`）は、利用者が選ぶ色（青・ピンク・グレー）と、状態の色（情報・成功・警告・危険）を1つの `color` で持ちます。技術のタグのような分類と、「公開中」のような状態の両方に使う形です（[ADR-0007](./adr/0007-tag-color.md)、[ADR-0028](./adr/0028-default-color.md)、[ADR-0043](./adr/0043-notice.md)）
- タグは押すものではなく、文字の大きさに従います（大きい指用でも変わりません）。寸法は文字 11px・12px、高さ 20px、pill です
- 決めること: 数（通知の件数など）や小さな状態の点を出す Badge を Tag と分けて作るか。名前（Tag・Badge・Chip など）と、どちらが何を持つか（状態の色と利用者が選ぶ色は、同じ `color` に並べたままにすることが決まりました — 上の「記録待ち」）。大きさの段階（文字の横に置く小さなもの、数字だけの丸など）。押せる・消せるタグ（絞り込みの Chip など）を持つか、持つならタグとは別の部品にするか（いまのタグは押せません）
- 実装方針には、Badge を素の要素で作る部品として挙げていますが、まだ作っていません

## 密度・全体

- ページ全体の倍率（スケール）を持ちたい、という話が出ています。「大きい指用というよりも、web ページ全体のスケールとしてコントロールできると良さそう」。大きい指用（`coarse-large`）で文字も大きくしたいこと、`coarse-large` という名前が直感的でないこと（「coarse-large ってあまり直感的なクラス名ではないような気もします」）から出ました（[ADR-0045](./adr/0045-coarse-size.md)）
  - おすすめ（まだ決めていない）: 寸法のトークン（高さ・文字・行の高さ・余白・間・アイコン・トグル）を rem で書き、`round()` で整数の px に丸めます。全体の倍率は html の文字の大きさで決めます。線の太さ・影・角丸は px のままです（角丸は原則5 の「高さに比例させない」）。行の高さは、上下の余白を丸めて「高さ − 余白 × 2」で出し、高さとの差を偶数に保ちます（[ADR-0032](./adr/0032-text-offset.md)）。`coarse-large` はやめ、指のときだけ大きくしたいアプリは `@media (pointer: coarse) { html { font-size: 118.75% } }`（52px 相当）と書きます（ADR-0045 を置き換える）。Storybook のツールバーの「指用の高さ」は「全体の倍率」（100%・112.5%・125%・150%）にします
  - 選ばない形: CSS の `zoom`（ブラウザで挙動が違い、1px の線もぼやけ、Select の高さの計算など要素の大きさを測る処理がずれる）、倍率の変数だけ（ブラウザの既定の文字の大きさの設定に従えず、下の px と rem のちぐはぐが残る）
  - 分かっていること: `round()` は Chrome 125・Firefox 118・Safari 15.4 以降で使えます。rem と `round()` で、html の文字 16・18・20px に対して部品の高さが 44・50・56px になることを確かめました（Chromium 151）。行の高さを別に丸めると、18px のとき高さとの差が奇数（50 − 27）になります。ブラウザの拡大（Cmd/Ctrl ＋、ピンチ）は、どの形でも効きます。iPhone の Safari には既定の文字の大きさの設定がありません
  - 一部（section など）だけを大きくすることは、rem ではできません（rem はいつも html の文字の大きさが基準）。残すなら、倍率の変数を別に持ちます
  - 決めること: この形で進めるか、一部だけ大きくする仕組みを残すか、何を大きくするか（角丸と線はそのままでよいか）
- いまはトークンが px、Tailwind のクラス（`gap-2`・`mt-1` など）が rem です。ブラウザの既定の文字の大きさを変えると、文字と高さはそのままで、間と余白だけが大きくなります（お知らせで測定。html 20px で、本文 14px・ボタン 40px のまま、操作の間 8→10px、上の余白 4→5px）
- 密度で文字の大きさを変える決まり（指用 16px・マウス用 14px）は、[ADR-0004](./adr/0004-density-and-structure-switching.md) の決定1「寸法は全部品で切り替える」から来ていて、文字の大きさそのものは比べていません（[ADR-0020](./adr/0020-control-size-fine.md) でマウス用 14px のまま、ADR-0045 で大きい指用も 16px のまま）。「スマホ用になったときに文字サイズが変わるのは想定外でした」。見直すかは決めていません
- 大きい指用（`coarse-large`）で、文字・左右の余白・並べる間を変えるかは比べていません。いまは高さだけが変わります（ADR-0045。上の全体の倍率で扱う）
- どんな場面で大きい指用を使うかは決めていません（[ADR-0045](./adr/0045-coarse-size.md)）
- 寸法を Provider で固定する仕組みがまだありません。クラス（`coarse-large` など）は `html` か要素に直接付けます（[ADR-0045](./adr/0045-coarse-size.md)）
