# デザイン原則

このドキュメントは、かずえもんがデザインをどう捉えているかを書いたものです。@kazuemon/ui の部品を作るときも、使うときも、迷ったらここに戻ります。

原則は「こう考えているので、こう見える」の順に書いています。数値やトークン名は書きません。値は [`tokens.css`](./tokens.css) に、決めた経緯は [`adr/`](./adr/) にあります。1 つの部品だけの決まりと、選べる形の一覧は、部品のドキュメントにあります。

## 存在理由

文字の大きさが同じままだと、画面の大きさが変わったときに、一度に見える量が極端に変わります。デスクトップ優先の UI はモバイルに合わず、モバイル優先の UI はデスクトップで間延びします。一方で、押すものには、どの画面でも指で押せる大きさが要ります。

このシステムは、押すものの大きさをそろえたまま、一度に見える量（[原則 11](#11-文字の大きさは入力方式で切り替える)）と指の動き（[原則 16](#16-重なる面は指の動きで浮かべるかシートにする)）を、使われ方に合わせて切り替えます。それがこのシステムを作る動機です。

## 判断の基準

候補を選ぶとき、また作っていて迷ったときは、次の 4 語に最も近いものを選びます。

| 基準の言葉     | 画面で見るところ                                                 |
| -------------- | ---------------------------------------------------------------- |
| **軽い**       | 影は弱く、線は細く、余白は多い                                   |
| **やわらかい** | 角が丸い。文字は黒ではなく濃紺グレー                             |
| **整然**       | 部品の構造がそろっている（名前・本体・補足の骨組み、状態の規則） |
| **人懐っこい** | 水色・ピンク・pill・和欧併記                                     |

### 顔は、構造を実直に、個性をトークンに

構造（状態の表し方、影、塗りと枠線）は実直にします。個性（色、角丸、文字、和欧併記）はトークンに出します。「整然」は構造が、「人懐っこい」はトークンが担います。

構造まで個性的にすると、部品が多く並ぶ画面でうるさくなります。構造だけにすると、どこにでもある没個性な見た目になります。

### ポップさは、トークンと動きで出す

温かみとポップさは、色や角丸と、押したときの動きで出します。動きは静止画では見えないので、整然とした見た目を崩さずに足せます（[原則 14](#14-動きは手応えと待ちを伝える)）。部品の内部に装飾は持ち込みません（[原則 9](#9-遊びはレイアウト層に置く)）。

### 反例

次の見た目は、基準から外れています。

- マテリアルデザインのような、影で階層を作る硬い見た目
- 字間を大きく空けた英字ラベル。AI が作ったように見えます

## 参照画像

原則の出どころになった画像は [`references/`](./references/) にあります。ブレのあるデザインも含まれており、あくまで参考です。構造は、コンポーネント見本の側に寄せます。個性は、Web サイトの側に寄せます。

## 部品の仲間

新しい部品を作るときは、まずどの仲間かを決めます。仲間が決まれば、影、hover、押したとき、押せないときの見た目が決まります。

| 仲間           | 例                                                         | 見た目の土台                                           |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| 浮いた押すもの | 塗りのボタン、トグル、全体が押せるカード                   | 塗りがあり、少し浮いていて、薄い影を持つ               |
| 平らな押すもの | 枠線のボタン、リンク、タブ、カレンダーの日                 | 塗りがないので影もない。hover で文字の色を淡く敷く     |
| 入力欄の仲間   | 文字を打つ欄、選ぶ欄、チェックボックスとラジオ、一覧の項目 | グレーの塗りで、影も枠線もない。hover で塗りが濃くなる |
| 面             | カード、お知らせ、重なる面                                 | 中にものを置く場所。それ自体は押さない                 |

## 1. 影はレイヤーの離れを表す

画面は 1 枚の面（ページ）です。影が付くのは、ページから離れているものだけです。高さは 3 段あります。ページ、少し浮いた押すもの、ページの上に重なる面です。

塗りのある押すものは、押すために少し浮いています。押すと沈んで、ページに着きます。

- 浮いた押すものには、輪郭程度の薄い影を付けます。hover で影が減ります（[原則 3](#3-hover-は手応え押すと沈む)）
- 白いものを白い地に浮かせるときは、影だけでは縁が分かりません。細い輪郭を足します
- 全体が押せるカードも、浮いた押すものです。カードはいつも押せるとは限らず、中のボタンだけが押せることもあります。影を付けるのは、全体が押せるときだけです
- 影を落とすのは塗りです。枠線のボタンやリンクには塗りがないので、影も出ません。平らな押すものは、ページに着いています。塗りにするか枠線にするかは、[原則 7](#7-塗りか枠線か) で決めます
- 入力欄の仲間は、塗りがあっても浮かせません。値を入れる場所であり、ページの一部だからです
- 押せなくなったものは、浮いていません。影を消します（[原則 13](#13-押せないものは浮かせず薄くする)）

重なる面は、ページの上に重なって出る面です。選択肢、シート、ダイアログ、マウスを載せて出る補足、あとから出て消えるお知らせがそうです。下の内容と切り分けるには、面の明るさの差だけでは足りません。

- 重なる面には、やわらかく広い影を付けます。押すものより高く見えます。輪郭は、白いものと同じ細い線です
- 画面の端から出る面の影は、出てくる向きへ向けます。画面の外に落ちる影は見えないためです
- 影は面の大きさに合わせます。小さく短い補足の影は、小さく淡くします。大きな面と同じ影では、重く見えます
- ページの一部でも、画面に貼り付いて、スクロールした内容が下を通るようになったら、重なりとして扱います
- スクロールできる面は、続きがあることを必ず見せます。途中で切れる端に内側の影を落とすのが基本です。内側の影を出さない枠では、スクロールのつまみをいつも出しておきます。文字やぼかしでは知らせません。内側の影も重なりの影で、押せることは表しません

ページと同じレイヤーにあるものには、影を付けません。お知らせ、押せないカード、入力欄、タグがそうです。記事の中の引用、囲み、表、画像、コードも同じです。

- これらの区別は、面の明るさと余白で付けます。カードが浮いて見えるのは、影のためではなく、背景より明るい面だからです
- 影が表すのは、物理的な離れ方だけです。情報の重要さを影で積み上げると、マテリアルデザインのように硬く重くなります（反例）
- 高さはこの 3 段だけです。浮いているものが少数になるので、画面が軽くなります

経緯: ADR-0006、0024、0025、0033、0036、0037、0043、0102、0106、0108、0119、0125、0129、0131、0160、0164、0167、0169

## 2. フォーカスとエラーは枠線で表す

部品の様子は、種類ごとに表し方を分けます。フォーカスとエラーは枠線、選んでいることは部品の色の塗りや印（[原則 6](#6-色は役割で持つ)）、押せないことは薄さ（[原則 13](#13-押せないものは浮かせず薄くする)）、hover と押したことは明るさと沈み（[原則 3](#3-hover-は手応え押すと沈む)）です。表し方を分けておくと、重なっても読み分けられます。

フォーカスとエラーは、いつ見ても分かる必要があります。一般的な、濃くしたり薄くしたりする方式は使いません。明るさの変化は hover の手応えに使うので、フォーカスまで明るさで表すと区別がつきません。ふだんの入力欄には枠線がないので、枠線を足すだけで目に入ります。

- 入力欄は、ふだんはグレーの塗りで枠線がありません
- フォーカスすると、塗りはそのままで、枠線だけが付きます
- 枠線の色は部品の色です。色を指定していない部品と、色を持たない欄では、本文と同じ濃紺になります
- エラーは、赤い枠線に加えて、塗りも淡い赤にします。明るさはグレーの塗りとほぼ同じで、変わるのは色相だけです
- エラーの欄にフォーカスしたときは、赤い枠線を残したまま、その外に白を挟んで、部品の色の線を離して引きます。いま操作している場所と、直すところの両方が同時に見えます
- hover に枠線は使いません。枠線はフォーカスとエラーのものです

変化の大きさは、知らせたい強さに合わせます。

- フォーカスは操作のたびに起こるので、枠線を足すだけにします
- エラーは見落とされると困るので、枠線と塗りの 2 つで知らせます
- 変化を小さくしたいときは、変わるものの数を減らします。枠線を細くはしません

押すものにも、キーボードで操作したときだけフォーカスの線を出します。マウスやタップでは出しません。

- 線は、部品から少し離して外側に描きます。部品の色ではなく地の色と比べることになるので、青やピンクのボタンでも線が溶けません。下に選んでいる印や区切りの線を持つ部品では、外側に描くと線がそれを越えてはみ出すので、内側に描きます
- 線は囲んだものの角に沿います
- 線の色は部品の色に従います。色を指定していない部品は濃紺です。動くのは線の色だけで、位置は動かしません
- 濃い面の上では、濃い線が見えません。そこでは線を、その面の文字の色にします
- いまいる場所を示す線は、同時に 1 本です。入力欄の中のボタンにフォーカスしているあいだは、欄の枠線を消してボタンの線だけにします。エラーの赤い枠線はフォーカスではないので、消しません
- フォーカスそのものが項目へ移る部品（カレンダーの日）では、項目に線を引きます。フォーカスが欄に残ったまま項目を指す一覧では、線ではなく手応えの塗りで示します（[原則 3](#3-hover-は手応え押すと沈む)）
- 1 つの値を区切りごとに打つ欄（日付・時刻）では、区切りそのものへフォーカスが移りますが、線ではなく塗りで示します。線で区切ると、値が途中で分かれて見えるためです

経緯: ADR-0019、0021、0022、0031、0040、0043、0047、0070、0071、0072、0136、0148、0164、0191

## 3. hover は手応え、押すと沈む

hover は状態ではなく、マウスを載せたことへの反応です。フォーカスやエラー（[原則 2](#2-フォーカスとエラーは枠線で表す)）より小さく、明るさで表します。

押すものは、押すと一段沈みます。押しても残り、画面の一部が切り替わるもの（タブ、木の行、行き先の並び）も沈みます。沈みがなくてもよいのは、2 つの場合だけです。押した瞬間に閉じて消えるもの（一覧の選択肢、メニューの項目）は、沈む様子が見えないことがあるので、塗りで返せば足ります。それ自体の動きが手応えになるもの（左右に動くトグル）には、沈みを重ねません。

- 浮いた押すものは、hover で影が減ります。押しても影は hover から変えず、色も薄くしません。変わるのは、わずかに下へ沈むことだけです。沈んでも縁の線は残します。縁まで消すと、縮んで見えるためです
- 全体が押せるカードも同じです。hover で影が減り、押すと沈みます。輪郭は変えません。大きな面では影が減る変化が小さく見えるので、面を淡く塗って手応えを足します。塗りは影の変化を補う程度にとどめ、濃くしません
- 平らな押すものは、hover で文字の色を淡く敷きます。青いボタンは淡い青、ピンクなら淡いピンクです。押すと敷く色が濃くなり、沈みます
- 文字のリンクは、文章の中にあるので背景を敷きません。敷くと目立ちすぎます。ふだんは淡い下線で、hover で下線だけが文字より濃くなります。押すと沈むだけです
- 入力欄は、hover で塗りが半段濃くなります。押すとフォーカスに移ります
- チェックボックスとラジオの箱は、押すと沈み、塗りが濃くなります。箱を押しても横の文字を押しても同じです
- 一覧の項目（選択肢、メニュー）は、いま指している項目をグレーの塗りで示します。マウスで指しても、キーボードで指しても同じ塗りです。指していることは状態ではなく、手応えです。危険な項目だけは、赤を淡く敷きます。押すと一覧が閉じて消えるので、沈みはなくてもかまいません
- 中に押す部品を持つ行（囲みや区切り線で範囲を見せたトグルの行）は、hover で行を淡く塗り、押しても濃くしません。行ごとは沈めません。中のトグルが左右に動くことが、そのまま手応えになるためです
- 指で操作するときは hover がありません。押したときの変化を、hover より明らかに付けます

経緯: ADR-0009、0022、0027、0030、0033、0047、0063、0066、0067、0129、0133、0149、0164、0166、0167、0169

## 4. 部品は「ラベル / 本体 / キャプション」の 3 層

部品は単独では置かれず、名前と説明を伴います。骨組みは、上に名前（ラベル）、真ん中に本体、下に補足（キャプション）の 3 層です。どの部品にもこの場所があり、ボタンにもキャプションを付けられます。

入力欄では、この骨組みに 2 つが加わります。本体を読む前に知っておくこと（ヘルプテキスト）と、入力した結果（ステータスメッセージ）です。呼び名はこの 4 つにそろえます。

- ラベルは太字で本体の上、キャプションは小さくグレーで本体の下です
- キャプションは省略できます。省略してもレイアウトは崩しません
- キャプションの有無や長さで、本体の位置は動きません。トグルは、トグルとラベルを 1 行に置き、キャプションはその行の外に出します
- ボタンのキャプションは、本体の下に中央寄せです

ヘルプテキストは、本体を読む前に知っておくことです。

- 左寄せで、本体の上に置きます。読む順に並べるためです
- ステータスメッセージが出ても、ヘルプテキストは消しません。入力の決まりを読みながら直せるためです

ステータスメッセージは、入力した結果です。

- 本体の下に、アイコン付きの行として足します。色と形の組み合わせは [原則 6](#6-色は役割で持つ) にあります
- 並びはエラー、警告、成功、情報の順です。複数あるときは、すべて出します
- 欄の見た目を変えるのはエラーだけです。警告は送信を止めないので、欄の見た目は変えません
- 行が出ても、本体とヘルプテキストは動きません。下の内容は、跳ばずに滑ります
- 読み上げでの知らせ方は [原則 15](#15-読み上げは見た目の順フォーカスは次に触るものへ) にあります

選択肢に説明が付くこともあります。

- 選べない選択肢は選べなくし、理由をその選択肢の 2 行目に出します。選べるが知っておくことがある選択肢には、警告の 2 行目を付けます。理由は選択肢ごとに違うので、まとめて見出しにはしません
- シートの見出しも、ラベル、ヘルプテキスト、ステータスメッセージの順です

経緯: ADR-0041、0044、0049、0052、0058、0068、0124、0164

## 5. 角丸は部品と包むもので分ける

角丸は、何であるかを表します。部品は部品の角、自分で場所を占める大きな面は一段大きい角、小物は pill です。高さに比例させる規則は採りません。大きさを切り替えると見た目が変わり、そろえたいときに困るためです。

- ボタンと入力欄は同じ角です
- 自分で場所を占める面（カード、シート、画面の横から出すパネル、ダイアログ）は、部品より大きい角です
- 部品に付いて出る面（選択肢、メニュー、押して開く吹き出し、マウスを載せて出る補足）は、部品の角です。流れの中に置く知らせ（お知らせ）も部品の角で、カードの角にはしません
- 画像はカードの角です。記事の中でも外でも変わりません。コードの枠と、外枠を付けた表は、部品の角です
- pill は、小物（タグ、トグル）と、移るための枠線のリンクです。リンクであることを、形でも見分けられます
- チェックボックスは小さな角丸の四角、ラジオは完全な丸です。同じ仲間ですが、形で見分けます
- 角は、要素ではなく見た目で決めます。見た目がボタンなら、リンクでもボタンの角です（[原則 18](#18-働きで部品を選び見た目は別に選ぶ)）
- 何かの内側に収めるものの角は、外側の角から余白を引いた同心の角です

経緯: ADR-0008、0014、0016、0017、0031、0035、0037、0043、0046、0047、0087、0090、0092、0102、0104、0116、0127、0134、0164

## 6. 色は役割で持つ

色には役割があります。水色は primary で、ブランドの色です。ただし水色は明るく、白い文字が載りません。押すものや文字には、primary の代わりの色として青を使います。ピンクは secondary です。情報、成功、警告、危険の 4 つは状態の色です。

- 水色は、見出しとロゴと装飾に使います。白地では、大きく太い文字にしか使えません。水色の面に載せる文字は濃紺です
- 青とピンクに用途の区別はありません。その場所に最も合う色を、使う側が選びます
- 色を指定しないとき、色を持つ部品はすべてグレーです
- 選んでいることを示す印（一覧で選んだ項目、チェック、トグルの ON）は、部品の色に従います。選んだものは部品の色の濃い塗り、つながり（期間の中）は同じ色の淡い面、まだ決まっていないところはさらに薄い面です
- フォーカスの線の色は [原則 2](#2-フォーカスとエラーは枠線で表す) にあります

状態の色は、知らせるための色です。お知らせ、タグ、ステータスメッセージ、白地の文字やアイコンに使います。

- 情報は青と同じ色です。色相がほとんど同じ別の青を持っても、見分けられません
- 危険は、ピンクと並んでも見分けられるよう、色相はそのままに明度を下げた赤です
- 危険は、取り消せない操作の色として、押すもの（ボタン、メニューの項目）でも選べます。情報、成功、警告は、押すものの色にしません
- 警告は、黄色を塗りに残します。黄色に白い文字は載らないので、黄色の上の文字とアイコンは濃紺にします。白地に置く文字、枠線、アイコンは、同じ色相で暗くしたオリーブ色です
- 色だけでなく、形でも見分けます。情報は丸の「i」、成功は丸のチェック、警告は三角、危険は丸の「!」です
- 世の中に慣習のある色は、役割より慣習を優先します。暦の日曜と祝日の赤、土曜の青がそうです

面に色を敷くときは、淡い面に、同じ色相の濃い文字を載せます。タグと、お知らせの既定の見た目です。

- タグは、利用者が選ぶ色と状態の色のどちらも持ちます。近い組み合わせ（情報と青、危険とピンクの面）があっても、文言で見分けます

経緯: ADR-0007、0012、0013、0023、0028、0038、0043、0071、0123、0134、0137、0140、0141、0149、0164

## 7. 塗りか枠線か

押すものの強さは 3 段です。色の塗りは、画面で最も進めたい操作です。グレーの塗りは、ふつうの操作です。枠線は、控えめにしたい操作と、密度の高い並びに使います。隣に並べたとき、この順に強く見えます。

- 密度の高い並び（カードの中のリンク、SNS のアカウント一覧）では、塗りが重すぎるので枠線に落とします
- 枠線のリンクは、枠線のボタンと同じ寸法です
- 文字のリンクは、文の中では周りの文字の大きさのままです。文の外に置いたときは、部品の文字と同じ大きさになります
- 押せる範囲の決まりは [原則 17](#17-押せる範囲は見た目の範囲)、リンクとボタンの選び方は [原則 18](#18-働きで部品を選び見た目は別に選ぶ) にあります

経緯: ADR-0024、0039、0046、0047、0056、0098、0164、0165

## 8. 入力欄の様式は「編集できるか」で決まる

編集できる欄はグレーの塗りです。グレーの塗りを見れば、書き換えられる欄だと分かります。読み取り専用の欄には塗りを持たせず、破線の輪郭で欄の形だけを残します。書き換えられないことを、塗りのあるなしと線の種類で伝えます。

- 読み取り専用の値の文字は、本文より一段淡くします。ただし読むための文字なので、押せない欄のようには薄くしません
- 読み取り専用の欄もフォーカスでき、値を選んで写せます。フォーカスしたときは、破線の代わりに編集できる欄と同じ枠線を付けます
- 読み取り専用の欄は、hover で変えません。prefix・suffix も塗りを持たせません
- プレースホルダー（空の欄に出る見本の文字）は値より淡くしますが、文字の基準を満たす淡さで止めます。値との見分けは、見本だと分かる書き方でも付けます。書式の決まった欄は、プレースホルダーの代わりに、打つべき形の見本を淡く出したままにします。書式や例は、見本ではなく説明の文で伝えます

prefix・suffix（「https://」「円」、パスワードの表示切り替え）は、入力欄の一部です。欄の端に付くものは、見た目で 3 つに分けます。文字は接頭辞・接尾辞で、グレーの塊です。グレー地にアイコンだけを置いたものは押せるボタンです。塗りのないアイコンは、押せない意味の説明です。

- 文字とボタンは、入力欄と同じグレーの、欄の端に接した塊です。区切りは入れません
- 同じ端に文字とボタンが並ぶときは、文字の地を外し、グレー地はボタンだけに残します。グレー地が押せることの印であることを保つためです
- フォーカスとエラーの枠線は、塊の外側にも途切れずに続きます
- エラーのときは、塊も赤みを帯びます。グレーのままだと、赤くなった欄の中で塊だけが浮いて見えます
- suffix に入れるボタンは、欄の値に作用するものだけです。伏せ字の切り替えや、入力した内容の消去がそうです。検索のように実行するものは、値とは関係がないので、欄の外に色か枠線のボタンとして置きます。グレーのボタンにすると、グレーの欄と見分けがつきません

チェックボックスとラジオは、入力欄の仲間です。

- ふだんはグレーの塗りで枠線がなく、影もありません。塗りはトグルの OFF と同じ濃さで、小さな箱でも白い地の上で分かります
- エラーでは、箱の塗りを淡い赤にし、内側に赤い線を引きます。エラーの文は、選択肢の下に、入力欄と同じ形で付けます
- 形は [原則 5](#5-角丸は部品と包むもので分ける)、選んだときの色は [原則 6](#6-色は役割で持つ)、押せないときは [原則 13](#13-押せないものは浮かせず薄くする)、待っているあいだは [原則 14](#14-動きは手応えと待ちを伝える) にあります

経緯: ADR-0024、0035、0040、0047、0062、0070、0164、0168、0170、0171、0187、0188、0189、0190、0192

## 9. 遊びはレイアウト層に置く

巨大な背景文字、隅のキャラクター、見出しの絵文字といった装飾は、部品の外側に置きます。部品の本体は、いつも真面目なままです。

- 装飾を部品の内部に取り込みません。部品を再利用できるままにするためです
- 情報を運ぶものは、装飾ではありません。待っていることや残りの時間を見せる動きは、部品の中に持ちます（[原則 14](#14-動きは手応えと待ちを伝える)）

経緯: ADR-0001、0164

## 10. 和欧併記

日本語の見出しに英語のサブを添えるのが、基本の単位です。英語のサブは装飾であり、日本語を読まない人への手がかりでもあります。

- 英語のセクションラベルは、すべて大文字で、大きく太い、前景用の水色です。大きく太いので、明るい水色でも読めます

和文と欧文を混ぜても、文字は行の中央にそろえます。

- 和文フォントは、そのままだと欄の中で少し上に寄ります。和文の縦の位置を補正します。欧文フォントは元のままです
- 行の高さと部品の高さに、端数を作りません。端数があると、置かれた位置によって文字だけがずれます
- 小文字の欧文が下に寄って見えるのは、欧文の組版として普通の見え方です。補正しません

経緯: ADR-0010、0032、0164

## 11. 文字の大きさは入力方式で切り替える

「デスクトップ／モバイル」を 1 つの判定にせず、原因ごとに分けて切り替えます。入力方式で決まるもの、画面の幅で決まるもの、入れ物の幅で決まるものは、それぞれ別です。

押すものは、指で押せる大きさを基準にします。文字の大きさが同じままだと、小さい画面では一度に見える量が減ります。一方で、スマホは画面を目に近づけて見るので、パソコンより小さい文字でも読めます。そこで、手に持つ画面では、一度に見える量が効く文字だけを小さくします。読ませる文は、量より読みやすさを優先し、小さくしません。

- 部品の高さと余白は、入力方式によらず同じです。マウスでも、指で押せる大きさを保ちます
- 指で小さくするのは、部品の中の文字、設定画面のような機能の画面の本文、表です。部品の文字と本文は同じ大きさにそろえます
- 入力欄の値と選択肢は、指でも小さくしません。小さい欄にフォーカスすると画面を拡大してしまう端末があり、入力のたびに画面が動くためです。見た目が同じ仲間の欄は、同じ大きさにそろえます
- ラベル、ヘルプテキスト、キャプションは、入力方式によらず同じ大きさです
- 記事のような読みものは、指でも小さくしません（[原則 19](#19-読みものは読みやすさを先にする)）。コードは、入力方式によらず、いつも同じ小さめの大きさです
- 見出しは本文に合わせて段を付けます。本文が小さくなるときは、見出しも一緒に小さくなります
- ページを囲む左右の余白は、押すものではありません。指で操作しているかどうかではなく、画面の幅で決めます
- 指用の高さは、場面によってさらに大きくできます。大きくするのは押すものの高さです。トグルも高さに比例して大きくなります。タグは押さないので、文字の大きさに従います
- 判定は、使う側が固定できるようにします。読みものかどうかも、使う側が決めます

経緯: ADR-0004、0020、0045、0065、0078、0079、0090、0092、0120、0164

## 12. 色は面用と前景用の 2 段で持つ

色のコントラストは、候補を作るときの制約です。あとから確かめるものではありません。テイストを保ったまま基準を満たすため、各色を 2 段で持ちます。

- 面用は元の値です。塗り、ロゴ、装飾に使います
- 前景用は、色相と彩度を保ち、明度だけを基準を満たす最小限まで下げた値です。文字と枠線に使います
- 白い文字を載せる面は、前景用の値を使うか、文字を濃紺にします。黄色のように前景用を作っても白文字が載らない色は、文字を濃紺にします
- 基準を満たせない面（トグルの OFF）には、輪郭を足しません。状態は、形と位置（ノブの位置と影）で伝えます
- 読むための文字は、淡くするときも基準を満たす淡さで止めます。それより強く見分けたいときは、色ではなく、線の種類や書き方で分けます。読み取り専用の欄の破線や、プレースホルダーの書き方がそうです

経緯: ADR-0002、0003、0005、0011、0029、0038、0067、0164、0170、0171

## 13. 押せないものは、浮かせず薄くする

押せないこと（無効、送信中）は、影と色と文字を同時に引いて伝えます。影を消すだけでは、トグルの OFF と紛れます。一方で、読むための文は薄くしません。「変更できません」などの説明を読めるままにするためです。

- 影を消します。押せないものは浮いていません（[原則 1](#1-影はレイヤーの離れを表す)）
- 本体の見た目も変えます。色を持つものは色を残して薄くし、色を持たないものはグレーに寄せて文字も薄くします
- 色を残せないもの（トグルのノブ、リンク）は、色を指定していてもグレーにします。地に対して薄い色が残ると、かえって見えなくなるためです
- ON と OFF のように状態が 2 つあるものは、押せないときは同じ地に置き、ノブの位置や印のあるなしで見分けます。押せるものと同じ色にすると、押せるかどうかが読めなくなります
- 押せないこととエラーが重なるときは、押せない見た目を優先します。エラーはステータスメッセージで伝わるので、枠線や赤い塗りは出しません
- ラベル、ヘルプテキスト、キャプションは変えません
- 押して反応する文字（チェックボックスの横の文字）は、本体の一部です。本体と一緒に薄くします
- 押せない欄で、文を出しているところは薄い文字、値が入っているところはさらに薄い文字です。文と値を見分けるためです
- 送信中も押せない見た目にします。ただし、動いている印は薄くしません。薄くすると、止まっているのか進んでいるのか分からなくなるためです
- 押せない理由は、そのもののそばに、見える文で書きます。キャプションや、選択肢の 2 行目です

押せないリンクは、押せないボタンと同じ扱いです。

- ボタンの見た目と枠線のリンクは、押せないグレーのボタンと同じ見た目にします。色を指定していてもグレーです
- 文字のリンクは、色と下線で押せることを表しています。押せないときはその両方を外し、ただの文字と同じ見た目にします

経緯: ADR-0026、0029、0034、0042、0059、0069、0072、0073、0164

## 14. 動きは手応えと待ちを伝える

動きは飾りではなく、返事です。押したことへの返事、待っていることの知らせ、ものがどこから来てどこへ行ったかを伝えます。整然とした見た目を崩さずに、ポップさを足せる場所でもあります。

- 押す動きは、素早く沈み、弾ませません。手応えとして十分で、待たせません
- 状態の移り変わりは速くします。ゆっくり変わると、操作できるまでのラグに見えます
- その場で現れる印（チェック、ラジオ、選んだ日）は、動かさずにすぐ切り替えます。場所をまっすぐ移る印（トグルのノブ、タブの印）は、滑らせます
- 重なる面は、出てくる元の側から短く滑って出ます。閉じるときは、開くときより短くします
- 内容が増えて下が押されるときは、跳ばずに滑らせます

待っているあいだ（入力した値を確かめている、選択肢を読み込んでいる）は、止めない形が既定です。打っている途中で入力を止めないことを優先します。

- 止めない形では、回る印を足すだけで、操作は続けられます
- 止めるときに止めるのは、値を変えるものだけです。見え方だけを変えるもの（伏せ字の切り替え）は止めません
- フォーム全体を送っているあいだは、値を変えるものをすべて止めます。フォーカスは外さず、送る値も変えません
- 止めたものは、押せない見た目にします（[原則 13](#13-押せないものは浮かせず薄くする)）。フォーカスとエラーの枠線は残します
- 読み込み中の場所取りは、面を横切るやわらかく淡い光で、読み込んでいることを伝えます。光は目立たせすぎず、待っていることが分かる程度にとどめます

動きを減らす設定でも、伝えることは減らしません。

- 小さな動き（回る円）は止めずにゆっくり続け、大きな動き（幅いっぱいを横切る線や、読み込み中の面の光）はその場の明滅に置き換えます
- ふわっと出る動きや滑る動きはなくし、すぐに出します
- 情報を運ぶ動き（待っている印、残りの時間）は止めません

経緯: ADR-0009、0034、0042、0044、0054、0055、0059、0112、0115、0118、0142、0147、0161、0164

## 15. 読み上げは見た目の順、フォーカスは次に触るものへ

読み上げでは、見えているものと同じことを、同じ順で、一度だけ伝えます。見た目と読み上げで順や中身が違うと、画面を見ながら聞く人が迷います。

- 説明は見た目の順に読みます。ヘルプテキスト、エラー、警告の順です
- 見えている文字を、二度読ませません
- 割り込むのは、あとから出た危険のお知らせだけです。入力の結果（欄のエラー）は割り込まず、いまの読み上げが終わってから知らせます。割り込ませると、移った先の欄の名前が聞こえなくなります
- 知らせるものでなければ、知らせません。記事の中にはじめからある囲みは、お知らせと同じ見た目でも、補足として読みます
- 見た目で伝えていることは、読み上げにも足します。新しいタブで開くリンクがそうです
- キーボードの振る舞いは、見た目ではなく働きに従います。ボタンの見た目のリンクも、リンクとして動きます

フォーカスは、次に触るものへ移します。

- ほかの操作を止める面（ダイアログ、シート）を開いたときは、フォーカスを面の中へ移します。閉じると、開いたものへ戻します
- 移る先は、その場面で最初に触るものです。入力を求める面では最初の欄、取り消せない操作を確かめる面では取り消しの側に置きます
- 指で開いたときは面そのものへ移し、線を出しません
- 送信してエラーになったときは、最初のエラーの欄へフォーカスを移します。欄の名前と説明が読まれるので、ほかに何もいりません

経緯: ADR-0040、0043、0044、0055、0060、0073、0074、0075、0084、0109、0164

## 16. 重なる面は、指の動きで浮かべるかシートにする

重なる面をシートにする理由は、画面の狭さではなく、指の動きを減らすことです。指で操作していて、かつ画面が狭いときだけ、画面の下から出るシートにします。タブレットとマウスでは浮かべたままです。

- この判定は、重なる面で共通です。使う側が固定できるようにします
- 形や出る場所を変えてよいのは、重なる面と、ページの上の帯の行き先だけです。ほかの部品は構造を変えません
- シートでは、下に並べる操作を幅いっぱいにして縦に積み、主な操作を上に置きます。指を大きく動かさずに押せるためです。浮かべるときは、横に並べて端に寄せます
- シートの中にさらに一段深い一覧があるときは、別の面を重ねず、同じシートの中で内容を横に滑らせて進みます。面は深さによらず 1 つのままです
- 入れ物の幅で決まることは、画面ではなく入れ物の幅で決めます。ページの上の帯は、行き先を並べきれない幅になると、行き先を畳みます。画面の一部に置いた帯も、置いた幅に合わせて畳めます
- 指で読めないと困ることは、マウスを載せて出る補足に置きません。押して開く吹き出しやキャプションで見せます
- できないことの印は出しません。シートの上端のつまみは、引けるときだけ出します

経緯: ADR-0004、0037、0102、0105、0106、0110、0130、0152、0161、0164

## 17. 押せる範囲は見た目の範囲

押せる範囲は、見た目の範囲と一致させます。見えない広がりがあると、押したつもりのないものが反応します。

- 見えない広がりは付けません。押して切り替わる横の文字（チェックボックスやトグルのラベル）も、文字の幅だけが押せます
- 範囲を広げたいときは、囲みや区切り線でその範囲を見せます
- 文字のリンクの押せる範囲は、文字の行だけです。広い範囲が要るときは、文字のリンクを広げずに、ボタンの見た目のリンクにします
- 寸法を大きくしても、押せる範囲は見た目の範囲のままです。見えない広がりを足して押しやすくはしません

経緯: ADR-0039、0048、0066、0164

## 18. 働きで部品を選び、見た目は別に選ぶ

部品は働きで選びます。別の場所へ移るものはリンク、その場で実行するものはボタンです。見た目は働きとは別に選べ、リンクにもボタンと同じ見た目があります。見た目の決まりは 1 か所なので、ボタンとリンクでずれません。

- 右上向きの矢印は「押すと、いまの場所を離れる」印です。ボタンの見た目のリンクは、ボタンと紛れるので、いつも付けます。文字のリンクは下線でリンクと分かるので、新しいタブで開くときだけ付けます。行き先を並べる部品（ページの上の帯、カード）は、形で移るものと分かるので付けません
- リンクは移るだけなので、送信中を持ちません
- 見た目が同じでも、働きが違えば部品を分けます。記事の中の囲みは、お知らせと同じ見た目ですが、知らせるものではないので別の部品です

経緯: ADR-0046、0073、0084、0164

## 19. 読みものは読みやすさを先にする

記事のような長い文を読む場面では、一度に見える量や部品の決まりより、読みやすさを優先します。

- 文字は、指で操作していても小さくしません（[原則 11](#11-文字の大きさは入力方式で切り替える)）
- 記事の中のリンクは、色を指定しなくても青にします。押せる文字を本文と見分けやすくするためです
- 文中のコードは、周りの文字の色を淡く敷きます。白地、グレーの面、色の面、濃い塗りのどこに置いても、地より一段濃い面になります
- 見出しと区切りの上の余白は、節の切れ目を見せるために使います。マウスでは広く取り、指では画面が狭いので詰めます
- 記事の中のものは、ページと同じレイヤーです。影を付けません（[原則 1](#1-影はレイヤーの離れを表す)）

経緯: ADR-0078、0081、0096、0097、0098、0164

## 20. 部品は知らないことを決めない

部品は、自分がどこに置かれるかを知りません。知らないことは決めず、使う側に渡します。決めるときは、既定を 1 つ決め、ほかの形は選べるようにします。原則には既定とその理由だけを書きます。

- どの文を出すかは使う側が決めます。部品は渡された文をそのまま出し、組み立てません
- 並べているかどうか、文がどこで折り返すと読みやすいかは、部品には分かりません。寄せ方や見出しの折り返し方は、使う側が選びます
- 記事の本文の部品は、変換した文章に部品と同じ見た目と余白を付けるだけで、見た目の選び分けを持ちません。記事の見た目を作り込むのは、使う側の仕事です。見た目を変えたいところには、部品を直接置きます
- 入力方式や画面の判定は、使う側が固定できるようにします
- 部品にするほどでない組み合わせは、部品にせず、組み合わせの見本として示します

経緯: ADR-0044、0096、0099、0132、0164

## 21. アイコンは文字に合わせる

アイコンは文字の仲間です。大きさも太さも、並ぶ文字に合わせます。

- 大きさは、周りの文字の大きさに比例させます。部品の中では、部品の文字と並ぶ大きさです
- 文字と並ぶときは細い線、アイコンだけで置くときは太い線にします。単独で置くと、細い線は弱く見えるためです
- 入力欄の中のアイコンは、欄の文字と同じく、指でも小さくしません
- 色だけで伝えず、形でも見分けます（[原則 6](#6-色は役割で持つ)）

経緯: ADR-0018、0080、0114、0164
