# デザイン原則

このドキュメントは、かずえもんがデザインをどう捉えているかを書いたものです。@kazuemon/ui の部品を作るときも、使うときも、迷ったらここに戻ります。

原則は「こう考えているので、こう見える」の順に書いています。数値やトークン名は書きません。値は [`tokens.css`](./tokens.css) に、決めた経緯は [`adr/`](./adr/) にあります。

## 存在理由

デスクトップ優先の UI はモバイルに合わず、モバイル優先の UI はデスクトップで密度が低くなります。どちらにも、それぞれに合った密度の部品が欲しい。それがこのシステムを作る動機です（[原則 11](#11-密度は入力方式で構造は指の動きで切り替える)）。

## 判断の基準

候補を選ぶとき、また作っていて迷ったときは、次の 4 語に最も近いものを選びます。

| 基準の言葉     | 画面で見るところ                                 |
| -------------- | ------------------------------------------------ |
| **軽い**       | 影は弱く、線は細く、余白は多い                   |
| **やわらかい** | 角が丸い。文字は黒ではなく濃紺グレー             |
| **整然**       | 部品の構造がそろっている（3 層構成、状態の規則） |
| **人懐っこい** | 水色・ピンク・pill・和欧併記                     |

### 顔は、構造を実直に、個性をトークンに

構造（状態の表し方、影、塗りと枠線）は実直にします。個性（色、角丸、文字、和欧併記）はトークンに出します。「整然」は構造が、「人懐っこい」はトークンが担います。

構造まで個性的にすると、部品が多く並ぶ画面でうるさくなります。構造だけにすると、どこにでもある没個性な見た目になります。

### ポップさは、トークンと動きで出す

温かみとポップさは、色や角丸と、押したときの動きで出します。動きは静止画では見えないので、整然とした見た目を崩さずに足せます。部品の内部に装飾は持ち込みません（[原則 9](#9-遊びはレイアウト層に置く)）。

### 反例

次の見た目は、基準から外れています。

- マテリアルデザインのような、影で階層を作る硬い見た目
- 字間を大きく空けた英字ラベル。AI が作ったように見えます

## 1. 影はレイヤーの離れを表す

画面は 1 枚の面（ページ）です。影が付くのは、ページから離れているものだけです。離れているものは 2 種類あります。押せるものと、ページの上に重なる別のレイヤーです。

押せるものは、押すために少し浮いています。押すと沈んで、ページに着きます。

- 押せる塗りのものには、輪郭程度の薄い影を付けます
- hover で影が減り、押すと沈みます（[原則 3](#3-hover-は手応え押すと沈む)）。沈んでも縁の線は残します。縁まで消すと、縮んで見えるためです
- 白いものを白い地に浮かせるときは、影だけでは縁が分かりません。細い輪郭を足します

別のレイヤーは、ページの上に重なっています。選択肢、ボトムシート、画面の横から出すパネル、メニュー、ダイアログ、押して開く吹き出し、マウスを載せて出る補足です。下の内容と切り分けるには、面の明るさの差だけでは足りません。

- 重なるレイヤーには、やわらかく広い影を付けます。押せるものより高く見えます。輪郭は、白いものと同じ細い線です
- 画面の端から出る面の影は、出てくる向きへ向けます。画面の外に落ちる影は見えないためです
- 小さく短い補足の影は、小さく淡くします。大きな面と同じ影では、重く見えます。輪郭だけで切り分ける形も選べます
- 一覧が途中で切れるときは、上下の端に内側の影を落として、続きが下にあることを見せます。文字やぼかしでは知らせません。これも重なりの影で、押せることは表しません
- スクロールする枠のつまみは、ふだんは隠しておき、枠にカーソルを載せたときやスクロールしているときだけ出します。つまみそのものに載せると内側へ膨らみ、つかめることを見せます。内側の影を出さない枠では、続きを伝える手段がほかにないので、つまみをいつも出しておきます

ページと同じレイヤーにあるものには、影を付けません。お知らせ、カード、入力欄、タグと、記事の中の引用、囲み、表、画像、コードです。

- これらの区別は、面の明るさと余白で付けます。カードが浮いて見えるのは、影のためではなく、背景より明るい面だからです
- 影が表すのは、物理的な離れ方だけです。情報の重要さを影で積み上げると、マテリアルデザインのように硬く重くなります（反例）
- レイヤーはページとその上しかありません。浮いているものが少数になるので、画面が軽くなります
- キーボードのキーは押すものの絵ですが、部品としては押せません。影は付けず、下辺の線を太くして厚みを見せます

影を落とすのは塗りです。枠線のボタンやリンクには塗りがないので、影も出ません。枠線は塗りの見た目のフレーバーであり、浮いているかどうかとは別です。塗りにするか枠線にするかは、[原則 7](#7-塗りか枠線か) で決めます。

押せなくなったもの（無効、送信中）は、浮いていません。

- 影を消します
- 影を消すだけでは、スイッチの OFF と紛れます。本体の見た目も変えます。色を持つものは色を残して薄くし、色を持たないものはグレーに寄せて文字も薄くします
- 色を残せないもの（トグルのノブ、リンク）は、色を指定していてもグレーにします。地に対して薄い色が残ると、かえって見えなくなるためです
- ON と OFF のように状態が2つあるものは、押せないときは同じ地に置き、ノブの位置や印のあるなしで見分けます。押せるものと同じ色にすると、押せるかどうかが読めなくなります
- 押せないことと、エラーのような状態が重なるときは、押せない見た目を優先します。エラーは下の行の文で伝わるので、枠線や赤い塗りは出しません
- ラベルとキャプションは変えません。「変更できません」などの説明を読めるままにするためです
- 押して反応する文字（チェックボックスの横の文字）は、本体の一部です。本体と一緒に薄くします
- 送信中も押せない見た目にします。ただし、動いている印は薄くしません。薄くすると、止まっているのか進んでいるのか分からなくなるためです

経緯: ADR-0006、0024、0025、0026、0029、0033、0034、0036、0037、0042、0043、0047、0067、0069、0072、0082、0102、0106、0108、0119

## 2. 状態は枠線で表す

フォーカスやエラーは、いつ見ても分かる「状態」です。一般的な、濃くしたり薄くしたりする方式は使いません。明るさの変化は hover の手応え（[原則 3](#3-hover-は手応え押すと沈む)）に使うので、状態まで明るさで表すと区別がつきません。ふだんの入力欄には枠線がないので、枠線を足すだけで目に入ります。

- 入力欄は、ふだんはグレーの塗りで枠線がありません
- フォーカスすると、塗りはそのままで、枠線だけが付きます。塗りが白に変わって同時に枠線が付く形は、変化が大きすぎました
- 枠線の色は部品の色です。色を指定していない部品と、色を持たない欄では、本文と同じ濃紺になります
- エラーは、赤い枠線に加えて、塗りも淡い赤にします。明るさはグレーの塗りとほぼ同じで、変わるのは色相だけです
- エラーの欄にフォーカスしたときは、赤い枠線を残したまま、その外に白を挟んで、部品の色の線を離して引きます。いま操作している場所と、直すところの両方が同時に見えます
- hover に枠線は使いません。枠線はフォーカスのものです

変化の大きさは、知らせたい強さに合わせます。

- フォーカスは操作のたびに起こるので、枠線を足すだけにします
- エラーは見落とされると困るので、枠線と塗りの 2 つで知らせます
- 変化を小さくしたいときは、変わるものの数を減らします。枠線を細くはしません
- 状態の移り変わりは速くします。ゆっくり変わると、操作できるまでのラグに見えます

ボタン、リンク、トグルにも、キーボードで操作したときだけフォーカスの線を出します。マウスやタップでは出しません。

- 線は部品から少し離して描きます。部品の色ではなく地の色と比べることになるので、青やピンクのボタンでも線が溶けません
- 線の色は部品の色に従います。色を指定していない部品は濃紺です。動くのは線の色だけで、位置は動かしません
- 濃い塗りの上（塗りのお知らせの中）では、濃い線が見えません。そこでは線をお知らせの文字の色にします
- いまいる場所を示す線は、同時に 1 本です。入力欄の中のボタンにフォーカスしているあいだは、欄の枠線を消してボタンの線だけにします。エラーの赤い枠線はフォーカスではなく状態なので、消しません
- 一覧の中をキーボードで選んでいるときは、その項目を線ではなく hover と同じ塗りで示します。線を引くのは、一覧の外にある部品です

ほかの操作を止める面（ダイアログ、シート）を開いたときは、フォーカスを面の中へ移します。閉じると、開いたものへ戻します。

- 移る先は、その場面で最初に触るものです。入力を求める面では最初の欄、取り消せない操作を確かめる面では取り消しの側に置きます
- 使う側が決めないときは、面の中で最初に止まるものへ移します。指で開いたときは面そのものへ移し、線を出しません

経緯: ADR-0019、0021、0022、0031、0040、0043、0047、0070、0071、0072、0109

## 3. hover は手応え、押すと沈む

hover は状態ではなく、マウスを載せたことへの反応です。状態（[原則 2](#2-状態は枠線で表す)）より小さく、明るさで表します。押したときは、押せるものすべてが一段沈みます。

- 影のあるものは、hover で影が減ります。押しても影は hover から変えず、色も薄くしません。変わるのは、わずかに下へ沈むことだけです。hover と押下は、沈むことで見分けます
- 入力欄は、hover で塗りが半段濃くなります。押すとフォーカスに移ります
- 枠線のボタンとリンクは、hover で文字の色を淡く敷きます。青いボタンは淡い青、ピンクなら淡いピンクです。新しい色相を持ち込まないので、原則 2 とぶつかりません。押すと敷く色が濃くなり、沈みます
- 文字のリンクは、文章の中にあるので背景を敷きません。敷くと目立ちすぎます。ふだんは淡い下線で、hover で下線だけが文字より濃くなります。押すと沈むだけです
- 文章の中の小さなリンク（脚注の番号や、戻る印）も文字のリンクと同じです。アイコンだけのリンクにも、下線を引きます
- チェックボックスとラジオの箱も、押すと沈み、塗りが濃くなります。箱を押しても横の文字を押しても同じです。状態そのものの切り替わり（選んだかどうか）は、動かさずにすぐ切り替えます
- 一覧の項目（選択肢、メニュー）は入力欄の仲間で、hover とキーボードの選択はどちらもグレーの塗りで示します。危険な項目だけは、赤い枠線のボタンと同じく赤を淡く敷きます。押しても沈みません。押した瞬間に一覧が閉じるためです
- 行全体を押せるもの（囲みや区切り線で範囲を見せたトグルの行）は、hover で行を淡く塗り、押しても濃くしません。行ごと沈めるとページが揺れて見えるので、押したことは中の部品の縮みで伝えます

押す動きは、素早く沈み、弾ませません。手応えとして十分で、待たせません。

- 指で操作するときは hover がありません。押したときの変化を、hover より明らかに付けます
- 読み込み中の場所取りは、面を横切るやわらかく淡い光で、読み込んでいることを伝えます。光は目立たせすぎず、待っていることが分かる程度にとどめます
- 動きを減らす設定では、小さな動き（回る円）は止めずにゆっくり続け、大きな動き（幅いっぱいを横切る線や、読み込み中の面の光）はその場の明滅に置き換えます。ふわっと出る動きはなくし、すぐに出します。待っていることは伝え続けたいためです

経緯: ADR-0009、0022、0027、0030、0033、0042、0047、0063、0066、0067、0089、0115

## 4. 部品は「ラベル / 本体 / キャプション」の 3 層

部品は単独では置かれず、名前と説明を伴います。ラベルは太字で本体の上、キャプションは小さくグレーで本体の下です。ボタンにもキャプションが付きます。これは例外ではなく既定です。

- キャプションは省略できます。省略してもレイアウトは崩しません
- ボタンのキャプションは、本体の下に中央寄せです。ボタンの見た目のリンクにも同じように付きます
- トグルは、トグルとラベルを1行に置き、キャプションはその行の外に出します。キャプションの有無や長さで、トグルとラベルの位置は動きません。キャプションに淡い面を敷く形も選べます

入力欄のヘルプテキストは、本体を読む前に知っておくことです。ボタンのキャプションとは別のもので、左寄せです。

- 既定では本体の上に置きます。本体の下にも置けます
- エラーと警告は、入力した結果です。本体の下に、アイコン付きの行として足します
- エラーや警告が出ても、ヘルプテキストは消しません。入力の決まりを読みながら直せるためです
- エラーは丸の「!」と赤、警告は三角とオリーブ色です。色だけでなく形でも見分けます。警告は送信を止めないので、欄の見た目は変えません
- うまくいったことや補足も、同じ形の行で出せます。成功は丸のチェックと緑、情報は丸の「i」と青です。並びはエラー、警告、成功、情報の順で、欄の見た目を変えるのはエラーだけです。成功のときは、欄の右端にも小さなチェックを置けます
- 両方あるときは、両方出します。エラーが上です
- 行が出ても、本体とヘルプテキストは動きません。下の内容は、跳ばずに滑ります

エラーや警告が出たことは、読み上げでも知らせます。割り込みはしません。

- 欄を離れたときやあとから確かめたときは、いまの読み上げが終わってから知らせます。エラーだけを割り込ませると、移った先の欄の名前が聞こえなくなります
- 送信したときは、最初のエラーの欄へフォーカスを移します。欄の名前と説明が読まれるので、ほかに何もいりません。長いフォームでは、エラーの一覧をフォームの上に出して、そこへ移す形も選べます
- 読み上げの説明は、見た目の順です。ヘルプテキスト、エラー、警告の順で、文字の prefix・suffix があるときはその前に来ます

選択肢に説明が付くこともあります。

- 選べない選択肢は選べなくし、理由を 2 行目に出します。選べるが知っておくことがある選択肢には、警告の 2 行目を付けます。理由は選択肢ごとに違うので、まとめて見出しにはしません
- ボトムシートの見出しも、ラベル、ヘルプテキスト、エラー・警告の順です
- どの文を出すかは使う側が決めます。部品は渡された文をそのまま出し、組み立てません

経緯: ADR-0041、0044、0052、0058、0060、0068

## 5. 角丸は部品と包むもので分ける

角丸は、何であるかを表します。部品は部品の角、部品を包むものは一段大きい角、小物は pill です。高さに比例させる規則は採りません。密度を切り替えると見た目が変わり、そろえたいときに困るためです。

- ボタン、入力欄、お知らせは同じ角です。お知らせは部品なので、カードの角にはしません
- カード、ボトムシート、画面の横から出すパネル、ダイアログは、部品より大きい角です。どれも部品を包むためです
- 浮かぶ面（選択肢、メニュー、押して開く吹き出し、マウスを載せて出る補足）は、包むものではないので部品の角です
- 画像はカードの角です。記事の中でも外でも変わりません。コードの枠と、外枠を付けた表は、部品の角です
- タグ、トグル、枠線のリンクは pill です
- チェックボックスは小さな角丸の四角、ラジオは完全な丸です。同じ仲間ですが、形で見分けます
- 見た目がボタンなら、要素がリンクでもボタンの角です。要素ではなく見た目で決めます
- 何かの内側に収めるものの角は、外側の角から余白を引いた同心の角です。入れ子のカードの画像や、内側に浮かせた prefix・suffix がそうです

カードは 2 つの型を用意します。画像を端まで届かせる標準の型と、画像を内側に収める入れ子の型です。入れ子の型の角を控えめにする案も比べましたが、どちらも同じ角にしました。画像の比率はどちらも同じです。

経緯: ADR-0008、0014、0016、0017、0031、0035、0037、0043、0046、0047、0087、0090、0092、0102、0104、0116

## 6. 色は役割で持つ

色には役割があります。水色はブランドの色で、見出しとロゴに使う構造の色です。青（Primary）とピンク（Secondary）は、色を持つ部品で利用者が選ぶ色です。情報、成功、警告、危険の 4 つは状態の色です。

- 青とピンクに用途の区別はありません。その場所に最も合う色を、使う側が選びます
- 色を指定しないとき、色を持つ部品はすべてグレーです。塗りのボタンはグレーの塗り、枠線のボタンとリンクはグレーの線と文字、トグルの ON は濃いグレーになります
- 選んでいることを示す印（一覧で選んだ項目、チェック、トグルの ON）も、部品の色に従います。指定しないときはグレーです。フォーカスの枠線と線も同じで、色を指定していない部品では濃紺になります（[原則 2](#2-状態は枠線で表す)）
- 水色は明るいので、白地では大きい文字にしか使えません。水色の面に載せる文字は濃紺です

状態の色は、利用者が選ぶ色とは別です。お知らせ、タグ、入力欄の下の行、白地の文字やアイコンに使います。

- 情報は Primary と同じ青です。色相がほとんど同じ別の青を持っても、見分けられません
- 危険は、ピンクと並んでも見分けられるよう、色相はそのままに明度を下げた赤です。ピンクは主要な操作にも使えるので、削除のボタンの隣に並ぶことがあります
- 警告は、黄色を塗りに残します。黄色に白い文字は載らないので、黄色の上の文字とアイコンは濃紺にします。白地に置く文字、枠線、アイコンは、同じ色相で暗くしたオリーブ色です
- 成功と警告の文字は明るさが近いので、アイコンの形でも見分けます。情報は丸の「i」、成功は丸のチェック、警告は三角、危険は丸の「!」です

淡い面に、同じ色相の濃い文字を載せます。タグと、お知らせの既定の見た目です。

- タグは、利用者が選ぶ色と状態の色のどちらも持ちます。近い組み合わせ（情報と青、危険とピンクの面）があっても、文言で見分けます
- お知らせは、淡い面が既定です。白文字が載る濃い塗り、白い面に色の枠線、グレーの面に色の小さな題も選べます。警告の濃い塗りだけは、黄色に濃紺の文字です。色を持たないグレーのお知らせもあります
- お知らせの形は、アイコンの右に太字の題、本文、操作を縦に積み、閉じる印を右上に置きます。操作には白いボタンか文字のリンクを置け、中のリンクはお知らせの文字の色になります
- 読み上げでは、危険だけが割り込み、ほかは静かに知らせます
- 記事の中にはじめからある補足や注意は、お知らせと同じ見た目の囲みにします。囲みは知らせるものではないので、読み上げでは補足として扱い、閉じる印や操作を持ちません。見た目が同じでも働きが違うので、部品を分けます

記事の中の色は、読みやすさを先にします。

- 記事の中のリンクは、押せる文字を本文と見分けやすいよう、Primary の青にします
- 文中のコードは、周りの文字の色を淡く敷きます。白地、グレーの面、色の面、濃い塗りのどこに置いても、地より一段濃い面になります
- 目立たせたい言葉は、黄色を薄く敷きます。Primary の青の補色なので、青いリンクと紛れません
- コードの色分けは、ブランドの色を混ぜず、GitHub のテーマに近い専用の色の組で持ちます。ブランドの水色、青、ピンクを混ぜると、青と紫の区別がつきにくくなるためです。明るい地と濃い地の両方を持ちます

経緯: ADR-0007、0012、0013、0023、0028、0038、0043、0071、0081、0084、0091、0094、0096

## 7. 塗りか枠線か

画面で最も進めたい操作は塗り、それ以外は枠線です。密度の高い並び（カードの中のリンク、SNS のアカウント一覧）では、塗りが重すぎるので枠線に落とします。

- 枠線のリンクは、枠線のボタンと同じ寸法です
- 押せる範囲は、見た目の範囲と一致させます。見えない広がりは付けません。押して切り替わる横の文字（チェックボックスやトグルのラベル）も、文字の幅だけが押せます。範囲を広げたいときは、囲みや区切り線でその範囲を見せます
- 文字のリンクは、文の中では周りの文字の大きさのままです。文の外に置いたときは、部品の文字と同じ大きさになります。押せる範囲は文字の行だけです。広い範囲が要るときは、文字のリンクを広げずに、ボタンの見た目のリンクにします
- 幅いっぱいに広げた枠線のリンクは、文字とアイコンをまとめて中央に寄せるのが既定です。文字を左、アイコンを右端に置く形も選べます。並べているかどうかを部品は知らないので、使う側が選びます

部品は働きで選びます。別の場所へ移るものはリンク、その場で実行するものはボタンです。見た目は働きとは別に選べ、リンクにもボタンと同じ見た目があります。見た目の決まりは1か所なので、ボタンとリンクでずれません。

- ボタンと見分ける印として、ラベルの後ろに右上向きの矢印を必ず付けます
- キーボードの振る舞いはリンクのままです。Enter で移り、Space では移りません
- リンクは送信中を持ちません
- 新しいタブで開くリンクには、読み上げに「新しいタブで開きます」を足します。文字のリンクは、新しいタブのときだけ文字の後ろに小さな矢印を付け、下線を矢印まで伸ばします。枠線のリンクは、使う側が置いたアイコンを使い、なければ矢印を付けます

押せないリンクは、押せないボタンと同じ扱いです。

- ボタンの見た目と枠線のリンクは、押せないグレーのボタンと同じ見た目にします。色を指定していてもグレーです。矢印は残します
- 文字のリンクは、色と下線で押せることを表しています。押せないときはその両方を外し、ただの文字と同じ見た目にします。矢印も付けません
- 押せないリンクは Tab で止まらず、読み上げでは「利用不可」と読まれます。押しても何も起きません

経緯: ADR-0039、0046、0047、0048、0056、0073、0098

## 8. 入力欄の様式は「編集できるか」で決まる

編集できる欄はグレーの塗り、読み取り専用の欄は下線だけです。使う人から見ると「下線が出てきたら読むだけ」という規則になります。この対応は崩しません。

- 文字のリンクの下線は、この規則とは別です。文字の下にだけ引く淡い線で、欄の幅いっぱいに引く下線とは形が違います

prefix・suffix（「https://」「円」、パスワードの表示切り替え）は、入力欄の一部です。

- 入力欄と同じグレーの、欄の端に接した塊です。区切りは入れません。内側に浮かせる形も選べます
- フォーカスとエラーの枠線は、塊の外側にも途切れずに続きます
- エラーのときは、塊も赤みを帯びます。グレーのままだと、赤くなった欄の中で塊だけが浮いて見えます
- suffix に入れるボタンは、パスワードの表示・非表示のように、欄そのものを操作するものだけです。検索のように内容を送るボタンは、欄の外に色か枠線のボタンとして置きます。グレーのボタンにすると、グレーの欄と見分けがつきません
- 文字の prefix・suffix は、読み上げでは欄の説明の先頭に来ます。見えている文字は読み上げから外し、二度読ませません

チェックボックスとラジオは、入力欄の仲間です。

- ふだんはグレーの塗りで枠線がなく、影もありません。塗りはトグルの OFF と同じ濃さで、小さな箱でも白い地の上で分かります。hover で塗りが半段濃くなります
- 選ぶと、指定した色の塗りと白い印になります。指定しないときは、トグルの ON と同じ濃いグレーです
- チェックボックスは角丸の四角、ラジオは完全な丸です（[原則 5](#5-角丸は部品と包むもので分ける)）
- 横の文字は押しても反応するので、本体の一部です。無効では本体と一緒に薄くなります
- エラーでは、箱の塗りを淡い赤にし、内側に赤い線を引きます。塗りだけでは、ふだんの箱との差が小さすぎました。エラーの文は、選択肢の下に、入力欄と同じ形（アイコン付きの行）で付けます

待っているあいだ（入力した値を確かめている、選択肢を読み込んでいる）は、止めない形が既定です。打っている途中で入力を止めないことを優先します。

- 止めない形は書き換えられます。欄の端に回る印を足すだけで、Select は開けます。開くと、選択肢の下に読み込み中の行が出ます
- 止める形は、押せない欄の見た目にします。印は薄くせず、フォーカスとエラーの枠線は残します。Select は開けないので、開ける印（▼）を隠し、その場所に回る印を置きます
- 押せない欄で、文を出しているところは薄い文字、値が入っているところはさらに薄い文字です。文と値を見分けるためです
- 止めているあいだも、suffix のボタンは押せます。止めるのは値の書き換えで、suffix のボタンは値を変えないためです

フォーム全体を送っているあいだは、値を変えるものをすべて止めます。入力欄も、チェックボックス・ラジオ・トグルも、押せない見た目にします。フォーカスは外さず、送る値も変えません。

経緯: ADR-0024、0030、0035、0040、0042、0047、0058、0059、0062、0070、0072

## 9. 遊びはレイアウト層に置く

巨大な背景文字、隅のキャラクター、見出しの絵文字といった装飾は、部品の外側に置きます。部品の本体は、いつも真面目なままです。

- 装飾を部品の内部に取り込みません。部品を再利用できるままにするためです
- 記事の本文の部品は、変換した文章に部品と同じ見た目と余白を付けるだけで、区切りの線や見た目の選び分けを持ちません。記事の見た目を作り込むのは、使う側の仕事です。見た目を変えたいところには、部品を直接置きます
- 見出しの折り返し方も、部品では決めません。使う側が文章に合わせて選びます

経緯: ADR-0001、0096、0099

## 10. 和欧併記

日本語の見出しに英語のサブを添えるのが、基本の単位です。

- 英語のセクションラベルは、すべて大文字、太字、前景用の水色です。参照画像では大文字、先頭だけ大文字、イタリックと揺れていましたが、大文字にそろえます
- 字間は空けすぎません（反例）

和文と欧文を混ぜても、文字は行の中央にそろえます。

- 和文フォントは、そのままだと欄の中で少し上に寄ります。フォントの縦の寸法を漢字の枠に合わせて補正します。欧文フォントは元のままです
- 行の高さは整数の値にし、部品の高さとの差を偶数にします。端数があると、置かれた位置によって文字だけがずれます
- 小文字の欧文が下に寄って見えるのは、欧文の組版として普通の見え方です。補正しません

経緯: ADR-0010、0032

## 11. 密度は入力方式で、構造は指の動きで切り替える

「デスクトップ／モバイル」を 1 つの判定にせず、原因ごとに分けて切り替えます。

押すものは、指で押せる大きさを基準にします。一方で、スマホは画面を目に近づけて見るので、パソコンより小さい文字でも読めます。押すものの大きさはそのままに、文字だけを指で小さくするのが、手に持つ画面に合った形です。

- 部品の高さと余白は、入力方式によらず同じです。マウスでも、指で押せる大きさを保ちます。文字が大きいマウスで高さを詰めると、窮屈に見えるためです
- ページを囲む左右の余白は、押すものではありません。指で操作しているかどうかではなく、画面の幅で決めます。部品の大きさとは決まる理由が違うので、分けて考えます
- 部品の中の文字と、設定画面のような機能の画面の本文は、指で操作しているときに小さくします。部品の文字と本文は同じ大きさにそろえます
- 入力欄（文字を打つ欄と、選ぶ欄）の値と選択肢だけは、指でも小さくしません。小さい欄にフォーカスすると画面を拡大してしまう端末があり、入力のたびに画面が動くためです。見た目が同じ仲間の欄は、同じ大きさにそろえます
- ラベルとキャプションは、入力方式によらず同じ大きさです
- 記事のような読みものでは、指で操作していても文字を小さくしません。長い文を読む場面では、一度に見える量より読みやすさを優先します
- 見出しは本文に合わせて段を付けます。本文が小さくなるときは、見出しも一緒に小さくなります
- 一度に見える量を優先するものは、読みものの中でも指で小さくします。表は、指では機能の画面の本文と同じ大きさです。コードは、入力方式によらず、読みものの中でもいつも同じ小さめの大きさです
- 記事の中の見出しと区切りの上の余白は、マウスでは広く取って節の切れ目をはっきりさせ、指では画面が狭いので詰めます
- 見出しのすぐ後ろは、段落より詰まって見えるリストを少し空けます。線や面で大きく見える引用や画像は、マウスでは空け、指では詰めたままにします
- 指用の高さは、場面によってさらに大きくできます。大きくするのは押すものの高さです。トグルも高さに比例して大きくなります。タグは押さないので、文字の大きさに従います
- 寸法を大きくしても、押せる範囲は見た目の範囲のままです。見えない広がりを足して押しやすくはしません（[原則 7](#7-塗りか枠線か)）
- 構造（浮かぶか、画面の下から出るシートか）を変えてよいのは、浮かぶ UI だけです。Select、Menu、Dialog、Tooltip、Popover です。ほかの部品は構造を変えません
- シートにする理由は画面の狭さではなく、指の動きを減らすことです。指で操作していて、かつ画面が狭いときだけシートにします。タブレットとマウスでは浮かべたままです。この判定は、浮かぶ UI で共通です
- シートでは、下に並べる操作を幅いっぱいにして縦に積み、主な操作を上に置きます。指を大きく動かさずに押せるためです。浮かべるときは、横に並べて端に寄せます。積む順は使う側が選べます
- マウスを載せて出る補足は、指では長押しで出します。長押しで出したものは、押したことにしません。指で触った場所の下は指と手で隠れるので、長押しで出すときだけ、向きを上に差し替えます。指で読めないと困ることは、この補足に置かず、押して開く吹き出しやキャプションで見せます
- シートの上端のつまみは、引けることの印です。はじいて閉じられるか、引いて高さを変えられるときに出します。どちらもできないときと、横から出すパネルには出しません
- どちらの判定も、使う側が固定できるようにします。読みものかどうかも、使う側が決めます

経緯: ADR-0004、0020、0037、0045、0065、0078、0079、0090、0092、0097、0100、0102、0105、0106、0110、0120

## 12. 色は面用と前景用の 2 段で持つ

色のコントラストは、候補を作るときの制約です。あとから確かめるものではありません。テイストを保ったまま基準を満たすため、各色を 2 段で持ちます。

- 面用は元の値です。塗り、ロゴ、装飾に使います
- 前景用は、色相と彩度を保ち、明度だけを基準を満たす最小限まで下げた値です。文字と枠線に使います
- 白い文字を載せる面は、前景用の値を使うか、文字を濃紺にします。黄色のように前景用を作っても白文字が載らない色は、文字を濃紺にします
- 基準を満たせない面（スイッチの OFF）には、輪郭を足しません。状態はノブの位置と影で伝え、押せない OFF との区別は押せない側の見た目で付けます

経緯: ADR-0002、0003、0005、0011、0029、0038、0067
