# 0355. Sidebar に足す操作は、入れ子の末尾の「作成」の行に置く

- ステータス: Accepted
- 日付: 2026-09-24
- ラウンド: Sidebar の実装を見てもらった直し

## 背景

ステージやグループを足す操作を、はじめは行の右端の「＋」ボタン（`action`）で作りました。実装を見てもらうと、行ごとに「＋」・開閉の矢印・新しいタブの矢印が並び、アイコンが混ざって見えました。

## 候補

比較のストーリーは作っていません。実装を見てもらい、直しの指示を受けました。

| 案        | 内容                                                                                      |
| --------- | ----------------------------------------------------------------------------------------- |
| A         | 行の右端に「＋」のボタンを重ねる（`action`）                                              |
| B（採用） | 入れ子の末尾に、「＋ 作成」の行を置く。行き先を持たない `SidebarItem`（`onClick` で足す） |

## 決定

**足す操作は、その入れ子の末尾に置く「＋ 作成」の行にします。`SidebarItem` の `action` は作りません。行き先を持たない `SidebarItem` に、アイコンと `onClick` を渡します。**

## 理由

ユーザーの返事の原文です。

> 思いの外アイコンの混在が複雑に見えたので、ステージとステージ内のグループについて、プラスボタンではなく、末尾の [ + 作成] というメニュー項目になっている設計に変更してもらえますか

行の右端に置く操作は、開閉の印と新しいタブの印と並んで、1 行に印が 3 つ並びます。末尾の行にすると、印は行の左（アイコン）と右（開閉・新しいタブ）に分かれ、足す操作は「一覧の最後の項目」として読めます。畳んだ列の面（Menu）でも、同じ行がそのまま項目になり、指の画面でも hover に頼りません。

これは [ADR-0353](./0353-sidebar-current.md) に書いた、行の末尾の操作をいつも見せる仮定を置き換えます。

## 影響

- `src/components/sidebar/`: `SidebarItem` に `action` は持たせません。行き先（`href`）も `render` も持たない行は、押すと `onClick` を呼ぶ行になります（畳んだ列の面では Menu の項目になります）
- 見本（`Overview/見本`「試合管理」）は、ステージ・各リーグの末尾に「作成」の行を置きます
