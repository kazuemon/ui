# 0395. 左右を空けた線（inset）は作らない。線は親の余白の中で目一杯伸び、空けるのは親の余白か className

- ステータス: Accepted
- 日付: 2026-10-01
- ラウンド: 後半 軸 410

## 背景

パネルの中の区切りとして、左右の端を空けた線（`variant="inset"`）を足すかを比べました。空け幅の案は、部品の左右の余白（16px）と、入れ子のカードの内側（8px）でした。

## 候補

比較は [ADR-0394](./0394-divider-vertical.md) と同じ軸 410 の比較のストーリー（決めた時点のコミット `244dd6a`）です。

| 案     | 左右を空けた線                                               |
| ------ | ------------------------------------------------------------ |
| 現行版 | なし（幅いっぱい）                                           |
| A・B   | 部品の左右の余白（16px）だけ空け、中の文字の始まりにそろえる |
| C      | 8px だけ空ける（入れ子のカードの内側と同じ）                 |

## 決定

**左右を空けた線は作りません。** 線は、今の横線と同じく、親の余白（padding）の中で目一杯伸びます。左右を空けたいときは、置く側の余白か `className` で空けます。

- 空け幅は、置かれる場所で違います。部品は置かれる場所を知らないので、決めません（[原則 20](../principles.md#20-部品は知らないことを決めない)）
- 線が親の余白を満たすので、親の余白を変えれば線の端も動きます

## 理由

ユーザーの返事の原文です。

> 410「高さは文字の高さで、inset の左右の余白はユーザー次第だと思ったので、基本は親の padding に依存する（目一杯伸びる）がいいかなと思いました。」

出どころは、トリアージの F68・F121 です。

## 却下した案と理由

- **A・B・C（空け幅を部品が持つ形）**: 採りませんでした。16px も 8px も、置く場所によって合わず、使う側が結局上書きします

## 影響

- `Divider` に `variant="inset"` は足しません
- 比較のストーリーは消しました

## 原則への反映

原則 20 に、「線の左右の空きは、部品が決めず、置かれる親の余白に任せる」を書き足しました。
