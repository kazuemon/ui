# 0237. size は、意味のある段はその名前で、ただの大小は Tailwind の尺度名で

- ステータス: Accepted
- 日付: 2026-09-21
- ラウンド: ループ外（props の監査）

## 背景

`size` が「文字の尺度」「部品の寸法」「最大幅」「バーの太さ」の 4 概念に使われていました。`Container`・`Navbar` の `size` は `prose`・`default`・`wide`・`full`（中身の幅の上限）、`Meter` の `size` はバーの太さ、`Combobox` の `chipSize` は `compact`・`regular` という、`xs`〜`xl` でも `sm`・`md` でもない語彙でした。語彙の案として「上限を `width` と呼ぶ」も検討しましたが、不採用でした。

## 候補

| 案     | 内容                                                                                                                        |
| ------ | --------------------------------------------------------------------------------------------------------------------------- |
| 現行版 | `size` が 4 概念に使われる。意味のある段（`prose`・`wide`・`full`、見出しの段）と、ただの大小が同じ props 名                |
| A      | 幅の上限を `width`、バーの太さを `thickness` に分け、`size` は文字の尺度だけにする                                          |
| B      | `size` を「その部品の大きさの段」と広く定義し、値の語彙だけ `xs`〜`xl` にそろえる                                           |
| C      | 現状維持。意味のある段はその名前で持ち、ただの大小は `xs`〜`xl` で持つ。`Combobox` の `chipSize` だけ `sm`・`md` にそろえる |

## 決定

**C（現状維持）を採用します。** `Container`・`Navbar` の `prose`・`default`・`wide`・`full`、見出しの段のように意味のある段は、その名前を尊重します。ただの大きい小さいは `xs`〜`xl` です。`Combobox` の `chipSize`（`compact`・`regular`）は `sm`・`md` にそろえます。`Tag`・`Badge`・`Chip` の大きさは 1 本の軸で決めます（別途、軸として比べます）。

## 理由

ユーザーの返事の原文です。

> wide, full, prose, default という意味的な命名自体は機能すると思っています。一方で xs-xl については「対応する意味が存在しない尺度」だと思うので、その基準で考えたいです。ただの大きい小さいなら xs-xl で、意味のあるサイズならその名前を尊重します。chipSize は意味とつながっていないので sm/md で良さそうです。

`width` という語については、次の返事です。

> 上限という意味で width を使うのはあまり適していないと思います。

## 却下した案と理由

- **A（幅の上限を `width` に分ける）**: 選ばれませんでした。「上限という意味で width を使うのはあまり適していない」ため
- **B（`size` を大きさの段として広く定義する）**: 検討しましたが、`Container` の `prose`・`default`・`wide`・`full` は段の名前に畳めないため、採りませんでした

## 影響

`Combobox.chipSize` の値を `compact` → `sm`、`regular` → `md` に直します。`Tag`・`Badge`・`Chip` の大きさを 1 本の軸にそろえる件は、別途軸として比べるため、この ADR では扱いません。

## 原則への反映

反映なし。`size` の値の語彙の整理で、部品の見た目・寸法そのものは変えていません。

## 比較画像
