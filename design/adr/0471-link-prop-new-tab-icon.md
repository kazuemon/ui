# 0471. リンクにするかは link で決め、↗ は新しいタブで開くときだけ付ける

- ステータス: Accepted（[ADR-0046](./0046-link-rest.md) の「ボタンの見た目のリンクには ↗ を必ず付ける」を置き換える）
- 日付: 2026-10-03
- ラウンド: トリアージ F41・F97（見た目の比較なし）

## 背景

リンクにするかどうかを、部品は `href` があるか、`render` に渡した要素が `href` を持つかで決めていました。ルーターのリンク（TanStack Router の `Link` など）は `href` ではなく `to` で行き先を受け、サーバーコンポーネントから渡した要素は props を読めません。そのため、`render` にルーターのリンクを渡した Card がリンクにならないことがありました（F41・F97）。

↗ は [ADR-0046](./0046-link-rest.md) で、ボタンの見た目のリンクには必ず付け、文字のリンクとアイコンのない枠線のリンクには新しいタブで開くときだけ付けると決めていました。ボタンの見た目のリンクだけが、同じタブで開くときも ↗ を持っていました。

## 候補

見た目の比較はしていません。レビューの中で、次を順に話して決めました。

- `render` だけで判断する（いまのまま）
- リンクかどうかを明示する `link` を足す。`href` があれば既定で true、渡せば上書きできる
- Link にも `link` を持たせ、`link={false}` では見た目だけを重ねる（`render` がないときは `span`）
- Link から `link` を外し、Link はいつもリンクにする。`render` はルーターのリンクを渡す口にする
- ↗ を出すかを、見た目ごとの決まりではなく、新しいタブで開くかと props で決める

## 決定

**Card は `link` で、カード全体をリンクにするかを決めます。既定は `href` があるかで、`render` に渡した要素の props は読みません。ルーターのリンクを `render` に渡すときは `link` を付けます。Link は `link` を持たず、いつもリンクです。↗ は、どのリンクの見た目でも、新しいタブで開くときだけ付け、`newTabIcon` で上書きできます。**

| 項目                 | 決定                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Card の `link`       | 既定は `href != null`。`true` で `render` の要素をリンクとして扱い、`false` で `href` を渡していても `div` にしてリンクの属性を描く要素に渡さない |
| Link                 | `link` を持たない。描く要素は `render` か `a`。`render` にはルーターのリンクを渡す。`render` だけ渡した Link もリンクとして扱う                   |
| ↗ の既定             | 文字・枠線・ボタンの見た目・下線のリンクのどれも、新しいタブで開くとき（`target="_blank"`、または `render` の要素の `target`）だけ付ける          |
| `newTabIcon`         | `true` で同じタブのリンクにも ↗ を付け、`false` で新しいタブのリンクからも外す。利用者が最後にアイコンを置いたときは、`true` でも足さない         |
| 新しいタブの読み上げ | 「（新しいタブで開きます）」と `rel="noopener noreferrer"` は、`newTabIcon` にかかわらず、新しいタブで開くリンクに付ける                          |
| 名前の決まり         | 既定がほかの props で変わる真偽値は、`hide`・`show` を付けない名前にする（[design/props.md](../props.md) の「出す／出さないの真偽値」）           |

## 理由

- **`render` だけでは決めない**: 「render だけで判断するのはうーんという感じです。断定できないためですね。link かどうかを明示する props をつける（href があるならデフォルト true で上書き可能）かなーと思います」。ルーターのリンクやサーバーコンポーネントから渡した要素は、部品から中身を読めません
- **Link は `link` を持たない**: 「link=false のときに Link の見た目にはなるけど span でレンダリングされる、は違和感があるかなと思っています」「render があるとき→見た目だけ使いたい（単なる a リンクや NextLink を使いたいだけなら、Link コンポーネントを使う意味がない）」。`render` にボタンを渡してリンクの見た目のボタンを作る使い方は、移る操作とその場の操作を見た目で分けてきた決まりと合わないので、想定しません
- **↗ は新しいタブのときだけ、props で上書きする**: 「矢印についてはデフォルトオフ、新しいタブを開くときはオン、props で上書きできる、かなと思いました。newTabIcon とかでいいかなと」。ボタンの見た目のリンクも、文字のリンクと同じ決まりにそろえます
- **読み上げは残す**: ↗ は飾りで読み上げません。↗ を外しても、新しいタブで開くことは読み上げの文で伝えます

## 影響

- `Card` に `link` を足しました。`render` だけを渡していたリンクのカードは、`link` を付けないと `div` になります（破壊的変更）
- `Link` に `newTabIcon` を足しました。ボタンの見た目・下線のリンクは、同じタブで開くときに ↗ が付かなくなりました（`Button` の `ButtonLink` も同じ）
- ボタンの見た目のリンクとボタンは、同じタブで開くときは見た目で見分けられなくなります。働きは読み上げ（リンクとボタン）で分かれます
- `src/internal/link-parts.ts` に `resolveLink`（`link ?? href != null`）を置きました。Tag など、`link` を持つほかの部品も同じ決まりにします（`link={false}` ではリンクにしない）

## 原則への反映

原則 18 の、右上向きの矢印の項を書き換えました（ボタンの見た目のリンクにいつも付ける → どのリンクも新しいタブで開くときだけ付け、変えることもできる）。

## 実装

`feat/link-prop` の `1c3cac3`（Link・Card の `link`）、`1246b6f`（ボタンの見た目・下線のリンクの ↗）、`4c75301`（Link の `link` を外し、`newTabIcon` を足す）。
