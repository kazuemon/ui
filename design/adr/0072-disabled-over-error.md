# 0072. エラーかつ押せないときは、押せない見た目を優先する

- ステータス: Accepted
- 日付: 2026-09-16
- ラウンド: ループ外

## 背景

押せない状態（disabled・送信中・止める形）を部品ごとに見比べるための一覧（[`design/stories/disabled-overview.stories.tsx`](../stories/disabled-overview.stories.tsx)）を作りました。軸の比較（`Comparison`）ではなく、いまの部品をそのまま描いて、見比べるためのストーリーです。

この一覧から、8つの食い違いが見つかりました（会話では番号1〜8で扱いました）。このうち2・3が、入力欄（TextField・Select）が押せない状態とエラーの状態を同時に持ったとき、赤い枠線・エラーの塗り・prefix・suffix の赤みを保ったまま押せない透明度が重なり、2つの状態が同時に主張して見づらいという問題でした。

チェックボックス・ラジオでは、これより前に、選んでいない箱の塗りをトグルの OFF と同じ濃さにそろえたとき（`--color-choice`・`--color-choice-hover`）に見つかった問題（「色を濃くしてそろえたあとに見つかった問題」の2・3）で、すでに「押せなくてエラーでもある箱は、押せないほうを優先する」という形に直していました（`Checkbox.tsx` の `choiceStyles` で、エラーの塗りは `:not([data-disabled])` の箱にだけ効きます）。あわせて、色を持たない押せない ON のトラック・選んだ箱を、押せない OFF・押せない箱と同じ地（`#F2F4F4`）にグレーのノブ・印にしていました（押せる OFF の色 `#E1E3E4` と紛れないようにするため。状態はノブの位置と印のあるなしで見分けます）。

この ADR は、その考え方（押せないほうを優先する）を、入力欄（TextField・Select）にも広げる決定です。一覧のほかの項目（1 押せないリンクの色の食い違い、5 色なしの押せない ON と OFF、6 フォームの送信中のチェックボックス・ラジオ・トグル、7 読み取り専用の TextField、8 押せない欄の prefix・suffix の塗り）は、この ADR の対象外です。1 はリンクの作り方の統一、5・6 は現状維持、7・8 は backlog に残しました。

## 候補

見た目の比較（候補を並べる形）はしていません。「押せない状態の一覧」で見つかった食い違いを、そのまま直しています。

| 対象                     | 直す前                                                                                                                                     | 決定                                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| TextField・Select        | エラーの赤い枠線・エラーの塗り・prefix・suffix の赤みを保ったまま、押せない透明度が重なる                                                  | 押せない見た目を優先する。赤い枠線は引かず、塗り・prefix・suffix の赤みと文字の色を押せないときの値にする。エラーの文（行）はそのまま出す |
| チェックボックス・ラジオ | すでに押せないほうを優先している（[ADR-0029](./0029-disabled-refine.md)・[ADR-0047](./0047-principles-probe.md) の色の詰めの中で対応済み） | 変更なし。入力欄をこれにそろえる                                                                                                          |

## 決定

**エラーかつ押せないときは、押せない見た目を優先します。**

- **TextField・Select**: 押せなくてエラーでもある欄は、赤い枠線を引きません。塗り・prefix・suffix の赤みと、文字の色は、押せないときの値に差し替えます。エラーの文（本体の下の行）は、押せないときも出したままです
- **チェックボックス・ラジオ**: すでに同じ考え方でした（選んでいない箱の塗りは、押せないほうを優先し、エラーの赤みにしません）。この決定で、入力欄も同じ考え方にそろいます

## 理由

「押せない状態の一覧」で見つかった問題への答えです（会話では1〜4の番号で聞きました）。

> 2 押せない見た目を優先したいです。prefix などもお願いします

以下は、答えから読み取れることです。

- **押せない状態を優先する**: エラーは「直すべきところ」を示す状態ですが、押せない欄は書き換えられないので、直しようがありません。赤い枠線や赤い塗りを出し続けると、直せない箇所を強調するだけで意味がありません。押せないことのほうを優先して見せます
- **エラーの文は残す**: エラーの理由そのものは、押せない状態でも意味のある情報です（なぜ押せないかの手がかりになることがあります）。見た目（枠線・塗り・色）だけを押せない値に差し替え、文の行は消しません
- **チェックボックス・ラジオとそろえる**: チェックボックス・ラジオでは、すでに「押せないほうを優先する」形になっていました。入力欄もこれにそろえることで、押せない状態とエラーが重なったときの扱いが部品を通して一貫します

## 却下した案と理由

候補を並べていないため、明確な却下案はありません。直す前の形（エラーの見た目をそのまま保ち、押せない透明度を重ねる）は、2つの状態が同時に主張して見づらいという問題（一覧で見つかった食い違い2・3）のため、そのままにしませんでした。

## 影響

- `src/components/field-styles.ts` の `fieldStyles` の `root`:
  - `data-invalid:not-data-disabled:[--field-invalid-border:var(--color-danger)]` — 赤い枠線の色（`--field-invalid-border`）は、エラーかつ押せる欄にだけ置きます。押せないときは未設定のまま（`controlBox` は `transparent` にフォールバックします）
  - `data-disabled:[--color-field-invalid:var(--color-field-disabled,var(--color-field))]` — エラーの塗り色を、押せないときの塗り色に差し替えます
  - `data-disabled:[--color-field-addon-invalid:var(--color-field-addon)] data-disabled:[--color-on-field-addon-invalid:var(--color-on-field-disabled)]` — prefix・suffix のエラーの赤みも、押せないときのグレーと文字色に差し替えます
- `src/components/field-styles.ts` の `controlBox`: 赤い枠線は `--field-invalid-border`（未設定なら transparent）を読むので、上の root の変更だけで、押せないときは枠線を引かなくなります。文字の色は、押せないときの規則（`group-data-disabled/field:text-[color:var(--color-on-field-disabled,...)]`）がエラーの規則より後にあり、そのまま優先されます
- `src/components/Select.tsx`: 本体は `field-styles.ts` の `controlBox` を共有しているため、追加の変更はありません
- `src/components/Checkbox.tsx`（`Radio.tsx` も同じ `choiceStyles` を使います）: 変更していません。すでに `data-invalid:[&:where(:not([data-disabled]))]:...` の形で、エラーの塗りを押せる箱にだけ効かせていたことを、この ADR で確認しました
- **分かっていること**:
  - 押せない欄の prefix・suffix が、欄本体と同じ塗りになる件（一覧の8）は、あとで考え直すため backlog に残しました
  - 読み取り専用（readOnly）の TextField の見た目（一覧の7）は、まだ作っていません。backlog の TextField の節に残しています

## 原則への反映

原則1（影はレイヤーの離れを表す）の Disabled の箇条書きに、次の一文を足します。「押せないことと、エラーのような状態が重なるときは、押せない見た目を優先します。エラーは下の行の文で伝わるので、枠線や赤い塗りは出しません」。

原則8（入力欄の様式は「編集できるか」で決まる）のチェックボックス・ラジオのエラーの記述は書き換えません。この決定は、原則1に足す一般規則の範囲内です。
