# 0166. 押すと沈むものの範囲

- ステータス: Accepted
- 日付: 2026-09-19
- ラウンド: ループ外

## 背景

原則 3 は「押したときは、押せるものすべてが一段沈みます」と書きながら、同じ原則の中に沈まないものを 3 つ持っていました（一覧の項目、行全体を押せるもの、入力欄）。原則の整理（[ADR-0164](./0164-principles-reorganization.md)）の問い D2 です。並行して作っていたタブ・木の行・パンくずの pill が沈むべきかも、同じ問いでした。

## 候補

| 案             | 内容                                                                                   |
| -------------- | -------------------------------------------------------------------------------------- |
| 離れているか   | 一つずつ離れて置かれた押すものは沈む。並びの一部（一覧の項目、行）は沈めず、塗りで返す |
| 塗りが変わるか | 塗りが変わるものは沈まない、塗りが変わらないものは沈む                                 |
| 押すと消えるか | 押すものは沈む。押した瞬間に閉じて消えるものだけ、沈みがなくてもよい                   |
| すべて沈む     | 一覧の項目と行も沈める形に、実装を寄せる                                               |

## 決定

**「押すと消えるか」で分けます。**

- 押すものは、押すと一段沈みます。押しても残り、画面の一部が切り替わるもの（タブ、木の行、行き先の並び）も沈みます
- 押した瞬間に閉じて消えるもの（一覧の選択肢、メニューの項目）は、沈みがなくてもかまいません。塗りで返せば足ります。あとから沈みを足しても、原則には反しません
- それ自体の動きが手応えになるもの（左右に動くトグル）には、沈みを重ねません。トグルの行を行ごと沈めないのも、このためです

## 理由

ユーザーの返事の原文です。

> ポイントは「押すと消えるか」だと思っていて、Select や Menu は押すと閉じられるので、沈む様子が確認できません。一方で、Tree や CodeGroup のタブ（また Tabs 本体）は、押しても閉じることがなく、画面の一部が切り替わります。なので、沈むことに対して違和感はないとおもいました。Breadcrumb の pill もこちらにあたると思います。

> 閉じると消えるものは「なくても許容する」（閉じた瞬間に見えなくなってしまう可能性があるため）のほうが正しいかもですね。あとから追加する可能性はありそうです。

> トグルの行はトグル自体が左右に動くことがそのまま手応えを表しているので、上下方向の手応えは不要、という形かもしれません。

## 却下した案と理由

- **離れているか**: はじめに台帳で選ばれましたが、タブや木の行（並びの一部だが沈んで違和感がない）を説明できないので、上の返事で置き換わりました
- **塗りが変わるか**: ユーザーのメモ「塗りが変わるものは沈まない、塗りが変わらないものは沈む、というような感じもしています。あまり厳密には測れていないですが⋯」。枠線のボタンとチェックボックスは塗りが変わり、かつ沈むので、いまの決まりと合いませんでした
- **すべて沈む**: 選ばれませんでした

## 影響

- 部品の変更はありません。Tabs、Tree、コードのタブ、パンくずの pill、一覧の項目、トグルの行は、いまの実装のままでこの決定に合います
- トグルの行を沈めない理由を、[ADR-0066](./0066-switch-row-frame.md)・[ADR-0067](./0067-switch-row-press.md) の「行ごと沈めるとページが揺れて見える」から、「トグル自体の動きが手応えになる」に言い直しました。見た目の決定は変わりません

## 原則への反映

原則 3 の考えの文を書き換えました。「押せるものすべてが沈む」と例外の列挙をやめ、沈みがなくてもよい 2 つの場合を理由と一緒に書いています。
