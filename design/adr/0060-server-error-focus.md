# 0060. 送信のあとのサーバーのエラーとフォーカス

- ステータス: Accepted
- 日付: 2026-09-14
- ラウンド: ループ外

## 背景

[ADR-0044](./0044-message-announce.md) では、送信したときに最初のエラーの欄へフォーカスを移す一方、「送信のあとで、あとから（非同期で）出たエラー（サーバーの答えなど）には、フォーカスを移しません。polite で知らせます」と決めていました（ADR-0044「分かっていること」）。

しかし、サーバーから返ってきたエラーも、利用者から見れば送信した結果です。フォーカスを移さないと、どこが悪いかを自分で欄を回って探すことになります。この ADR は、ADR-0044 のこの部分を覆し、Form の `submitting` が終わったとき（送信中に見つかったサーバーのエラーも）、送信したときと同じ規則でフォーカスを移すようにします。ADR-0044 のほかの決定（送信したときの規則、欄を離れたときの polite、シート・選択肢の文など）は変えません。

## 候補

見た目の候補は作っていません。推奨（backlog の F7）をそのまま実装し、実装で分かったことを踏まえてユーザーに確認しました。

## 決定

**送信中（`submitting`）が終わったとき、送ったときの場所（押した送信のボタン、Enter を押した欄。`body` だったときも含む）にフォーカスが残っていれば、送信したときと同じく、最初のエラーの欄（`errorSummary` のときはエラーの一覧）へフォーカスを移します。送っているあいだに別の欄へ移っていたら、フォーカスは奪わず、行を polite で知らせるだけにします。その描画で出た（変わった）行は、読み上げで知らせません（移った先で読むため）。**

サーバーから返ってきたエラーは、`submitting` を `false` にするのと同じ描画で渡す必要があります。先に渡すと、送っているあいだに polite で読まれ、移った先でもう一度読まれます（二重）。あとに渡すと、フォーカスは移りません。この書き方を `Form` の JSDoc に書きました。

| 項目                        | 決定                                                                                                    |
| --------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 条件1                       | 送信中が終わった（`submitting` が `true` から `false`）描画に、エラーの行がある                             |
| 条件2                       | 送ったときの場所（送信のボタン、Enter を押した欄、`body`）にフォーカスが残っている                          |
| 両方満たすとき              | 送信したときと同じく、最初のエラーの欄（`errorSummary` のときは一覧）へフォーカスを移す                     |
| 条件2を満たさないとき       | フォーカスは動かさず、出た行を polite で知らせる                                                            |
| その描画で出た行の読み上げ  | 知らせない（`aria-live="off"`）。フォーカスの移る先で読むため                                                |
| アプリの書き方              | サーバーのエラーは、`submitting` を `false` にするのと同じ描画で渡す                                        |
| ADR-0044 との関係           | 「あとから（非同期で）出たエラーにはフォーカスを移さない」を覆す。送信したときの規則・欄を離れたときの規則はそのまま |

## 理由

backlog の推奨（F7）です。

> F7: 送信のあとでサーバーから返ってきたエラーも、送信の結果として、送信中が終わったときに最初のエラーの欄（かエラーの一覧）へフォーカスを移す。条件は2つ。その描画で出た行は読み上げで知らせない（移った先で読むため）。送ったときの場所（送信のボタン、Enter を押した欄。body のときも含む）にフォーカスが残っているときだけ移し、別の欄へ移っていたら奪わずに静かに知らせる。ADR-0044 の「非同期のエラーにはフォーカスを移さない」を覆す

実装して分かったことを踏まえた確認への返事です。

> S2, F7, Chip はそれでよさそうです。

## 却下した案と理由

- **ADR-0044 の元の決定（あとから出たエラーにはフォーカスを移さず、polite で知らせるだけ）**: 覆しました。サーバーのエラーも送信の結果であり、フォーカスを移さないと、どこが悪いかを自分で探すことになるためです

## 影響

- `src/components/Form.tsx`:
  - 送信したときにフォーカスのあった場所（`origin`）を、押した送信のボタン・Enter を押した欄・`body` として覚えます
  - `submitting` が `true` から `false` に変わった描画で、`origin` にフォーカスが残っているか（`focusStayedAt`）を見て、残っていればフォーカスを移す回数（`focusCount`）を増やします。残っていなければ増やしません
  - `focusCount`（送信の回数 `submitCount` ＋ この「送信中が終わって移した」回数）が変わった描画のあとで、これまでと同じ処理（`collectErrors` で開いているエラーの行を集め、`errorSummary` なら一覧へ、そうでなければ最初のエラーの欄へフォーカスを移す）を行います
  - `submitting`・サーバーのエラーは、同じ描画で渡す必要があることを JSDoc に書きました
- `src/components/form-context.ts`: `FormSubmitState.focusCount` の説明に、送信中が終わったときにも増えることを足しました
- `src/components/Field.tsx`: `FieldMessageLine` は、これまでどおり `focusCount` が変わった描画で出た（変わった）行を `aria-live="off"` にします。送信中が終わって増えた回数でも同じ仕組みが働きます
- backlog: 記録待ちの該当行（F7）を消します

## 原則への反映

反映なし。原則4には「送信したときは、最初のエラーの欄へフォーカスを移します」とすでに書かれており、この決定はその適用範囲を、送信した直後だけでなく、送信中が終わったとき（サーバーの答えを待った場合）にも広げたものです。原則の文は書き換えません。読み上げの二重防止や、フォーカスを奪わない条件といった細部は、原則の定性的な書き方には含めず、ADR にとどめます。
