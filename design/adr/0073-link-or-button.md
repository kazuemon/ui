# 0073. リンクの作り分け（移動は Link、実行は Button）と押せないリンク

- ステータス: Accepted
- 日付: 2026-09-16
- ラウンド: ループ外（押せない状態の一覧の確認）

## 背景

2026-09-16 に、押せない状態の見た目を一覧にして確かめました。一覧の1で、押せないリンクの見た目が、作り方の経路によって食い違っていることが分かりました。

- Button に `render` で `<a>` を渡す経路（[ADR-0046](./0046-link-rest.md) の「ボタンの見た目のリンク」）は、押せないときも `<Button disabled>` の一般の Disabled（[ADR-0026](./0026-disabled.md)）に従い、色を残したまま薄くする見た目でした
- 枠線のリンク（Link の `appearance="outline"`）は、押せないグレーの枠線のボタンと同じ見た目（グレーの枠線・文字、薄くしない）でした（ADR-0046・[ADR-0029](./0029-disabled-refine.md)）

同じ「押せないリンク」なのに、経路によって「色を残して薄く」と「グレーにする」の2通りの表し方が混ざっていました。確かめると、押せないグレーの枠線のボタンの値は塗り `#E1E3E4`・文字 `#A3A5A6`（薄くしない・影なし）でした。

あわせて、リンク（移動）とボタン（実行）を部品としてどう分けるかも、ADR-0046 の時点では固まっていませんでした。ADR-0046 は Button に `render` を足して見た目を継承させましたが、ボタンの見た目のリンクの入口は Button（`render`）に、それ以外のリンクの入口は Link にと、2か所に分かれていました。

原則5（リンクは pill）・原則6（色は役割で持つ）・原則7（塗りか枠線か、押せないリンクの扱い）に関わります。

## 候補

見た目の候補を並べる比較はしていません。押せない状態の一覧で見つかった食い違いと、部品の分け方についてのやり取りから決めました。話した形は次のとおりです。

| 案                               | 内容                                                                                                                                          |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 現行版                           | リンクにできるボタン（Button の `render`）と、Link の枠線・文字のリンクが並ぶ。押せないときの見た目が経路で食い違う                          |
| A（リンクにできるボタンを廃止）  | ボタンの見た目のリンクは Link に一本化する。移動は Link、実行は Button に、機能で分ける                                                       |
| 見た目の置き場所                 | 「共通のボタンスタイリングから、Button と ボタンを継承した Link にする」。見た目のコードは Button に1つだけ置き、Link がそれを呼ぶ            |

## 決定

**部品は機能で分けます（移動は Link、実行は Button）。見た目のコードは Button に1つだけ置きます。**

| 項目                            | 決定                                                                                                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 部品の分け方                    | 機能で分ける。移動は Link、実行は Button                                                                                                                          |
| ボタンの見た目のリンク          | Link に `appearance="button"` を足す。中で Button を描き、見た目（塗り）は Button に任せる                                                                       |
| 色                              | primary・secondary・neutral                                                                                                                                       |
| 送信中の印                      | 持たない                                                                                                                                                           |
| caption                         | 使える（「外部のサイトに移動します」など）                                                                                                                       |
| 押せないとき                    | 色を指定していても、押せないグレーのボタンと同じ見た目にする（原則7）。`appearance="button"` は `disabled` のとき色を `neutral` に強制して Button を描く          |
| 枠線のリンク                    | pill のまま。枠線のボタンの見た目のリンクは作らない                                                                                                               |
| Button の古い書き方（`render`） | `@deprecated` として残す。Link が中で使うのと、過去の比較のストーリー（軸26・31）が、比べたときの見た目のまま描くために残す                                       |

## 理由

ユーザーのメモです（来た順）。

> 原則7に揃えて、同じ見た目にしてほしいです。というか、リンクにできるボタンは廃止して、ボタンの見た目のリンクに統一するのが正しいかなと思いましたがどうでしょうか？一旦意見だけ

> なるほど。共通のボタンスタイリングから、Button と ボタンを継承した Link にするみたいな感じですね。それであればよさそうです。appearance は button で、色は一旦 primary, secondary, neutral あたりがあればよさそうですね。リンクには送信中のしるしなし、キャプションは同じように使えるようにしたいです（外部サイトに～みたいなのを付けられるので）

> 機能的分割には適していますが、見た目的な分割は難しいですね。

以下は、メモと確かめた値から読み取れることです。

- **機能で分け、見た目は1か所**: 「機能的分割には適していますが、見た目的な分割は難しいですね」。移動と実行という役割は Link と Button で分けますが、見た目（塗り・枠線・色・disabled の表し方）は Button の定義を Link が呼ぶ形にし、二重に持ちません
- **色は3色に絞る**: 「色は一旦 primary, secondary, neutral あたりがあればよさそう」。danger・white は、ボタンの見た目のリンクとしては用意しません
- **送信中は持たない**: 「リンクには送信中のしるしなし」。ページを移るリンクは、送信中という状態を持ちません（ADR-0046 のまま）
- **caption は使える**: 「キャプションは同じように使えるようにしたいです（外部サイトに～みたいなのを付けられるので）」
- **押せないときは、色によらずグレー**: 押せない状態の一覧で見つかった食い違い（色を残して薄い／グレー）を、原則7の「押せないリンクは、押せないボタンと同じ扱いです」「色を指定していてもグレー」にそろえました。測ると、通常も押せないときも、塗りのボタンとの差はゼロで、押せないリンクは押せないグレーのボタンと同じ値（塗り `#E1E3E4`・文字 `#A3A5A6`・薄くしない・影なし）でした

あわせて、次の2つの推奨（2026-09-14 の a11y レビュー）を決めます。どちらもすでに実装されている、文字のリンクの押せないときの読み上げと、新しいタブのリンクの名前の付け方です。

- **L1**: 押せない文字のリンクは、読み上げでもただの文字にします。href のない `<a>` に `role`・`aria-disabled` を付けません（枠線のリンク・ボタンの見た目のリンクは、いままでどおり `role="link" aria-disabled="true"` で「リンク、利用不可」と読まれます）。ユーザーの返事: 「L1 はよさそうです。」
- **L2**: `aria-label`・`aria-labelledby` で名前を付けたリンクが新しいタブで開くときは、部品が名前に「（新しいタブで開きます）」を足します。ほかの推奨とまとめて確かめ、ユーザーの返事は「それ以外の項目は特に違和感はありませんでした。」でした

## 却下した案と理由

- **現行版のまま両方の経路を残す**: 選ばれませんでした。押せないときの見た目が経路で食い違ったままになります
- **Button の `render` を削除する**: 採りませんでした。Link が中で使うのと、過去の比較のストーリー（軸26・31）が比べたときの見た目のまま描くために、`@deprecated` として残しました
- **Button と Link で見た目のコードをそれぞれ持つ（見た目でも分ける）**: 「見た目的な分割は難しい」。見た目のコードは Button に1つだけ置きます

## 影響

- `src/components/Link.tsx`: `appearance="button"` を足しました。中の `ButtonLookLink` が、`disabled` のとき `color` を `neutral` に強制して `Button`（`appearance="filled"`）を描きます。枠線のリンクの props（`contentAlign`・`leadIconPlacement`）は効きません
- `src/components/Button.tsx`: `ButtonLinkProps.render` の JSDoc に `@deprecated` を付けました。「移動するものは Link で作ります（`<Link appearance="button">`）。この形は、Link が中で使うのと、過去の比較のストーリーを比べたときの見た目のまま描くために残しています」という注記です
- `src/components/link-parts.ts`: Link と Button（`ButtonLink`）で共有する小物（`disabledAnchor`・`disabledLinkProps`・`disabledTextLinkProps`・`newTabNaming` など）は、ADR-0046 のときのまま変わっていません
- 測った値（押せない状態の一覧、2026-09-16）: `<Link appearance="button" color="primary" disabled>` と `<Button appearance="filled" color="neutral" disabled>` の見た目の差はゼロでした。押せないリンクの塗りは `#E1E3E4`・文字は `#A3A5A6` で、薄くせず、影もありません
- **分かっていること**: Components/Button の「リンクとして使う」のストーリーは、Components/Link の「ボタンの見た目」に移しました

## 原則への反映

原則7の「押せないリンクは、押せないボタンと同じ扱いです」の節を、ボタンの見た目のリンクと枠線のリンクのどちらも、色を指定していても押せないグレーのボタンと同じ見た目になることが分かるように書きます（両方の作り方が同じ1つの見た目のコードから来ることが前提になるため）。あわせて、押せないリンクの読み上げの段落で、文字のリンクだけはただの文字として読まれ（「利用不可」とは読まれない）、枠線のリンクとボタンの見た目のリンクは「利用不可」と読まれる、という区別が伝わるように書きます。
