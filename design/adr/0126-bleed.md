# 0126. 本文の幅の外へ出す枠（Bleed）の広げ方

- ステータス: Accepted
- 日付: 2026-09-19
- ラウンド: 後半（ループ外）

## 背景

画像やコードを、本文の幅（Container の中身の幅）の外、Container の左右の余白まで広げる枠（Bleed）を作ります。[ADR-0120](./0120-container.md) で backlog に残していたものです。見た目の比較ではなく、どこまで広げるかという 1 つの分かれ目だけの判断なので、比較のストーリーは作っていません。

## 候補

比較ではなく、ユーザーへの問いと答えです。

| 問い                     | 答え               |
| ------------------------ | ------------------ |
| どこまで広げるか（既定） | 左右の余白いっぱい |

## 決定

**既定は、Container の左右の余白いっぱいまで、左右に同じだけ広げます。** Container が画面いっぱいのとき（スマートフォンなど）は、画面の端まで広がります。Container が幅の上限で止まっているとき（広い画面）は、実際の余白ではなく本文の幅の 1/18 だけ広げます（`--container-gutter-size` が置いた場所の幅の 5% なので、本文の幅はその 90%、余白は本文の幅の 1/18 にあたります）。見た目（色・線・角）は持たず、中の画像やコードの見た目はそのままです。

## 理由

ユーザーの返事の原文です。

> 10: 余白いっぱいでOKです。

- **余白いっぱいを既定に**: 返事のとおり、Container の余白と同じだけ広げる形にしました。Container の `--container-gutter` は `%` を含み、読む要素（Bleed の親）の幅を基準に解決されるため、本文の中（Prose の中など）でそのまま使うと Container の余白と合いません。代わりに、本文の幅（Bleed の親の幅）から余白を逆算する値（`--bleed-gutter`）にしました

## 却下した案と理由

比較ではなく設計の判断なので、却下した案はありません。

## 影響

- `src/components/bleed/Bleed.tsx`: `render` の props を持つ、見た目を持たない部品にしました。Container の直下、Prose の直下など、本文の幅いっぱいの要素の直下に置く前提です
- `design/tokens.css`: `--bleed-gutter`（`clamp(16px, 100%/18, 48px)`）を足しました
- `src/index.ts` に `Bleed`・`BleedProps` を足しました
- backlog の「土台の部品」から、Bleed が未着手であることの記述を消しました

## 原則への反映

反映なし。ページを囲む左右の余白の決め方は [ADR-0120](./0120-container.md) で原則11 に反映済みで、Bleed はその余白を画像やコードのために逆に使う仕組みです。
