# 0356. Sidebar の余白は他の部品に合わせて広げ、縦にあふれたら ScrollArea でスクロールする

- ステータス: Accepted
- 日付: 2026-09-24
- ラウンド: Sidebar の実装を見てもらった直し

## 背景

Sidebar の内側の余白（列の上下左右）を、行が並ぶ最小限で取っていました。畳んだ列の幅の中でアイコンが中央に来るように行の余白を決めていて、列の内側の余白は Card や Popover より狭くなっていました。また、縦にあふれたときのスクロールが、素の `overflow` でした。

## 候補

比較のストーリーは作っていません。実装を見てもらい、直しの指示を受けました。

| 案        | 内容                                                                                                  |
| --------- | ----------------------------------------------------------------------------------------------------- |
| A         | 列の内側の余白を最小限にする。あふれたら素の `overflow` でスクロールする                              |
| B（採用） | 列の内側の余白を、ほかの部品（Card・Popover）と同じ段に広げる。あふれたら ScrollArea でスクロールする |

## 決定

**列の内側の余白（上下左右）は、ほかの部品と同じ段に広げます。畳んだ列の幅と開いた列の幅も、それに合わせて広げます。行が縦にあふれるときは、列の中を ScrollArea でスクロールさせます。余白は ScrollArea の枠の外ではなく、中身（と下端のボタン）が持ちます。枠の外に一律の余白を取ると、影が列の端まで届かず、下に不自然な空きができるためです。**

列の題を上に固定するかどうかは、その後 [ADR-0357](./0357-sidebar-section.md) で見直しました。題は節（`SidebarSection`）の見出しとしてスクロールする中身に含めます。

## 理由

ユーザーの返事の原文です。

> 他のコンポーネントと比較して、上下左右の余白が少ないです

> スクロールが発生した場合に ScrollArea が使われていないのが気になります

> スクロールエリアに一律の余白を設定すると、画面下に不自然な影の空白ができてしまいます。

余白は、部品どうしで段をそろえるほうが、並べたときに揃って見えます。スクロールは、続きがあることを端の内側の影で見せ、つまみで位置を伝える ScrollArea の決まりに従います（Drawer の中は Drawer のスクロールに任せます）。

## 影響

- `design/tokens.css`: `--sidebar-padding`（列の内側の余白）を広げ、`--sidebar-rail-width`・`--sidebar-width` を、それに合わせて広げました。行の左右の余白（`--sidebar-row-px`）は、畳んだ列の幅の中でアイコンが中央に来る値を、計算で出します（開いた形と畳んだ形でアイコンの位置が動きません）
- `src/components/sidebar/`: 行の並びを ScrollArea（縦だけ）で包みます
- 入れ子の行の左の余白（`--sidebar-nested-px`）を、`--spacing` の 3 倍（12px）から 4 倍（16px）に広げました。案内線（`border-s`）から文字までの間が、Tree の案内線と文字の間（16px）と同じ広さになります。畳んだ列の幅から計算する行の余白（`--sidebar-row-px`）とは別の値なので、幅を広げても縮んでいたわけではありませんが、値そのものを Tree と同じ広さにそろえました

その後（2026-09-29）、畳んだ列の幅を、部品の高さと左右の余白から決めるようにしました（`--sidebar-rail-width`）。アイコンだけの行が縦長にならず、角丸の正方形になります。
