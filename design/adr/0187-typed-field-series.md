# 0187. 文字を打つ欄の系列（範囲と共通の仕組み）

- ステータス: Accepted
- 日付: 2026-09-20
- ラウンド: ループ外

## 背景

backlog に残っていた「文字を打つ欄」の系列（検索・パスワード・書式の決まった値・数値・PIN・日付・時刻）を作るにあたり、見た目の軸を比べる前に、次の 5 つを決める必要がありました。

1. 部品にする範囲（どれを部品にし、どれをレシピ（組み合わせの見本）に回すか）
2. 書式の決まった値の欄の名前
3. 書式の処理をどう作るか
4. 日付・時刻の欄を、どう打たせるか
5. 複数の部品で共有する仕組み

## 候補

| 項目                       | 候補                                                                                                                                                  |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 部品にする範囲             | 検索・パスワード・確認入力・型違いの欄（メール・URL・電話）・金額の欄も含めてすべて部品にする案と、既存の部品の組み合わせで作れるものはレシピに回す案 |
| 書式の決まった値の欄の名前 | `MaskInput`（Base UI や他ライブラリでよく使う呼び方）と、ほかの部品の名前（`TextField`・`SearchField` など）にそろえた `MaskField`                    |
| 書式の処理                 | 自前でパースを書く案と、ライブラリ（[maska](https://beholdr.github.io/maska/)）を使う案                                                               |
| 日付・時刻の打ち方         | ネイティブの `<input type="date">` のように 1 本の文字列として打たせる案と、年・月・日（時・分）のように区切りごとに操作する案                        |

## 決定

**Search・Password・Mask・Number・Pin・Date・Time の 7 つを部品にします。** そのほかは、既存の部品の組み合わせで作れるため、レシピに回します。

| 項目                                   | 扱い                                                                  |
| -------------------------------------- | --------------------------------------------------------------------- |
| 検索欄と、欄の外に置く検索ボタンの組み | レシピ（SearchField ＋ Button）                                       |
| パスワードと、強さを示すメーター       | レシピ（PasswordField ＋ Meter）                                      |
| 確認のための入力（もう一度入力）       | レシピ（PasswordField を 2 つ並べ、一致を呼び出し側で確かめる）       |
| メール・URL・電話番号の欄              | レシピ（TextField に `type`・`inputMode`・`autoComplete` を渡すだけ） |
| 金額の欄                               | レシピ（NumberField に `format`・`suffix="円"` を渡すだけ）           |

書式の決まった値の欄は `MaskInput` ではなく **`MaskField`** にします。書式の処理は **maska** を使います。カーソル位置の補正や桁ごとの記号など、この用途に要る処理をすでに持っているためです。

DateField・TimeField は、**年・月・日（時・分）の区切りごとに操作する欄**にします。区切りを打つと次へ進み、空の区切りでは ↑↓ キーで増減し、貼り付けた文字は日付・時刻として読み取ります（和暦、全角の数字、「令和8年9月20日」「午後3時」のような書き方も読みます）。

複数の部品で共有する仕組みは次のとおりです。

- 本体は共有の `FieldBox`（prefix・suffix・待っている印・成功の印を並べる）で作ります
- 消去のボタンは共有の `FieldClearButton` にします。読み取り専用では出さず、欄を止めているあいだ（待っている・送信中）は押せない形にします（[ADR-0168](./0168-field-suffix-acts-on-value.md)）
- 単位（suffix の「円」など）は、値が空でも欄に残します
- 全角の数字・英字は、黙って半角に直して受け取ります。MaskField だけ、直したことを `halfWidthNotice` で任意に知らせられます

## 理由

書式の決まった欄の名前は、ほかの部品がすべて `〜Field` で終わる名前（`TextField`・`SearchField`・`PasswordField` など）を持つため、そろえました。maska を選んだのは、カーソル位置の補正・桁ごとの記号・配列の書式（桁数で書式が変わる）をすでに持っており、自前で書くと同じものを作り直すことになるためです。

日付・時刻を区切りごとの欄にしたのは、ブラウザのネイティブの日付欄に近い体験（桁を打つと次へ進む、↑↓ で増減する）を作れるためです。1 本の文字列として打たせる形だと、書式（年が先か月が先か）を言語ごとに使う側が用意する必要があります。

範囲をレシピに回したものは、いずれも既存の部品を組み合わせるだけで作れ、部品として固定する見た目の決まりがほとんどありません。部品にすると、組み合わせ方を限定してしまいます。

## 却下した案と理由

- **すべてを部品にする**: 検索ボタン・強さのメーター・確認入力・型違いの欄・金額の欄は、既存の部品の組み合わせで作れます。部品にすると選べる幅がかえって狭くなります
- **`MaskInput`**: ほかの部品の名前とそろいません
- **自前でパースを書く**: maska がすでに持つ処理（カーソル位置の補正など）を作り直すことになります
- **日付を 1 本の文字列にする**: 書式（年・月・日の並び）を言語ごとに使う側が用意する必要があり、ブラウザのネイティブの日付欄に近い体験を作れません

## 影響

- `src/components/{search,password,mask,number,pin,date,time}-field/`: 7 部品を新設
- `src/internal/field/FieldBox.tsx`・`FieldClearButton.tsx`・`input-field-props.ts`: 2 つ以上の部品で共有する部分を切り出しました
- `src/internal/date-segments/`: 区切りの状態管理（`use-date-segments.ts`）・貼り付けた文字の読み取り（`parse.ts`）・並び（`segments.ts`）・色（`colors.ts`）を持ちます
- `package.json`: `maska` を依存に追加しました
- `src/index.ts`: 7 部品と props の型を公開しました
- backlog に、検索欄・パスワード・確認入力・型違いの欄・金額の欄のレシピをまだ書いていないことを足しました

## 原則への反映

反映なし。範囲・名前・使うライブラリの決定で、原則 8（入力欄の様式）・原則 14（止めるのは値を変えるものだけ）の範囲内です。
