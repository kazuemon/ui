# 0003. トークンを値の層と役割の層に分ける

- ステータス: Accepted
- 日付: 2026-09-12
- ラウンド: ループ外

## 背景

ダークモードを対象に含めるかどうかは、`tokens.css` の命名の仕方を左右します。色を「値の名前」（`--blue-500`）で持つか、「役割の名前」（`--color-primary`）で持つかです。後から役割の名前に付け替えると、それまでの ADR や原則に書いたトークン名がすべて変わります。

## 候補

| 案  | 内容                                                                       |
| --- | -------------------------------------------------------------------------- |
| A   | ダークモードは対象外。トークンは値の名前でよい                             |
| B   | 今は作らないが、後から足せる構造にする。トークンを値の層と役割の層に分ける |
| C   | 今から両方作る。ループの候補も両テーマで描く                               |

## 決定

B を採用します。

- **値の層**（`--palette-*`）: 生の色。部品と原則からは直接参照しません
- **役割の層**（`--color-*` など）: 部品と原則は、こちらだけを参照します
- ダークモードは、役割の層の対応先を差し替えて、後から足します

## 理由

- ADR-0002 で決めた「面用と前景用」は、すでに役割による分類です。役割の名前で命名すれば、追加のコストはほぼかかりません
- ダークモードを足すときも、原則と ADR を書き換えずに済みます

## 却下した案と理由

- A: 後でダークモードが必要になったとき、トークン名の付け替えで原則と ADR の記述がすべて変わる
- C: 前半のキャンバスの artboard 数が倍になる。参照画像はすべてライトテーマなので、ダーク側には判断の基準もない

## 影響

- `tokens.css` を値の層と役割の層の2層で書きました
- `principles.md` と ADR は、役割トークン名で値を参照します
