# 0079. 部品の文字と高さ・余白（入力方式で文字だけを変える）

- ステータス: Accepted
- 日付: 2026-09-17
- ラウンド: 後半（軸51 のあと）

## 背景

[ADR-0078](./0078-reading-type.md) で読む文字の大小関係を反転させたあと、部品（ボタンなど）の文字の決まり方について聞かれました。

当時の決まりは次のとおりです。

| 項目             | マウス用                                        | 指用                                      |
| ---------------- | ----------------------------------------------- | ----------------------------------------- |
| 部品の文字       | 14px                                            | 16px                                      |
| ラベル           | 13px                                            | 14px                                      |
| キャプション     | 11px                                            | 12px                                      |
| 高さ             | 40px（[ADR-0020](./0020-control-size-fine.md)） | 44px（[ADR-0045](./0045-coarse-size.md)） |
| 左右の余白       | 12px                                            | 16px                                      |
| ラベルと本体の間 | 6px                                             | 8px                                       |
| アイコン         | 16px                                            | 20px                                      |

比較のストーリーは作らず、会話と見本のページ（`Design Review/00 見本のページ`）で決めました。そのため、この ADR には比較画像がありません。

## 決定

会話の中で、次の順に決めました。

1. 部品の文字をマウス 16/24・指 14/20px に入れ替えます。原則を変え、パソコンの部品の文字が 16px、スマホの部品の文字が 14px になるようにします。大きい指用（`coarse-large`、52px）は残します
2. ラベルとキャプションは、どちらも大きいほう（ラベル 14px、キャプション 12px）にそろえます。ほかの選択肢だった「一緒に入れ替える」「変えない」は採りませんでした
3. 文字を打つ欄（TextField・Select）の値は、指でも 16px にします。ほかの選択肢だった「入力欄も 14px のまま」「比べてから決める」は採りませんでした。理由は、iPhone の Safari が 16px より小さい欄にフォーカスすると画面を拡大するためです
4. TextField と Select（値・プレースホルダ・prefix/suffix の文字・開いたときの選択肢）の文字を、指でも 16/24px にそろえます。「欄と同じ 16px」という答えでした
5. 左右の余白 16px、ラベル・本体・キャプションの間 8px を、マウスでも指の値にそろえます。「どちらも指の値にそろえる」という答えでした
6. マウスの高さを 40px から 44px に上げ、指と同じにします。16px の文字で上下 10px です。[ADR-0020](./0020-control-size-fine.md) を置き換えます

行の高さの決まり（原則 10、[ADR-0032](./0032-text-offset.md)）は、この決定でも保たれます。マウス 44 − 24 = 20、指 44 − 20 = 24、大きい指 52 − 20 = 32、入力欄 44 − 24 = 20・52 − 24 = 28 で、どれも部品の高さとの差が偶数です。

## 理由

ユーザーのメモです。

> はい。原則を変更して、パソコンの部品の文字が16px、スマホの部品の文字が14pxとなるように修正もしたいです。今作っている途中の部品の変更よりも、こちらを優先して進めてもらえるでしょうか。coarse-large 自体は残しておいてください。

> スマホでプロフィールページを見たときに、Select と TextField で文字サイズが違うのが気になりますね…同じ見た目系（Select, TextField）は 16px 統一がいい気がしてきました。あとは、TextField などの余白が操作方法によって変わることに気づきました。

> 1 のことで合ってます。マウスと指を同じにできますか？詰まってみえました。

（「1」は、マウスで 16px の文字に上下 8px の余白で詰まって見えるかもしれない、という指摘です。）

- **部品の文字を反転**: [ADR-0078](./0078-reading-type.md) の考え方（パソコンは大きく、スマホは小さく）を、読む文字だけでなく部品の文字にも広げました
- **見た目が同じ仲間はそろえる**: Select と TextField は、プロフィールページのようなフォームで並んだときに文字の大きさが違うと気になります。値・選択肢とも 16/24px にそろえました
- **入力欄は指でも小さくしない**: 画面が拡大される端末があるため、文字を打つ欄・選ぶ欄の値と選択肢は入力方式によらず 16px を保ちます
- **高さと余白は入力方式によらず同じ**: 文字だけをマウスで大きくすると、40px の高さでは窮屈に見えました（「詰まってみえました」）。高さを 44px にそろえ、余白も指の値にそろえました

## 却下した案と理由

- **ラベル・キャプションを一緒に入れ替える**: 選ばれませんでした。どちらも大きいほうにそろえました
- **ラベル・キャプションを変えない**: 選ばれませんでした
- **入力欄も 14px のまま**: 選ばれませんでした。iPhone の Safari で画面が拡大される問題があります
- **入力欄は比べてから決める**: 選ばれませんでした。理由（画面が拡大される）がはっきりしていたため、比べずに決めました
- **マウスの高さを 40px のままにする**: 選ばれませんでした。16px の文字に対して窮屈に見えました

## 影響

- `tokens.css`: `--text-control-*`・`--leading-control-*`・`--text-label-*`・`--text-caption-*`、新しく足した `--text-input-*`・`--leading-input-*`、`--spacing-control-fine`（44px）、`--spacing-control-x-fine`・`--spacing-field-gap-fine` を更新しました
- `src/styles/theme.css`: `--text-input`・`--leading-input` を密度の規則に足しました
- `src/internal/field/field-styles.ts`: `controlBox` の文字を `text-input` にしました
- `src/components/select/Select.tsx`: 選択肢の文字を `text-input` にしました
- 見た目の基準画像を撮り直しました
- [ADR-0004](./0004-density-and-structure-switching.md) の決定1（寸法は全部品で入力方式で切り替える）のうち、高さと余白は入力方式で切り替えなくなりました。ADR-0004 自体のステータスは変えていません
- トグルのトラック（マウス 40×22px・指 48×28px）と、チェックボックス・ラジオの箱（18px・22px）は、まだ入力方式で変わります。`design/backlog.md` に足しました

## 原則への反映

原則 11 の文を書き換えました。押すものの高さと余白は入力方式によらず同じであること、部品の文字は指で小さくすること、入力欄は指でも小さくしないこと、ラベルとキャプションは入力方式によらず同じであることを書きました。
