# 0004. 密度は入力方式、構造は画面幅で切り替える

- ステータス: Accepted
- 日付: 2026-09-12
- ラウンド: ループ外

## 背景

既存原則3には「モバイルが主戦場」と書かれていました。一方で、このデザインシステムを作る動機の一つは、「デスクトップ優先の UI はモバイルに適していない。逆に、モバイル優先の UI はデスクトップだと密度が低い」というアンバランスを解消することです。

そのため、デスクトップとモバイルの両方に対応します。そのうえで、次の3点を決める必要がありました。

1. 何を切り替えるか
2. 何を基準に判定するか
3. 前半のループで、2つの密度をどう扱うか

## 決定 1: 寸法はすべての部品で、構造は浮かぶ UI だけで切り替える

| 案            | 内容                                                                   |
| ------------- | ---------------------------------------------------------------------- |
| A             | 寸法だけ変える。構造と状態の規則は完全に共通                           |
| **B（採用）** | 寸法は全部品で切り替える。構造は、入力方式に依存する部品に限って変える |
| C             | 寸法は変えず、レイアウトだけ変える                                     |

構造を変えてよいのは、ポインタ前提の**浮かぶ UI**（Select、Menu、Dialog、Tooltip、Popover）だけです。例: Select や Menu はモバイルではボトムシート、Dialog は全画面シート、Tooltip は長押しか常時表示にする。

**理由**: 「デスクトップ優先の UI はモバイルに適していない」問題の多くは、寸法ではなく構造から来ています（小さなドロップダウンを指で操作する、hover しないと出てこない情報がある）。一方で、構造を変える部品を無制限に認めると、原則が部品ごとの例外の集まりになるため、範囲を閉じます。

**却下**: A は構造由来の問題が残ります。C は部品が小さいまま、または大きいままになり、アンバランスが解消しません。

## 決定 2: 寸法は入力方式、構造は画面幅で判定する

| 案            | 内容                                                         |
| ------------- | ------------------------------------------------------------ |
| A             | すべて画面幅で切り替える（Tailwind の `sm:`、`md:`）         |
| B             | すべて入力方式で切り替える（`pointer: coarse` / `fine`）     |
| **C（採用）** | 寸法は入力方式、構造は画面幅。どちらも Provider で固定できる |

**理由**: 寸法を大きくする理由は「指は精度が低い」ことで、ボトムシートにする理由は「画面が狭くてポップオーバーが窮屈になる」ことです。原因が別なので、判定も別にします。タブレット（指＋広い画面）、タッチ対応ノート PC、幅を狭めたデスクトップのウィンドウでも、それぞれ適切に切り替わります。Tailwind v4 には `pointer-coarse:` / `pointer-fine:` のバリアントが標準で入っています。Provider で固定できれば、Storybook で両方の密度を並べて比較でき、判定を誤る環境への逃げ道にもなります。

**却下**: A はタブレットで押しにくい密な寸法になり、狭いデスクトップのウィンドウでは不要に大きくなります。B は指で操作する広い画面でもボトムシートになります。

## 決定 3: 前半は見本シートだけ2密度を並べる

| 案            | 内容                                                                 |
| ------------- | -------------------------------------------------------------------- |
| A             | 各候補を両方の密度で描く（1ラウンドに20枚前後）                      |
| B             | 前半は指用の密度だけで描く                                           |
| **C（採用）** | 見本シートだけ2密度を並べ、画面は指用1枚。密度の差は仮の値で固定する |

仮の値は `--size-control-coarse: 44px`（指）、`--size-control-fine: 36px`（マウス）です。差の詰めは後半に、Storybook と実機で行います。

**理由**: ムードは主に色・角丸・文字・動きで決まり、密度からはほぼ独立しています。ただし「軽い」は余白に依存するので、マウス用の詰まった密度でも軽さが保たれるかは、横に並べて確認する必要があります。密度の差そのものは指で押してみないと判断できないので、画面上でしか見られないキャンバスより、実機で詰めるほうが確かです。

**却下**: A は選ぶ負担が大きすぎます。B は片方の密度で破綻する案を選んでしまう危険があります。

## 影響

- `principles.md` に原則11「密度は入力方式、構造は画面幅で切り替える」を追加しました
- 原則3の「モバイルが主戦場」を、「指で操作するときは」という条件の書き方に改めました
- `tokens.css` に `--size-control-coarse`、`--size-control-fine`、`--text-control-coarse`、`--text-control-fine` を定義しました
- 指用とマウス用の寸法の差を、後半の軸に加えました
