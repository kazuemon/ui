# 0329. Dropzone は依存なしで自前に作る

- ステータス: Accepted
- 日付: 2026-09-28
- ラウンド: 後半（軸外。Dropzone の作りはじめに決まりました）

## 背景

Dropzone（ファイルを落とす・押して選ぶ場所）を作りはじめる時点で、土台をどう作るかを決める必要がありました。原則8「入力欄の様式は『編集できるか』で決まる」の仲間として置く部品ですが、値は文字ではなくファイルの一覧です。DataTable（TanStack Table）・Sortable（dnd-kit）のように、重い処理を伴う部品は外のヘッドレスライブラリに任せる作り方も @kazuemon/ui にはあります（[ADR-0298](./0298-carousel-scroll-snap-engine.md) の Carousel も同じ検討をしています）。Dropzone についても、2026-09-28 に、ヘッドレスのライブラリを使わず自前で作ると決めました。ファイルを落とす処理はブラウザ標準のドラッグイベントと隠した input で足り、Form との連携を素直に作れるためです。

## 候補

| 案                                                        | 内容                                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 依存なしで自前に作る（採用）                              | 隠した本物の `<input type="file">`（`BaseField.Control`）を箱いっぱいに重ね、クリック・キーボード・ドラッグ＆ドロップをすべて input が直接受ける。判定（accept・大きさ・数の上限）は DOM を読まない純粋関数に分け、選んだファイルの見せ方は別部品 `DropzoneFileList` に分ける。依存は増やさない |
| 外部のヘッドレスライブラリに乗せる（react-dropzone など） | ドラッグの状態管理・accept 判定などを外部ライブラリに任せる。DataTable・Sortable と同じ考え方にそろえられるが、Dropzone の処理はブラウザ標準のイベントと隠した input で足り、Form との連携（選んだファイルをそのまま送れる）を自分で作れるため、依存を増やす理由がない                          |

## 決定

**Dropzone は依存を増やさず自前で作ります。** 隠した `<input type="file">` を箱いっぱいに重ね、クリック・キーボード（Enter・Space）・ドラッグ＆ドロップをその input が直接受けます。input の上に何も置かないので、dragenter・dragleave の数え方の落とし穴（子要素をまたぐたびに発火する）が起きません。判定（accept・multiple・大きさ・数の上限）は DOM を読まない純粋関数（`dropzone-utils.ts` の `evaluateFiles`・`evaluateDragItems`・`matchesAccept`）に分け、受け付けなかったファイルは理由（`accept`・`maxSize`・`maxFiles`）付きで返します。選んだファイルの一覧の見せ方は、Dropzone 自身が持たず、`DropzoneFileList` という別の部品に分けます（Dropzone はアップロードそのものを行わないため）。

## 理由

ユーザーとの会話で、ヘッドレスライブラリを使わず自前で作ると決まりました（この決定に、ADR に引ける原文はありません。決定メモに書き起こしたものです）。ファイルを落とす処理はブラウザ標準のドラッグイベントと隠した input で足り、Form との連携（`name`・値をそのまま送れる）を素直に作れるため、外部ライブラリに依存する理由がありませんでした。

部品を作ったエージェントの判断（原則にない判断）は次のとおりです。

- 読み取り専用・Form の送信中の見た目を、Slider・Switch と同じ `useChoiceLock` に合わせました。値を持つのは箱そのもの（input）なので、TextField の読み取り専用の破線（[ADR-0170](./0170-readonly-field.md)）ではなく、選んで決める部品（原則8「チェックボックスとラジオは、入力欄の仲間です」）と同じ「押せないときと同じ見た目」を採りました
- ドラッグ中の受け付け判定（dragenter・dragover）は、`DataTransferItem` に大きさ（size）がないため、accept・multiple だけで見た目を決め、大きさ・数の上限は実際に drop できてから確かめます。受け付ける色になっても、実際に落とすと `maxSize` で弾かれることがあります
- 案内の2行目（「対応形式: image/\*」「まとめて選べます」「1 つ 5MB まで」「最大 3 件」のような文）は、accept・multiple・maxSize・maxFiles のうち指定されているものだけを「・」でつなぐ、原則にない独自の組み立てです
- 選んだファイルの見せ方を Dropzone から分け、`DropzoneFileList` という別の部品にしました。アップロードの進み具合（`progress`）・失敗（`errorText`）は使う側が渡す形にし、アップロードの実行そのものは持ちません

## 影響

- `src/components/dropzone/Dropzone.tsx`・`DropzoneFileList.tsx`・`dropzone-utils.ts`・`dropzone-icons.tsx` を新しく作りました。新しい依存（package.json への追加）はありません
- `Dropzone` は `internal/field/Field`・`internal/form-context` の `useChoiceLock` を再利用します
- `DropzoneFileList` は Dropzone とは別の公開部品です（`variant`: `list`・`thumbnail`。軸381で決定、[ADR-0333](./0333-dropzone-file-list.md)）
- backlog に、ドラッグ中は maxSize を判定できないこと・サムネイルの EXIF・実機でのタップ・スクリーンリーダーでの確認などを足しました（記録の提案は `dropzone-shared.md`）

## 原則への反映

反映なし。原則8「入力欄の様式は『編集できるか』で決まる」の仲間としての扱い（読み取り専用・送信中は押せないときと同じ見た目）は、既存の原則の範囲内です。部品の作り方（依存を増やすかどうか）についての決定で、見た目は変えていません。
