# 0110. シートのつまみは引ける印、Tooltip は長押しで上に出す

- ステータス: Accepted
- 日付: 2026-09-18
- ラウンド: ループ外

## 背景

[ADR-0102](./0102-overlay-components.md) で 4 つの部品を作ったあと、実機に近い形で触った指摘が 2 つありました。

- Tooltip を指で長押しして出すと、本体の下（既定の向き）に出るので、指と手で隠れます
- Drawer のつまみは「中身が画面の半分より長いとき」に出していました。つまみが何の印なのかが、決まっていませんでした

つまみの決まりについて、ユーザーの言葉です。

> Drawer について、引ける場合はハンドルがついている、という原則の上で、デフォルトはハンドルなし、コンテンツがはみ出るほど長い場合（スクロールが発生する）は、ハンドルありになる、という制御は難しいでしょうか？（DOMを見るとかだと重くなるので、props制御になりますか？）
> （横向きは例外で、ハンドルは常になし）

「DOM を見ると重いか」には、すでにシートの中身に ResizeObserver を 1 つ付けており（続きの印と半分の段の判定に使う）、開いているあいだだけ動くので測って決められる、と答えました。そのうえで、短いシートも下へはじけば閉じられるため、「引けるならつまみ」を満たすには、はじいて閉じるのをやめるか、つまみの意味を決め直すかのどちらかになる、と示しました。

## 候補

比較のストーリーは作っていません。つまみを出す条件（見えるか見えないか）だけの違いで、並べて選ぶより言葉で決められるためです。

| 案            | つまみを出す条件                                                   |
| ------------- | ------------------------------------------------------------------ |
| 現行版        | 中身が画面の半分より長いとき（半分の段があるとき）                 |
| A             | 中身がはみ出てスクロールするとき。短いシートでは、はじいて閉じない |
| **B（採用）** | 引けるとき。はじいて閉じられるか、上へ引いて広げられるときに出す   |

## 決定

**つまみは「引ける」ことの印です。はじいて閉じられるか、上へ引いて広げられるときに出します。Tooltip を指で長押しして出したときは、向きを上に差し替えます。**

| 項目                     | 決定                                                                                                                             |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| つまみ                   | 下から出すシートで、はじいて閉じられる（`closeOnSwipe`、既定）か、上へ引いて広げられる（中身が開いた高さに収まらない）ときに出す |
| つまみを出さないとき     | はじいて閉じず、上へも広げられないとき。横から出すパネルはいつも出さない                                                         |
| はじいて閉じるのを止める | `closeOnSwipe={false}`。閉じる合図を取り消し、Base UI が近い段に戻す                                                             |
| Tooltip の長押しの向き   | 上（`longPressSide`、既定 `'top'`）。`false` を渡すと `side` のまま。画面の上に空きがないときは、今までどおり反対側へ逃げる      |
| マウス・キーボード       | 渡された `side`（既定は下）のまま。差し替えるのは、長押しで出したときだけ                                                        |

## 理由

ユーザーのメモです。

> Tooltip は問題なさそうでしたが、指 長押しで出た場合は、上書きして基本上に出したほうが良さそうですね。デフォルトはオンで、上書きオフにもできると良さそう。

> 2 条件は新しいもので良さそうです。はじいて動かせる or 閉じれる場合はつく、にしてもいいかもですね（Esc や × のようにスライドで閉じれないようになっているかつ、上にも広げられない場合は出さない）

以下は、メモから読み取れることです。

- **指の下は見えない**: 指で触った場所の下は、指と手で隠れます。iOS・Android の標準も、触った位置より上に出します。マウスで載せたときは指がないので、下のままにします
- **つまみは引ける印**: 「引けるならつまみ」を、部品の側から読み替えると「つまみがあるものは引ける」になります。閉じる手段（Esc・×）と同じように、はじいて閉じるのも止められるようにし、止めたうえで広げられないときだけ、つまみを出しません
- **測って決める**: 上へ広げられるかは、開いた高さに中身が収まるかで決まります。これは続きの印のためにすでに測っているので、props で指定させる必要はありません

## 却下した案と理由

- **現行版（中身が画面の半分より長いとき）**: つまみがなくても下へはじけば閉じられるので、「引けるならつまみ」と合いませんでした
- **A（短いシートでは、はじいて閉じない）**: 下へ払って閉じる操作は、指では覚えられている動きです。原則を守るために消すのは、不便が大きいと判断しました

## 影響

- `src/components/drawer/Drawer.tsx`: `closeOnSwipe`（既定 `true`）を足しました。つまみは「はじいて閉じられる、または上へ広げられる」で決めます。狭い画面の Dialog・Popover のシートにも同じ決まりが効きます
- `src/components/tooltip/Tooltip.tsx`: `longPressSide`（既定 `'top'`）を足しました
- ストーリー: Drawer に「はじいて閉じない」を足しました。下から出すシートの見た目の基準画像（Drawer・Dialog・Popover）は、つまみが出た分を撮り直しました
- `principles.md`: 原則11 に、つまみは引ける印であることを足します
- 後ろの暗さは、引いた量に合わせて薄くします（閉じる方へ引くほど、後ろの画面が見えてくる）。段があるシートでは、Base UI の引いた量が段の位置によらず 1 になるため、暗さを変えません
- つまみを出さないときも、場所は取ります。出し入れで見出しの位置と上の余白が動かないようにするためです（ユーザーのメモ「場所は取る必要がありそうです！余白が変わってしまうので」）
- 面のない場所（後ろの暗い面の側）には、引く操作を無視する場所（`data-base-ui-swipe-ignore`）を敷きます。Base UI は面を置く枠（Viewport）の中を引く操作を拾うので、これがないと、空いた場所を引いてもシートを引いたことになり、面が動かないまま後ろの暗さだけが変わりました。押して閉じる（外を押す）のはそのまま効きます
- 面の下の余白は、段のずれの分だけにします。引いている量まで足すと、面が下に伸びて指の動きと打ち消し合い、面が止まって見えました
- 中身に入力欄を置くシートのために、Base UI の `Drawer.VirtualKeyboardProvider` で包みます（ソフトウェアキーボードに合わせてスクロールを整える）
- 中身の高さを測るときは、引いているあいだを飛ばし、段のずれの分に足した面の下の余白を引きます。これを入れる前は、はじいて閉じない設定で下端まで引くと、引いたあとにつまみが出たまま残りました（余白の分だけ中身が長いと測っていた）
- 分かっていること: 長押しで出したあと、指を離さずに動かすと、Base UI の位置の追従で向きが変わることがあります。実機で確かめる項目に足しました（backlog）

## 原則への反映

原則11の文に、シートのつまみは引ける（はじいて閉じられる・上へ広げられる）ことの印である、という 1 行を足しました。長押しで出す補足を上に出すことも、同じ原則の「指の動き」の並びに入れています。
