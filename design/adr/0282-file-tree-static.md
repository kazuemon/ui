# 0282. FileTree は開閉しない静的な部品

- ステータス: Accepted
- 日付: 2026-09-23
- ラウンド: 後半（軸外。軸 275〜278 の作りはじめに決まりました）

## 背景

FileTree を作りはじめる時点で、Tree（`src/components/tree`）との役割分担を決める必要がありました。Tree はナビゲーション（開閉・行き先・キーボード操作）の部品です。FileTree を、記事に置く「読みものの中の図版」として、行き先も開閉も持たない静的な一覧にするか、実際に開閉できる部品にするかです。

## 候補

| 案                 | 内容                                                                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 静的な一覧（採用） | 開閉・行き先を持たず、最初から全部描く。フック・ref・イベントの props を持たないので、サーバーコンポーネントのまま描ける |
| 開閉できる部品     | Tree と同じように、フォルダの行を押すと開閉する。実際にファイルを選ばせる操作も持てる                                    |

## 決定

**FileTree は、開閉しない静的な部品にします。**

実際にフォルダを操作させたい（開閉・選択・キーボード操作が要る）ときは、Tree を使います。FileTree は、記事の中で CodeBlock・Callout・Steps と同じ「本文」の仲間として、フォルダとファイルの構成を見せるためだけの部品です。

## 理由

FileTree は README の「本文」の仲間（CodeBlock・Callout・Steps と同じ並び）に置く部品で、使う場面は「この記事で説明するプロジェクトの構成を見せる」ことです。実際に操作させたいわけではないので、開閉やキーボード操作は要りません。静的にすることで、フック・ref・イベントの props を持たず、`'use client'` が要らないサーバーコンポーネントのまま描けます。字下げと案内線も、深さを JS で数えず CSS の入れ子だけで作れるので、開閉がある Tree より軽い実装になります。

## 却下した案と理由

- **開閉できる部品にする**: 選ばれませんでした。実際にファイルを操作させたい場面は Tree でまかなえており、FileTree にも同じ機能を持たせると役割が重なります

## 影響

- `src/components/file-tree/FileTree.tsx`: フック・ref・イベントの props を持たない、サーバーコンポーネントのまま描ける部品として作りました
- README「本文」の一覧に FileTree を追加しました

## 原則への反映

反映なし。原則18（働きで部品を選び、見た目は別に選ぶ）の「見た目が同じでも、働きが違えば部品を分けます」の範囲内です。
