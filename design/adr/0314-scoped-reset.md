# 0314. Tailwind のリセットを、部品の要素とその中にだけ当てる

- ステータス: Accepted
- 日付: 2026-09-24
- ラウンド: ループ外

## 背景

Tailwind を使わないアプリ向けの CSS（[0313](./0313-css-entries.md)）には、Tailwind のリセット（preflight）を入れていません。preflight はページ全体に効くので、既にあるページの見出し・一覧・ボタンの見た目を変えてしまうためです。

ところが部品は、preflight がある前提で書いています（ボタンの枠や余白、見出しの大きさ、一覧の印、画像の `display`、`box-sizing` など）。Storybook から preflight を外して見た目の比較を流すと、768 件中 375 件がずれました。

## 候補

比較の候補はありません。次の形を比べ、選びました。

| 案                               | 形                                                                                       |
| -------------------------------- | ---------------------------------------------------------------------------------------- |
| 部品の中だけにリセットを当てる   | 部品の要素に目印のクラスを付け、その要素とその中にだけ、preflight と同じリセットを当てる |
| 部品ごとに直す                   | 各部品に、要るリセット（`m-0`・`border-0`・`box-border` など）をクラスで足す             |
| preflight を別の入口にして勧める | `reset.css` を配り、使う側に読んでもらう                                                 |

## 決定

**部品の中だけにリセットを当てます。**

- 目印のクラスは `kz-ui`（`SCOPE_CLASS`）。`tv` で書いた部位には、`tv` がすべてに足します。`tv` を通らない Base UI の Portal（ポップアップを body の直下へ運ぶ要素）と、クラスを直に書いている外側の要素（Badge・AspectRatio・NoticeRegion）には直に付けます
- リセット（`src/styles/reset.css`）は `:where(.kz-ui, .kz-ui *)` に絞り、詳細度を 0 にして base の層に置きます。中身は Tailwind v4.3 の preflight を写したものです。部品のクラス（utilities の層）と、使う側の CSS が必ず勝ちます
- preflight が `html` に置く文字の設定（フォント・行の高さなど）は、Tailwind なしの CSS でだけ、いちばん外の部品の要素（`.kz-ui:not(.kz-ui *)`）に置きます。Tailwind ありでは置きません。置くと、使う側が親に付けた `font-*`・`leading-*` を部品が受け継がなくなるためです
- 部品の中に使う側が入れた要素（Card の中の段落など）も、リセットの範囲に入ります。Tailwind ありのアプリと同じ見え方です
- ThemeProvider と Portal 部品の包み（`display: contents`）には付けません。使う側のアプリ全体を包むので、付けるとアプリ全体にリセットが効いてしまいます

## 理由

依頼は [0313](./0313-css-entries.md) と同じです。示した進め方（「部品がリセットに頼っている箇所をなくす」）に「1から順にお願いします」と答えてもらい、その 3 番目として形を決めました。

- **ページを変えない**: Tailwind なしで入れる先は、既に自分の CSS を持つページのことが多いので、部品の外には何も効かないようにします
- **部品の書き方を変えない**: 部品ごとに直す案は、ずれた 375 件を 1 つずつ直すことになり、これからの部品でも毎回気をつける必要があります。目印は `tv` が足すので、ふだんの書き方のままで済みます

## 却下した案と理由

- **部品ごとに直す**: 量が多く、足し忘れを見つける方法がありません。Tailwind ありのアプリでは preflight と同じ値を二重に書くことになります
- **preflight を別の入口にして勧める**: ページ全体に効くので、既にあるページに入れにくくなります

## 影響

- `src/internal/tv.ts`: `tv` が、base と slots のすべてに `SCOPE_CLASS` を足します。部位の名前と variants の型は変わりません
- Calendar: react-day-picker が 1 語として足し外しする「月を送る動き」のクラスは、`tv` を通さない文字列にしました（通すと 2 語になり、動かすときに落ちていました）
- `src/internal/scope-class.test.ts`: Base UI の Portal への付け忘れを確かめます。CLAUDE.md の「部品を作る」に決まりを足しました
- 確かめたこと
  - Storybook の全ストーリーを開き、部品が描いた要素（React の記録で、どの部品が作ったかを見る）が目印の範囲に入っていることを確かめました。残ったのは、ストーリーの中で書いた要素と、意図して付けない包みだけです
  - Tailwind ありの見た目の比較は、変更前と同じ結果でした（この環境で前から落ちる 9 件を除き、すべて一致）
