# 0368. 見出し 1 より大きい 3 段（Hero・節の大見出し）を足す。値は C（実例から）

- ステータス: Accepted
- 日付: 2026-09-29
- ラウンド: 後半 軸 387

## 背景

見出しは 4 段（マウスで 28・22・18・16px、指で 24・20・16・14px — [ADR-0078](./0078-reading-type.md)）で、機能の画面に合わせて差を小さくしてあります。ポートフォリオのトップ（Hero）やランディングの節の見出しでは、いちばん大きい段でも小さく見えます。見出し 1〜4 の値は変えずに、その上に 3 段（でかい・おおきい・おおきめ）を足します。

## 候補

比較は、決めた時点のコミット `fbc1e5c` の比較のストーリー（`design/stories/axis-387-display-heading.stories.tsx`）です。列は、Hero（デスクトップ・スマホ）、節の見出しと数字、段の一覧（デスクトップ・スマホ）です。段の一覧には、描いた大きさ（px）と、すべての案で同じではない値の下線を出しています。案は、観点を変えた 3 人のエージェント（和文の組版・比の設計・実例の調査）に出してもらいました。

値は「文字/行の高さ」（px）で、デスクトップ（マウス）・スマホ（指）の順です。

| 案                  | でかい                 | おおきい     | おおきめ     | 字間                    |
| ------------------- | ---------------------- | ------------ | ------------ | ----------------------- |
| 現行版              | —（見出し 1 の 28/40） | —            | —            | —                       |
| A（和文の組版から） | 56/68・38/46           | 44/56・32/42 | 36/48・28/38 | 段ごとに −0.02〜−0.01em |
| B（比から）         | 56/72・40/52           | 44/56・34/44 | 36/48・28/36 | −0.01em                 |
| C（実例から。採用） | 56/68・40/50           | 44/56・32/42 | 36/48・28/38 | −0.01em                 |
| D（幅で伸び縮み）   | 40〜56                 | 32〜44       | 28〜36       | −0.01em                 |

## 決定

**C を採用します。** 3 段は Heading の `size` の `5xl`・`4xl`・`3xl` です（名前は [ADR-0369](./0369-type-scale-names.md)）。

- 値は、見出しの 4 段と同じくマウスか指か（密度）で切り替えます。読みもの（`data-reading`）の中では、指でもマウスの値です
- 字間は 3 段とも −0.01em にします。大きな太字の和文は、字間を少し詰めると締まって見えるためです
- 3 段は Prose の要素（h1 など）には割り当てません。記事の見出しは、今の 4 段のままです
- Text（`size`）と Stat（数字の大きさ）でも、同じ 3 段を選べます

## 理由

ユーザーの返事の原文です。

> 追加で3段ぐらいあると嬉しいですが、スマホ・デスクトップそれぞれでのバランスを見直したいです。雰囲気は各端末で「でかい」「おおきい」「おおきめ」だと分かるものが良いですね。サブエージェントに聞いてみるとかするといいと思いました。個人的にはAのデスクトップは「でかい」に分類されるなと思いました。

> C がよさそうですね。

- デスクトップの 56・44・36 は、3 人の案がそろって出した値で、「デスクトップで 56 はでかい」という感覚にも合います
- スマホのでかいは 40 にします。38（A）ではおおきい（32）との差が 1.19 倍しかなく、40 なら 1.25 倍になって見分けやすくなります。1 行に全角 8 字ほど入り、2 行の Hero に収まります
- 行の高さの比は、見出し 1 の 1.43 から 1.33・1.27・1.21 と少しずつ詰まり、今の 4 段とつながります

## 却下した案と理由

- **A**: スマホのでかいとおおきいの差が小さく、段ごとの字間は並べても違いが分かりにくいため
- **B**: でかいの行の高さ（72）が広く、2 行の Hero で間延びするため
- **D**: 文字の大きさを入力方式で切り替える仕組み（原則 11）と別の仕組みになるため。Hero の大きさが画面の幅に合わないと分かったら、でかいの段だけ伸び縮みさせることを backlog で検討します

## 影響

- トークン: `--text-heading-3xl`〜`5xl`・`--leading-heading-3xl`〜`5xl`（`-fine`・`-coarse`）と、字間の `--heading-large-tracking`
- Heading・Text・Stat の `size` に 3 段を足しました
- 比較のストーリーは消しました

## 原則への反映

原則 11 の文を書き換えました。見出しの段に、Hero や節の大見出しのための大きい段があることと、それも本文と一緒に小さくなることを書きました。
