# 0394. 縦の Divider は、周りの文字の高さで中央にそろえる

- ステータス: Accepted
- 日付: 2026-10-01
- ラウンド: 後半 軸 410

## 背景

Divider に `orientation="vertical"` を足し、横に並べたもの（ツールバー・リンクの並び・メタ情報の行）のあいだに縦の線を置けるようにしました。縦の線の長さを決めました。

## 候補

比較は、決めた時点のコミット `3148cf6` の比較のストーリー（`design/stories/axis-410-divider-vertical-inset.stories.tsx`）です。列は「ツールバー」「リンクの並び」「メタ情報の行」「パネルの中の区切り」です。

| 案        | 縦の線の長さ           |
| --------- | ---------------------- |
| 現行版    | 縦の線なし（間だけ）   |
| A         | 並んだ行の高さいっぱい |
| B（採用） | 周りの文字の高さ       |
| C         | 周りの文字の高さ       |

B と C は縦の線が同じで、左右を空けた線の空け幅だけが違います（[ADR-0395](./0395-divider-no-inset.md)）。

## 決定

**縦の線は、周りの文字の高さで、中央にそろえます。**

- ボタンが並んでも線が短く、軽く見えます
- 行の高さいっぱいに引く形（A）は、ボタンのまわりの余白まで線が伸びて重く見えます

## 理由

ユーザーの返事の原文です。

> 410「高さは文字の高さで、inset の左右の余白はユーザー次第だと思ったので、基本は親の padding に依存する（目一杯伸びる）がいいかなと思いました。」

出どころは、トリアージの F68・F121 です。

## 却下した案と理由

- **A（行の高さいっぱい）**: 採りませんでした。文字の高さのほうが軽く見えます

## 影響

- `src/components/divider/Divider.tsx`: `orientation="vertical"` は周りの文字の高さ（1em）で中央にそろえます
- 比べるためだけに置いた `--divider-vertical-*` のトークンは、切り替えを畳んだコミット（`a373082`）で消しました
- 縦の線の左右の間は、置く側（並べる枠の `gap`）が決めます
- 比較のストーリーは消しました

## 原則への反映

反映なし。縦の線の長さの決定で、原則が新しく扱う対象は増えていません。
