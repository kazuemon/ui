# 0199. backlog の仕分け（原則と ADR から決めたこと）

- ステータス: Accepted
- 日付: 2026-09-20
- ラウンド: ループ外

## 背景

backlog が約 170 行に膨らみ、「まだ決めていないこと」と「もう原則や既存の ADR から答えが出ていること」が混ざっていました。1 行ずつ軸を立てて比べると、決めるだけで何ラウンドもかかります。

そこで 2026-09-20 に、backlog の全行を次の 4 つに仕分けました。

1. 見た目を比べないと決まらないもの（軸を立てる。軸 174〜179 → [ADR-0193](./0193-underline-button.md)〜[ADR-0198](./0198-pagination-compact.md)）
2. 原則と既存の ADR から答えが出るもの（この ADR）
3. 作らないと決めるもの（この ADR）
4. まだ決めないもの（backlog に残す）

この ADR は 2 と 3 をまとめて記録します。見た目の比較をしていない決定だけを集めた 1 本です。

## 候補

見た目の候補は作っていません。仕分けの一覧（[artifact](https://claude.ai/artifact/ExWxpTXfiogK9DUXJNmAry)）をユーザーと一緒に上から読み、行ごとに「原則から出る答え」「作らない」「まだ決めない」を選びました。

### 作らない・保留と決めたもの

| 決めたこと                                                                                   | 理由                                                              |
| -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 警告の色のボタンは作らない                                                                   | 警告は押すものの色にしない（原則6）。必要になったときに考える     |
| 押すものの 4 段目は、下線の形だけにする。ほかの軽い見た目は足さない                          | 段を増やすほど、隣に並べたときの強さの順が読めなくなる（原則7）   |
| 省略（…）は、ふだんは押せないまま。押して選べるのは、選んだときだけの形にする                | [ADR-0198](./0198-pagination-compact.md) で、選べる形として足した |
| 押すものの大きさの比例（大きい指用で箱やトグルをどこまで大きくするか）は、部品ごとに決めない | 押すもの全体を一度に監査する                                      |
| MaskField の見本の字間が広いのは、そのまま許容する                                           | 見やすさを優先する                                                |
| 数字の幅をそろえるか（tabular-nums 相当）は保留する                                          | 推奨のフォントを使わない場合があるので、色の軸のときに一緒に見る  |

## 理由

仕分けの場でのユーザーの言葉です。

- Popover の題: 「popover は題を必須でいいと思います」
- Pagination の色: 「secondary は選べるようにしたいです。status は Pagination に status の概念がないので不要」
- コピーの失敗: 「ペーストの場合と異なり、こちらでフィードバックできる口があるため」（`onCopyError` があるときは部品から知らせない）
- RelativeTime: 「Provider の上書きを考慮する」
- Menu の印: 「デフォルトは揃うが、props で揃わないようにもできるようにしたい」
- 大きさの比例: 「大きさ比例については、押せるもの全体を監査したいです。」
- MaskField の字間: 「間隔が広いのは許容するつもりです（見やすさのため）」
- tabular-nums: 「設定しておいて損はない気はします（推奨フォントを選ばない可能性もあるため）」

原則から答えが出る行を先に落としたことで、見た目を比べる必要のある軸が 6 本（174〜179）に絞れました。

## 却下した案と理由

- 1 行ずつ軸を立てて比べる: 原則から答えの出る行まで比較のストーリーを作ることになり、決めるまでの時間がほとんど比較の準備に消えます
- 決まった行を backlog に残したまま実装する: 「決めること」に決まったものが混ざり、次の仕分けで同じ行をもう一度読むことになります

## 影響

- 部品: Popover・RelativeTime・Textarea・Accordion・Tree・Menu・Badge・Pagination・Card・Notice・RadioGroup・CheckboxGroup・Link と、型違いの欄（MaskField・NumberField・PinField・DateField・TimeField）を直しました。スクロールの判定と全角の変換は `src/internal/` に移して共有しました
- backlog: 決まった行・実装した行を 25 行消し、3 行（必須の印、CodeBlock のスクロールの判定、欄の端の文字のボタン）はいまの状態に書き直しました。新しく分かった未決事項を 24 行足しました
  - 決めること（17 行）: 下線のリンクに ↗ をいつも付けるか、下線の太さと位置、アイコンだけの下線のボタン、枠線から下線に落とす場所の監査、CopyButton の既定の見た目を下線にするか、失敗の知らせを出す長さ・割り込み・貼り付けなどほかの失敗との足並み、`errorLabel` と `copyErrorLabel` で props の名前がそろっていないこと、必須・任意の印の文言の差し替え、必須と任意を混ぜたときの勧め方、「\* は必須の項目です」の一文の置き場、グループ（fieldset）の必須をキャプションの文で書く決まり、読み取り専用と押せないものを見分けられないことの伝え方、読み取り専用の Select が開かないと分かるか、省略のメニューにページが並びすぎるときの畳み方、`pageInput` と `ellipsisMenu` を同時に付けたときの並び、狭いところの切り替わる幅を使う側が変えられるようにするか、CodeBlock のスクロールを外側の包みに移すか
  - 確かめること（7 行）: 読み取り専用の Select で ▼ を一段淡くして残したこと、下線のボタンの押せる範囲、暗い面の上での淡い赤の見え方、読み取り専用でエラーの欄とボタンの赤みの強さ、読み取り専用の選ぶ部品を指で押したとき、省略のメニューと数を打つ欄を指で操作したとき、数を打って移る欄でルーターを使うときは `onChange` も要ること
- backlog の見出しを、「決めること」「レシピの案」「確かめること・既知の制約」の 3 部として書き直しました

## 原則への反映

- 原則15 に、重なる面には読み上げの名前が要る（題を必ず持たせ、画面に出さないときも読み上げには届ける）という 1 行を足しました
- お知らせを閉じたあとのフォーカス、二度読ませないこと、Tab で止める場所は、原則15 の既存の文の範囲内なので書き換えていません
- そのほかの決定（RelativeTime・Textarea・Badge・Card・Pagination の色・Menu の印）も、原則6・原則14・原則19・原則20 の範囲内です
- 軸で決まった分の原則の書き換えは、[ADR-0193](./0193-underline-button.md)（原則7 を 4 段に）・[ADR-0194](./0194-required-mark.md)（原則4 に印）・[ADR-0196](./0196-choice-readonly.md)・[ADR-0197](./0197-readonly-addon.md)（原則8・原則13）にあります
