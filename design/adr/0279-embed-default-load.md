# 0279. Embed の既定は、最初から読み込む

- ステータス: Accepted
- 日付: 2026-09-23
- ラウンド: 後半（軸外。軸 267〜284 の返事の中で決まりました）

## 背景

Embed を作りはじめる時点で、埋め込みの既定の読み込み方が決まっていませんでした。「押すまで読み込まれない」を既定にする案と、「最初から読み込む」を既定にする案があり、この点を先にユーザーに確かめました。

## 候補

| 案                       | 内容                                                                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 最初から読み込む（既定） | ブラウザの `loading="lazy"` で、画面に近づいたときに iframe を読み込む。X の投稿の文面などは、読み込めるまでの `children` としてあらかじめ表示できる |
| clickToLoad              | クリックするまで iframe を作らない。読み込む前の面（プレースホルダー）を出す                                                                         |

## 決定

**既定は最初から iframe を置き、ブラウザの `loading="lazy"` で画面に近づいたら読み込みます。クリックするまで待つときは `clickToLoad` を渡します。`children` を渡すと、読み込めるまでのあいだ（JS が動かなくても、Server Components でも）その中身を出せます。**

## 理由

ユーザーの返事の原文です。

> X にも対応はしたいですが、そもそも Embed って押すまで読み込まれないのがデフォルトですか？ ツイートの文面などはあらかじめ読み込まれているのがベースかなと思っていました。

X の投稿のように、埋め込み先が文面をあらかじめ読み込んでおくサービスもあり、「押すまで何も出ない」を既定にすると、そうした使い方と合いません。ブラウザの `loading="lazy"` に任せれば、画面外では読み込まず、画面に近づけば自然に読み込まれるので、パフォーマンス上の理由だけなら既定を `clickToLoad` にする必要はないと判断しました。サードパーティの script（widgets.js など）は部品に抱え込まず、iframe で埋められるものだけを対象にしています。

## 却下した案と理由

- **既定を clickToLoad にする**: 選ばれませんでした。X の投稿のように、埋め込み先があらかじめ文面を用意しているサービスの使い方と合いません

## 影響

- `src/components/embed/Embed.tsx`: `clickToLoad`（既定 `false`）・`loading`（既定 `'lazy'`）・`children`（読み込めるまでの中身）を公開しました
- クリックする前の面の見た目は [ADR-0265](./0265-embed-idle-face.md)、枠は [ADR-0266](./0266-embed-frame.md) で別に決めました

## 原則への反映

反映なし。原則20（部品は知らないことを決めない）の「既定を 1 つ決め、ほかの形は選べるようにする」の範囲内です。
