# 0495. CodeBlock の折り返さないコードは、枠の中で中身がスクロールする

- ステータス: Accepted
- 日付: 2026-10-08
- ラウンド: 後半 軸 582

## 背景

折り返さない CodeBlock は、横にあふれると、コードの要素そのものがスクロールしていました。スマートフォンで枠より長い行を見ると、スクロールバーも影も出ず、続きがあることが分かりません（backlog の「CodeBlock が横にスクロールできることが、見た目で分かりません」）。[ADR-0494](./0494-table-scroll.md) の軸で、表と同じ列で比べました。

## 候補

候補は、ADR-0494 と同じです（現行版・A・B）。比較は、決めた時点のコミット `fea855ff` の `design/stories/axis-582-reading-scroll.stories.tsx` です。

## 決定

**A の見せ方（端の内側の影と、載せたとき・スクロール中に出るつまみ）にします。ただし、表と違って外観は動かさず、枠の中で中身をスクロールします。マウスで引っぱる動きは付けません。**

- 折り返さないコードがあふれると、枠は止まったまま、中のコードが動きます。続きのある端に影が出ます
- Tab の止まり方は、回数も順番も今と同じです。あふれているときだけ止まり、矢印キーでスクロールできます。止まる要素は、コードの要素（`pre`）から枠に変わりました。Shiki が出す HTML の中の `pre` を、スクロールする枠にできないためです
- Prose の素の `table`・`pre` は、ネイティブのスクロールのままです。使う人が MDX の `components` で、Table・CodeBlock に差し替えます

## 理由

ユーザーの返事の原文です。

> 折り返しの無いコードブロックの場合は、表と同じ挙動ではなく、中身をスクロールできるようにしたいですね。Prose についてはユーザー側で差し替えてね、でよさそうです。

> Tab での挙動はできる限り現在の状態を維持したいですね。

以下は、決めたときの考えです。

- **コードは外観を動かさない**: コードの面は、表のように 1 枚の物として見るより、窓の中で行を読む物です。枠が動くと、読んでいる行の位置が失われます
- **引っぱらない**: コードは文字を選んで写すことが多く、文字の上の引っぱりを空けたいので、引っぱる動きは付けません

## 却下した案と理由

- **表と同じく外観ごと動かす**: 上のとおり、窓としての読み方に合いません
- **Prose の中で素の table・pre を自動で差し替える**: 使う人が MDX の置き換えで決めるもので、Prose が部品を勝手に選ぶことはしません

## 影響

- `src/components/code-block/CodeBlock.tsx`: 折り返さないときの中身を ScrollFrame で描き、Tab の止まり先を pre から ScrollFrame の枠に移します
- `src/components/code-block/code-block.tokens.css`: 比べるためだけの切り替えのトークンを畳んで消しました
- 比較のストーリーは消しました。backlog から、CodeBlock の続きの見せ方の行を消しました

## 原則への反映

原則 1 の、スクロールできる面の見た目の文に、コードも含めました。表と違い、コードは枠の中で動きます。
