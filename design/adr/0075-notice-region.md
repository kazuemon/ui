# 0075. あとから出すお知らせの領域と、閉じるボタンの名前

- ステータス: Accepted
- 日付: 2026-09-14
- ラウンド: ループ外（a11y レビュー）

## 背景

[ADR-0043](./0043-notice.md) で Notice（お知らせ）の見た目と役割（`role="alert"`・`role="status"`）は決まりましたが、Notice は自分で role の箱を出す作りでした。送信の結果やエラーのように、ページを開いたあとから出すお知らせは、箱ごと DOM に足すと、読まれない組み合わせがあります。空の箱を先に置いておき、中身だけをあとから入れると、多くの読み上げソフトで確実に知らせます。この仕組みを持つ部品がありませんでした。

あわせて、× の名前が「閉じる」に固定で、題（`title`）があっても名前に含まれないこと、警告のお知らせを危険と同じ `alert` にするかどうかも、2026-09-14 の a11y レビューで扱いました。

原則1（影・レイヤー）、原則6（色は役割で持つ。読み上げでは危険だけが割り込む）に関わります。

## 候補

比較の候補はありません。2026-09-14 の a11y レビューで示した推奨（N1〜N3）と、実装したあとの確認への答えです。

| 案                        | 内容                                                                                                                 |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 現行版                    | あとから出す通知をまとめて置く領域の部品がない。× の名前は「閉じる」固定で、題があっても名前に含まれない。警告は `status`（変更なし） |
| N1（NoticeRegion）        | あとから出すお知らせのために、先に置いておく領域（live region）の部品を足す。トーストは別に考える                            |
| N2（× の名前）            | × の名前は props で変えられるようにし、既定は「閉じる」。題があるときは aria-labelledby で題も名前に含める                    |
| N3（警告の役割）          | 警告のお知らせは `status` のまま（`alert` は危険だけ）                                                                       |

## 決定

**N1〜N3 をすべて採用します。**

| 項目                          | 決定                                                                                                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| NoticeRegion（N1）             | あとから出す通知のために、先に空の読み上げの箱（危険用の `role="alert"`、ほか用の `role="status"`）を置いておく領域の部品。中の Notice は自分では箱を出さず、領域が置いた箱の中身として描かれる（React の Portal）。トースト（一定時間で消える通知）は別に考える |
| 箱の並び                       | 危険の箱（alert）が上、ほか（status）が下。お知らせどうしの間、箱どうし（両方に中身があるとき）の間は、どちらも 8px。空の箱の分の間はあけない                                                                        |
| aria-atomic                    | 両方の箱で `false`。2つ目のお知らせが入っても、1つ目を読み直さず、足したものだけを読む                                                                                                                              |
| × の名前（N2）                 | `closeLabel` props で変えられる。既定は「閉じる」。題（`title`）があるときは、× の名前のあとに題を続けて読む（`aria-labelledby` で自分の名前を先に、題の id をあとに指す）。操作の名前を先にすると、Tab で移ったときに何をするボタンかが先に聞こえ、音声操作で「閉じる」と言ったときも名前の頭で当たる |
| 警告の役割（N3）               | 変更なし。警告は引き続き `status`。`alert` は危険（danger）だけ（ADR-0043 のまま）                                                                                                                                  |
| NoticeRegion の中の × の読み上げ | 領域の箱の中に、お知らせ全体（アイコン・題・本文・操作・×）がまとめて入るので、× も箱の中身として一緒に読まれうる。問題なしとした                                                                                     |

## 理由

ユーザーのメモです。推奨（N1〜N3 を含む一連の項目）への返事です。

> それ以外の項目は特に違和感はありませんでした。

実装したあとの確認への答えです。

> このままにするもの: 1 押されなかった送信のボタンのカーソルは待っている形。2 ボタンを押さずに送ったときの回る円は最初の送信のボタン。3 シートを高さいっぱいから下へはじくと半分の高さへ（はじく速さの値と閉じる動きの長さは実機で詰める）。4 NoticeRegion の中の並びは危険が上・間 8px。5 NoticeRegion の中の × も一緒に読まれうる（「問題なし」）。11 送り終えたときフォーカスが body なら移す。12 「N 件の選択肢」の N は選べない選択肢も含む。答えは「このまま」

以下は、メモから読み取れることです。

- **N1〜N3 は違和感なく受け入れられた**: 「それ以外の項目は特に違和感はありませんでした」なので、推奨どおりに実装しました
- **NoticeRegion の並び（4）はそのまま**: 「答えは『このまま』」。危険の箱を上に置き、間は 8px のまま変えません
- **× も箱の中で一緒に読まれてよい（5）**: 「（『問題なし』）」。× は role の箱の外に置いていますが、NoticeRegion の中ではお知らせ全体が箱に入るので、× もその一部として読まれます。これは問題として扱いません

## 却下した案と理由

- **現行版（領域の部品がない）**: 選ばれませんでした。あとから出すお知らせを多くの読み上げソフトで確実に知らせるには、箱を先に置いておく必要があります
- **× の名前を「閉じる」に固定する**: 選ばれませんでした。ページに × が複数並んだとき、どれを閉じるボタンか分からなくなるため、題も名前に含められるようにしました
- **警告を `alert` にする（危険と同じ扱いにする）**: 選ばれませんでした。ADR-0043 で示した W3C・MDN の勧め（`alert` は急ぎの知らせだけ）どおり、危険だけを `alert` のままにします

## 影響

- `src/components/NoticeRegion.tsx`（新規）: `role="alert"`（危険用）・`role="status"`（ほか用）の空の箱を先に置き、`NoticeRegionContext`（`alert`・`status` の2つの箱）で子に渡します。両方の箱に `aria-atomic={false}` を付けます。箱の中の間、箱どうし（中身があるとき）の間はどちらも 8px です
- `src/components/notice-region-context.ts`（新規）: `NoticeRegionBoxes`（`alert`・`status`）を持つ Context。既定は `null`（領域の外）です
- `src/components/Notice.tsx`:
  - `closeLabel` props（既定 `'閉じる'`）を足しました。× の `aria-label` は `closeLabel`、題があるときは `aria-labelledby` で「× の名前 → 題」の順に読ませます
  - `live` props（既定 `true`）を持ちます。`NoticeRegion` の中にあり `live` が `true` のときは、自分では role の箱を出さず、領域が用意した箱の中へ `createPortal` で描きます。`live={false}` は箱を使わず、その場に描きます（出したお知らせにフォーカスを移して読ませるとき用 — [ADR-0044](./0044-message-announce.md)）
  - 危険は `alert`、ほかは `status`（`roleOf`）という役割の割り当ては、ADR-0043 のまま変えていません
- **分かっていること**: × で閉じたあと、フォーカスが body に落ちる問題は、まだ解決していません（`design/backlog.md` の「Notice」節）。トーストはまだ作っていません

## 原則への反映

反映なし。読み上げで危険だけが割り込む、という決まりは原則6にすでにあり（「読み上げでは、危険だけが割り込み、ほかは静かに知らせます」）、この ADR で変わりません。NoticeRegion の仕組みと × の名前の付け方は、部品の実装の決まりとして JSDoc に書きます。
