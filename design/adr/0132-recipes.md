# 0132. レシピ（Footer を部品にせず組み合わせの見本にする）

- ステータス: Accepted
- 日付: 2026-09-19
- ラウンド: ループ外

## 背景

ページの下の帯（Footer）が要るかを検討していました。列に並んだリンクと著作の行を持つだけの帯で、既存の部品（Container・Link・Text）を組み合わせればすぐに作れます。部品として切り出すほどの見た目の決定（角・色・状態）を持たないため、Footer 自体を部品にするかどうかを決める必要がありました。

## 候補

Footer のような「部品にはしないが、組み合わせ方の見本を示したいもの」を置く場所の名前です。

| 案                         | 内容                                     |
| -------------------------- | ---------------------------------------- |
| パターン（Patterns）       | UI パターン集としてよく使われる呼び方    |
| レシピ（Recipes）          | 材料（部品）を組み合わせる手順という比喩 |
| 組み合わせ（Compositions） | そのまま「組み合わせ」と呼ぶ             |

## 決定

**レシピ（Recipes）を採用します。** Footer は部品にせず、既存の部品を組み合わせた「レシピ」として置きます。

- README に「レシピ」の節を作り、Footer をチェック済みで載せます
- Storybook では `Recipes/Footer` に組み方の見本のストーリーを置きます
- コードは `src/recipes/` に置き、公開の入口（`src/index.ts`）には足しません
- `CLAUDE.md` のファイルの地図に `src/recipes/` の行を足します

## 理由

ユーザーの返事の原文です。

> Footer ってそもそも既存コンポーネントで簡単に実装できるので必要なのかなと思っています

> Footer のように直接実装しないけど組み合わせて作ることを推奨するもの、というセクションを作りたい

名前の候補について、Claude はパターン（Patterns）を勧めましたが、ユーザーの返事は次のとおりです。

> レシピいいですね。レシピで行きましょう

- **Footer を部品にしない理由**: 返事のとおり、Container・Link・Text だけで組めるため、専用の部品として角や色の決定を持つ必要がありませんでした
- **「レシピ」を選んだ理由**: 返事のとおりです。Claude が注意として挙げた「CSS のライブラリ（Panda CSS など）では見た目の変種の定義という別の意味で使われる」点は、Storybook と README の節の名前として使う範囲では問題にならないと判断しました

## 却下した案と理由

- **パターン（Patterns）**: 選ばれませんでした。Claude が最初に勧めた案でしたが、ユーザーは「レシピ」を選びました
- **組み合わせ（Compositions）**: 選ばれませんでした。候補には挙げましたが、返事では触れられていません

## 影響

- `src/recipes/Footer.stories.tsx`: Footer の組み方の見本のストーリーを追加しました。Container・Link・Text を組み合わせた例で、Docs には使い方だけを書いています
- `README.md`: 「レシピ」の節を足し、Footer にチェックを付けました
- `CLAUDE.md`: ファイルの地図に `src/recipes/` の行（「レシピ: 部品にせず、既存の部品を組み合わせて作るもの（Footer など）の見本のストーリー。公開の入口には足さない」）を足しました
- backlog に足す未決事項: レシピに回す部品の見直し（Sidebar・Stack などが部品として要るか）は決めていません
