# 0167. 全体が押せるカードは、浮いた押すものにする

- ステータス: Accepted
- 日付: 2026-09-19
- ラウンド: ループ外

## 背景

原則 1 は「離れているものは、押せるものと、重なる別のレイヤー」と書きながら、カードは「ページと同じレイヤー」で影がなく、それでも「押すと沈む」としていました（[ADR-0129](./0129-card-press.md)）。ページに着いているものがどこへ沈むのかが説明できず、原則 2 の「hover に枠線は使いません」とも、カードの hover で輪郭を濃くする決まりが食い違っていました。原則の整理（[ADR-0164](./0164-principles-reorganization.md)）の問い D3・D5 です。

## 候補

| 問い | 案  | 内容                                                                                      |
| ---- | --- | ----------------------------------------------------------------------------------------- |
| D3   | a   | 高さを 3 段に書き直し、「沈む」を高さの話から切り離す。平らな押すものとカードは影なし     |
| D3   | b   | 「押せるものは浮いている」を保ち、カードの扱いを決め直す                                  |
| D5   | a   | 原則 2 の文を「hover で枠線を足さない。もとからある輪郭が濃くなるのは明るさのうち」に直す |
| D5   | b   | カードの hover から輪郭の変化を外す                                                       |

## 決定

**全体が押せるカードは、浮いた押すものにします。** 薄い影を付け、hover で影を減らし、押すと沈めます。hover の輪郭の変化は外します。影を付けるのは、カード全体が押せるときだけです。中のボタンだけが押せるカードと、押せないカードは、ページと同じレイヤーのままで影を付けません。

高さは 3 段です。ページ、少し浮いた押すもの（塗りのボタン、トグル、全体が押せるカード）、ページの上に重なる面です。

## 理由

ユーザーの返事の原文です。

> 押せるカードは少し浮かせる、に改修するのが良さそうです。カードは常に押せるとは限らず、ボタンしか押せない可能性があるため、常に浮くのではなく、カード全体が押せる場合のみ影を追加するかたちにします。

> D3で書いた通りに、影をつけて輪郭を外します。

塗りがあって押せるものは浮く、と例外なしで書けるようになります。「hover に枠線は使いません」（原則 2）も、そのまま成り立ちます。

## 却下した案と理由

- **D3 の a**: 選ばれませんでした。カードが影なしのまま沈むことになり、「沈んでページに着く」という説明と合わないままです
- **D5 の a**: 選ばれませんでした。輪郭を hover に使う例外を原則 2 に残すことになります

## 影響

- **実装はまだです。** Card と LinkCard は、いまは ADR-0129 の見た目（影なし、hover で面を淡く塗り輪郭を濃くする）のままです。backlog に足しました
- 影の値、hover の面の塗りを残すか、画像を少し大きくする動きとの組み合わせは、軸を立てて比べます。決まったら ADR-0129 を置き換えます
- それまで、原則 1・3 と Card・LinkCard の実装は食い違っています。点検表でカードの影を指摘するときは、この ADR と backlog を根拠にしてください

## 原則への反映

原則 1 の考えの文を、高さ 3 段の説明に書き換えました。原則 3 のカードの行を、浮いた押すものと同じ手応え（hover で影が減り、押すと沈む。輪郭は変えない）に書き換えました。前置きの「部品の仲間」でも、全体が押せるカードを浮いた押すものに入れています。
