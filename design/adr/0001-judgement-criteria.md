# 0001. 判断の基準

- ステータス: Accepted
- 日付: 2026-09-12
- ラウンド: ループ外

## 背景

原則のブラッシュアップは、候補を生成し、最もイメージに近いものを選び、その特徴を保存する、という方法で進めます。「イメージに近い」の基準点が頭の中にしかないと、ラウンドごとに気分で選ぶことになり、選んだ特徴を積み重ねても一貫しません。

また、参照画像（コンポーネント見本3枚、Web サイトなど5枚）と、別のエージェントと作った既存原則の間には、いくつか食い違いがありました。どちらを正とするかも決める必要がありました。

## 候補

基準点の置き方:

| 案  | 内容                                                 |
| --- | ---------------------------------------------------- |
| A   | 参照画像を正とする                                   |
| B   | 短い言語化（形容詞、反例）を正とし、画像は補助にする |
| C   | 明示的な基準は作らず、都度直感で選ぶ                 |

ライブラリの顔:

| 案  | 内容                                                         |
| --- | ------------------------------------------------------------ |
| A   | コンポーネント見本寄り。無彩色＋青の実直な部品               |
| B   | Web サイト寄り。水色・ピンク・pill・大きな文字を部品にも出す |
| C   | 構造は A、トークンで差し替えられる部分は B                   |

## 決定

1. **言語化した基準を正とします。** 基準の言葉は次の4語です

   | 基準の言葉 | 画面上で見るところ                            |
   | ---------- | --------------------------------------------- |
   | 軽い       | 影は弱く、線は細く、余白は多い                |
   | やわらかい | 角が丸い。文字は黒ではなく濃紺グレー          |
   | 整然       | 部品の構造が揃っている（3層構成、状態の規則） |
   | 人懐っこい | 水色・ピンク・pill・和欧併記                  |

2. **顔は、構造を実直に、個性をトークン層に出します。** 状態の表し方・影・塗りと枠線はコンポーネント見本に寄せ、色・角丸・文字・和欧併記は Web サイトの個性を既定値にします
3. **温かみとポップさは、トークン層と動きで出します。** 動きは原則3「一段沈む」の延長として、押下時にバネのように沈む、といった形にします。コンポーネント内部の装飾は許しません（原則9を維持）
4. **画像と既存原則が食い違う箇所は、どちらも仮説として扱います。** 食い違いをループの振る軸にし、判定には基準の言葉を使います。食い違いのない部分は固定し、振りません
5. **反例の初期値**は「マテリアルデザインのような、影で階層を作る硬い見た目」です（README の「マテリアルデザインほどかたい感じじゃない」から）。以降は、却下した候補から追加します

## 理由

- 画像1枚を基準にすると、写っていない部品（Select、Dialog、Pagination など）では判断できません。言葉なら全部品に当てはめられ、選んだ理由も「どの語に近かったか」として記録できます
- 顔を A だけにすると、Tailwind UI の標準に近い没個性な見た目になります。B だけにすると、部品の主張が強くなり、部品が多く並ぶ画面ではうるさくなります。C は、原則9「本体は真面目、遊びはレイアウト層」と、README の「マテリアルほどかたくない」の両方を満たします
- 動きは静止画では見えないので、「整然」とした見た目を崩さずにポップさを足せます。「一段沈む」はすでに物理的な比喩なので、概念が増えません
- 既存原則は画像を解釈して作ったもので、画像もユーザー自身が「ブレがある」としています。どちらも絶対の正にはできないので、基準の言葉を判定役にしました

## 却下した案と理由

- 基準点 A（画像を正とする）: 画像にない部品で判断できない
- 基準点 C（直感）: ラウンド間で基準がぶれ、矛盾を検証できない
- 顔 A、B: 上記「理由」のとおり
- ポップさを「コンポーネント内部の装飾」で出す案: 原則9が守ってきた再利用性を手放すことになる
- 形容詞の別案「明るい・丸い・素直・ポップ」: 構造層まで派手になる
- 形容詞の別案「静か・清潔・精密・ミニマル」: 「マテリアルほどかたくない」に反して、別の方向にかたくなる

## 影響

- `principles.md` の冒頭に「判断の基準」「顔」「ポップさの出し方」「反例」を置きました
- 原則の各項目に【固定】【前半の軸】【後半の軸】の印を付けました
