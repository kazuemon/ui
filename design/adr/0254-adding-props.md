# 0254. props を足す基準と、今回足す props

- ステータス: Accepted
- 日付: 2026-09-21
- ラウンド: ループ外（props の監査）

## 背景

見本のページ（`src/samples`・`apps/docs/examples`）で、同じ `className` を繰り返し書いている箇所がありました。表のセルの縦そろえ（M-01）、`Skeleton` の幅と高さ（M-02）、`Form` の項目の間隔（M-03）、タブと中身のあいだの余白（M-04）、読みものの縦のリズム（M-05）、`Container` の上下の余白（M-06）、本文の太字（M-07）、ラベルと同じ見た目の見出し（M-08）などです。兄弟の部品で props が欠けている箇所（`missing-props.md` の A〜D）もありました。ui-A-line（見本のページを移したセッション）の報告が、このうちいくつかを裏付けています。

## 候補

| 項目                               | 現行版                                             | 候補                                                                                                                                             |
| ---------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| props を足す基準                   | 決めていない                                       | a. よくする調整は props、まれな調整は `className`（同じ調整が繰り返す・用途が広い） ← 推奨／b. すべて `className` のまま／c. すべて props にする |
| `Skeleton` の幅・高さ（M-02）      | `className` のみ（27 箇所）                        | a. `width`・`height` を足す／b. 段の名前で渡す／c. `className` のまま（Docs に明文化）← 採用                                                     |
| `Form` の項目の間隔（M-03）        | `className` のみ（Form・ストーリー合わせて 11 回） | a. `gap?: StackGap` を足す／b. 既定で縦積みにする／c. `Stack` を子に入れる形を Docs に書く ← 採用                                                |

| `Container` の上下の余白（M-06）   | 左右のみ持つ                                       | a. `py` を足す ← 採用／b. `gap`/`direction` も足す／c. `render={<Stack>}` と組む形を Docs に書く                                                 |
| `Text` の太字（M-07）              | 持たない                                           | a. `weight` を足す ← 採用／b. `tone` に `strong` を足す／c. `className` のまま                                                                   |
| ラベルと同じ見た目の見出し（M-08） | `Field` は非公開                                   | a. `Text` に `variant`（`label`・`caption`）を足す ← 採用／b. `FieldLabel` を公開する／c. `className` のまま                                     |

## 決定

**基準は、よくする調整は props、まれな調整は `className` に任せます。** 見本やストーリーで同じ `className` が繰り返す調整は props にします。用途が多すぎる調整（`Skeleton` の幅と高さ）は `className` のままにします。並べる間隔は `Stack` を子に入れて決め、部品自身の内側の余白（`Container` の `py`、`TabPanel` の余白）は部品が持ちます。兄弟の部品は同じ props を同じ名前で持ちます。

### 足すもの

| 部品                                      | 足す prop                                                                             | 根拠             |
| ----------------------------------------- | ------------------------------------------------------------------------------------- | ---------------- |
| `Prose`                                   | 子の部品（`Heading`・`Text`・`CodeBlock` など）にも縦のリズムを効かせる               | M-05             |
| `Container`                               | `py`（上下の余白）                                                                    | M-06             |
| `Text`                                    | `weight`（太字）／`variant`（`label`・`caption` の段）／`as` に `strong`・`em`・`del` | M-07・M-08・M-10 |
| `Prose` か `Container`/`Stack`            | 読みものの入口（`reading`）                                                           | M-11             |
| `Switch`                                  | `Field` に載せ、`errorText`・`warningText`・`captionPlacement` を持たせる             | M-14             |
| `Textarea`                                | `InputFieldProps` の継承に書き換える                                                  | M-15             |
| `Checkbox`・`CheckboxGroup`・`RadioGroup` | `infoText`                                                                            | M-16             |
| `NavbarLink`・`TreeItem`                  | 新しいタブの共通処理（`target`・`rel`）                                               | M-17             |
| `Dialog`・`Drawer`・`Popover`・`Menu`     | `autoFocus`（[0251](./0251-overlay-base-ui-props.md)であわせて決定）                  | M-19             |
| `TabPanel`                                | 既定の余白（`Tabs` の `panelGap` から配る）                                           | M-04             |
| `Figure`                                  | `Image` を使う形を案内（キャプションのない画像は `Image` へ）                         | M-09             |
| `Tag`・`Badge`・`Chip`                    | 大きさを 1 本の軸で決める（軸として比べる）                                           | M-30             |

### 足さないもの

| 部品       | 足さない prop     | 理由の原文                                                                                                                                                                                |
| ---------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Skeleton` | `width`・`height` | 「ユースケースが多すぎるため。文字の場合もあるし、ブロックの場合もあるため。shape="text" 自体は、入力方式によって変化するため、それを高さとして自動指定してくれる、という認識。」（M-02） |
| `Form`     | `gap`             | 「Form の内部で Stack コンポーネントなどを使ってもらう想定。」（M-03）                                                                                                                    |

## 理由

M-04 のメモです。

> 文字サイズが変わっても、タブと本文で同時に変わるので余白は固定で良さそうでした。Tabs は Tab の見た目だけに徹してもらいます。

M-06 のメモです。

> py px などはコンポーネント全部に付けたい気持ちもありますね… 内部については Stack を子に入れてもらうことを考えています。

M-17 のメモです。

> 共通化はして良さそうですが、BreadcrumbItem と Pager は、外部サイトになる可能性が薄いのでいらない気がします。一旦 NavbarLink と TreeItem だけでお願いします。

`Skeleton` と `Form` の「足さない」の原文は、上の表のとおりです（M-02・M-03）。

## 却下した案と理由

- **`Skeleton` に `width`・`height` を足す**（M-02 の a、おすすめ）: 選ばれませんでした。「ユースケースが多すぎる」ため、`className` のままにしました
- **`Form` に `gap` を足す**（M-03 の a、おすすめ）: 選ばれませんでした。「`Form` の内部で `Stack` を使ってもらう想定」のため
- **`TabPanel` ごとに `gap`/`padding` を足す**（M-04 の b）: 選ばれませんでした。文字サイズが変わってもタブと本文で同時に変わるものなので、既定の余白 1 つに固定しました
- **`BreadcrumbItem`・`Pager` にも新しいタブの共通処理を足す**（M-17 の候補の範囲を広げる案）: 選ばれませんでした。「外部サイトになる可能性が薄い」ため、`NavbarLink`・`TreeItem` だけにしました
- **`FieldLabel` を公開する**（M-08 の b）: 選ばれませんでした。`Text` に `variant` を足す形（入口が 1 つ増えるだけ）を採りました

## 影響

- 上の「足すもの」の表のとおり、各部品に props を足します
- 見本の書き直し（M-20: `Badge` の `children` の形に直す、M-21: `Stack` と `DescriptionList` で書き直す）
- 分かっていること: `Skeleton` の幅・高さと `Form` の `gap` は、今後も `className`（と `render={<Stack>}`）で対応します

## 原則への反映

反映なし。[原則 20](../principles.md#20-部品は知らないことを決めない)（部品は知らないことを決めない）の範囲内の決定です。`Skeleton`・`Form` を「足さない」としたのも、用途が広すぎて部品側では決められないという、同じ原則の判断です。
