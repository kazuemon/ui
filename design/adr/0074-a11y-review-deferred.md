# 0074. 2026-09-14 の a11y レビューのうち、据え置き・backlog にしたもの

- ステータス: Accepted
- 日付: 2026-09-14
- ラウンド: ループ外（a11y レビュー）

## 背景

2026-09-14 に、部品ごとの a11y・慣例・API についての判断を、記号（B1〜C7）でまとめて尋ねました。ほとんどは「推奨どおりにする」として実装し、実際に見た目や挙動が変わったものは、それぞれの ADR（[0046](./0046-link-rest.md) など）に記録しています。

このレビューで出た項目のうち、他の ADR に入らない、据え置き（いまは何もしない）・backlog へ回した・後日ほかの部品として作る、としたものが複数ありました。ここにまとめて記録します。

## 候補

比較の候補はありません。推奨した内容と、「そのまま実装する」か「いまは何もしない」かの分かれ目を尋ねた記録です。ここで扱うのは、後者（据え置き・backlog・先送り）に決まった項目だけです。

## 決定

次の項目は、いまは手を付けない（据え置き）か、backlog に回すか、別の部品として要るときに作ることに決めました。

| 記号       | 内容                                                        | 扱い                                                                                                 |
| ---------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| B3         | 警告の色のボタン                                            | 据え置き。必要になったら `color` に足す                                                              |
| B4         | 開発時の警告の書き方                                        | `process.env.NODE_ENV !== 'production'` で書く。`typeof` の確かめは付けない（React・Base UI と同じ） |
| S1         | 閉じてフォーカスが戻るときの説明と aria-live の重なり       | 据え置き                                                                                             |
| S5         | 構造（浮かぶ・シート）を固定する Provider                   | 据え置き。部品をまたぐ形で、Menu など2つ目の浮かぶ UI を作るときに作る                               |
| S6         | 浮かぶ選択肢の項目の数の上限（10.5）                        | 据え置き                                                                                             |
| S8         | ほかの浮かぶ UI（Menu・Popover・Tooltip）との影・動きの共有 | 据え置き                                                                                             |
| F4〜F6     | prefix・suffix の読み上げ順とつなぎ方                       | 据え置き（[ADR-0040](./0040-field-addon-rest.md) のまま）                                            |
| F9         | エラーの一覧に「必須」が入る件                              | 据え置き。必須の印を部品で持つときに除く                                                             |
| F8         | 本物の読み上げソフト（VoiceOver・NVDA）での確かめ           | ユーザーが試す。部品側では確かめない                                                                 |
| S4         | Select の選択肢の群（Base UI の `Select.Group` 相当）       | backlog へ足す                                                                                       |
| T1（Chip） | 押せる・消せる小物（ボタンと同じ部品の高さの pill）         | 別の部品として、要るときに作る。今は作らない                                                         |

あわせて、`<Form>` が Base UI の Form を包まない自前の部品のままであることも、このとき変えないと決めました。

## 理由

ユーザーのメモです。

> それ以外の項目は特に違和感はありませんでした。

S4（Select の選択肢の群）への返事です。

> S4 はちょっと欲しいかもですね。もっとも S5 で語っているように、Provider ベースの実装が最近は多い気がするので、backlog に追加しておきたいですね。

T1（Chip）への返事です。

> T1 の Chip はどういう立ち位置にするか迷いますね。

> S2, F7, Chip はそれでよさそうです。

以下は、メモから読み取れることです。

- **ほとんどは推奨どおりで違和感なし**: 「それ以外の項目は特に違和感はありませんでした」なので、B3・B4・S1・S5・S6・S8・F4〜F6・F8・F9 は、レビューで示した推奨（いまは何もしない、または据え置き）のまま進めます
- **S4 は欲しいが、いまは作らない**: 「ちょっと欲しいかもですね」。ただし S5（構造を固定する Provider）が絡む実装で、「Provider ベースの実装が最近は多い気がする」ため、いま作らず backlog に残します
- **Chip は立ち位置に迷いがあるので、今は作らない**: 「どういう立ち位置にするか迷いますね」。Tag（文字のラベル）・Badge（数と点）とは別の「押せる・消せる小物」として切り分ける方針だけを決め、実装は要るときにします。最終的には「それでよさそうです」で決着しました

## 却下した案と理由

却下した案はありません。ここでの決定は、推奨のうち「いま手を付けない」「あとに回す」を選んだことです。対になる「推奨どおりに実装する」ものは、実装した機能ごとにほかの ADR に記録しています。

## 影響

- `design/backlog.md`:
  - 「Button」節に、B3（警告の色のボタンは必要になったら足す）がすでに記録されています
  - 「Select」節に、S4（選択肢の群）・S5（構造を固定する Provider）・S6（項目の数の上限）・S8（ほかの浮かぶ UI との共有）が、すでに記録されています
  - 「Switch・Tag・Badge・Chip」節に、T1（Chip は要るときに作る）がすでに記録されています
  - 「Form・読み上げ」節に、F8（本物の読み上げソフトでの確かめ）・F9 に関わる必須の印の扱い・「`<Form>` は自前のまま」が、すでに記録されています
- B4（開発時の警告の書き方）は、`src/components/link-parts.ts` の `warnOnce`（`process.env.NODE_ENV` を見る。`typeof process` の確かめは付けない）に、すでに沿っています
- **分かっていること**: S1（閉じてフォーカスが戻るときの説明と aria-live の重なり）は、この ADR の時点で backlog に新しく項目を足していません。挙動を変えない、という判断です

## 原則への反映

反映なし。ここでの決定は、いまは何もしない・あとに回すという判断であり、原則の範囲を変えるものではありません。
