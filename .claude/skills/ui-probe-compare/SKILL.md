# 検証の比較

引数: `ISSUE: <番号> OUT: <ディレクトリ>`

Issue のコメントにある「## 検証 A」と「## 検証 B」を比べ、かずえもんが決めるための質問にまとめます。ADR-0047（`design/adr/0047-principles-probe.md`）の手順の後半です。

文だけでは、A と B がどんな見た目を言っているのかが伝わりません。割れた項目は、A・B・案がそれぞれどう見えるかを図にして添えます。

## 読むもの

1. Issue の本文とコメント全部（`gh issue view <番号> --comments`）
2. `design/principles.md`
3. `design/adr/README.md`（索引）。関わりそうな ADR だけ本文を読む
4. `design/backlog.md`（すでに未決として挙がっているか）
5. `design/tokens.css`

## 分け方

A と B の答えを見出しごとに並べ、違いを次の 3 つに分けます。

| 分類               | 意味                                              | 出し方                                             |
| ------------------ | ------------------------------------------------- | -------------------------------------------------- |
| **空白**           | 原則も ADR も触れていない。かずえもんが決める     | 質問にする。既定の案を 1 つ添える                  |
| **読み違い**       | 原則にはあるが、文が曖昧で 2 体が違う読み方をした | どの文がどう読めたかを書く。文の直し方の案を添える |
| **トークンで済む** | 原則には書かず、tokens.css の値で決まっている     | 一覧に載せるだけ。質問にしない                     |

A と B が同じ答えでも、既存の ADR と食い違うなら「読み違い」に入れます（2 体そろって間違えるのは、原則の文が誘導している印です）。

backlog にすでにある未決事項は、質問に「backlog にあり」と添えます。

## 書くこと

```
## 検証の比較

### 決めてほしいこと（空白）
- [ ] <何を決めるか>。A: … / B: …。**案**: <既定の案>（<近い原則>）
  <!-- figure:q1 -->
- [ ] …

### 原則の文を直す候補（読み違い）
- 原則 N「<引用>」: A は …、B は … と読んだ。**案**: <書き換えの案>
  <!-- figure:r1 -->

### トークンで決まっていること
- <項目>: <トークン名>

### 2 体がそろっていたこと
- <項目>: <答え>（原則 N）
```

「決めてほしいこと」は、多くて 8 つに絞ります。似た質問はまとめます。書式にない見出し（次のステップなど）は足しません。

## 図を描く

「決めてほしいこと」と「読み違い」のうち、見た目に違いが出る項目を図にします。props の名前や、prop を持つかどうかのように見た目に出ない項目は描きません。

図は 1 項目につき 1 つの `<section>` です。本文では、その項目の下の行に `<!-- figure:<名前> -->` を書きます（名前は、決めてほしいことが `q1`・`q2`…、読み違いが `r1`・`r2`…）。ワークフローがこの印を画像に置き換えます。

```html
<section data-figure="q1" data-title="文字数の表示">
  <figure data-label="A: 「n 文字」を欄の中の右下に置く">
    <!-- A の見た目 -->
  </figure>
  <figure data-label="B: 「n/上限」を欄の下の右に置く">
    <!-- B の見た目 -->
  </figure>
  <figure data-label="案: …">
    <!-- 案の見た目。A か B と同じなら省く -->
  </figure>
</section>
```

- `<section>` を並べた断片だけを書きます。`<html>`・`<head>`・`<body>`・`<script>`・`<style>` は書きません。見出しと列の枠は、描く道具が付けます
- 見た目は Tailwind のクラスで書きます。色・角・寸法は `design/tokens.css` の名前を使います（`bg-field`・`text-fg-subtle`・`rounded-control`・`h-control`・`text-caption`。クラスがないものは `px-[var(--spacing-control-x)]` のように CSS 変数で）。Tailwind の既定の色（`bg-gray-100` など）と影は使えません
- 違いに関わる部分だけを描きます。ラベル・本体・キャプションのように、違いを読むのに要る周りは添えますが、部品を丸ごと作り込むことはしません
- hover・フォーカスなどの状態は、`:hover` ではなく、その状態の見た目を直接書きます。状態を比べる項目では、`<figure>` の中に状態ごとの見本を横に並べ、小さな文字で状態の名前を添えます
- 文字は日本語と英数字だけにします。矢印などの記号は、同梱のフォントになく化けるので、言葉か SVG にします
- A と B が文で言っていないことは足しません。書かれていない細部は、tokens.css の値と、ほかの項目の答えから補います

## 出し方

投稿はワークフローがします。自分では Issue にコメントしません。

1. 本文を Write で `<OUT>/compare.md` に書く
2. 図があれば Write で `<OUT>/figures.html` に書く。本文の `<!-- figure:… -->` の名前と、`data-figure` の名前をそろえる

書いたら終わります。最後の返事に本文を書いても Issue には届きません。
